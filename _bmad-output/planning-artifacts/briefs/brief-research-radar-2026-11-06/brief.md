# 產品簡介：Research Radar

## 摘要

Research Radar 是給資管研究生用的文獻研究助理。它會自動追蹤指定期刊的新論文，依主題和研究方法分類，畫出各主題逐年的變化，再透過附出處的問答幫忙找論文題目。實驗室成員共用同一個系統。

最直接的使用者是開發者本人 Kevin：中央大學資管所碩一，還沒有論文題目。指導教授王存國的研究多屬行為與管理類（資訊經濟、電子商務、供應鏈、ERP、IT 專案管理），Kevin 想在這個範圍裡找偏技術的題目。手動找論文、讀論文、分類很花時間，而且看不出哪些主題正在成長。同屆另外 3 位同學也還沒開始整理文獻，現在導入可以讓大家從一開始就用同一套系統。

這也是 Kevin 求職作品集的主力專案（目標：台積電、聯發科、Google、NVIDIA 的 IT／軟體職缺），要補上作品集缺的三塊：部署上雲的後端、資料 pipeline、LLM 應用（RAG）。所以工程品質和「講得出每個決策的理由」本身就是需求。

## 要解決的問題

- **找題目沒有依據**：碩一生不知道哪些主題正在變熱、哪些構面之間的關係還很少人研究，只能靠零星閱讀和直覺。
- **整理文獻很花時間**：資管行為研究的閱讀重點是研究問題、方法、理論、研究模型和發現，現在只能一篇一篇手動抄進筆記。
- **實驗室各自為政**：同屆 4 人都還沒建立文獻庫，之後很可能重複找同一批論文、格式也不一致。
- **一般 AI 問答不能直接拿來用**：研究指出 LLM 單獨回答時，引用常常是捏造的，論文寫作不能接受這種答案。

[ASSUMPTION] 3 位同學的痛點和 Kevin 相同。會在寫 PRD 前，每人訪談約 10 分鐘來驗證（OQ-03）。

## 解決方式

第一版的目標只有一個：**幫 Kevin 找到論文題目**。

1. **自動追蹤期刊**：定期從官方 API（OpenAlex、Semantic Scholar、Crossref）抓 14 本期刊（AIS 資深學者頂尖期刊清單 11 本，加上 Project Management Journal、IEEE Transactions on Engineering Management、DATA BASE）的新論文，只存書目和摘要。第一次匯入暫定近 10 年，等 OQ-02 試抓後，再依資料量和費用確認。
2. **上傳 PDF**：一次上傳多個檔案，在背景解析，自動補齊書目，並去除重複。中文論文第一版用上傳的方式納入。
3. **分類與結構化筆記**：LLM 依主題和研究方法分類，並擷取研究問題、方法、理論、主要發現和研究模型（構面、假設，以及假設是否成立）。所有論文的研究模型會累積成一張構面關係網，標出很少被研究的關係，作為題目候選。使用者可以修正分類和筆記。
   - 主題（初版）：ERP、供應鏈、電子商務、IT 專案管理、資訊經濟、AI／資料分析
   - 研究方法（初版）：問卷／SEM、訪談／個案、實驗、資料分析／機器學習、文獻回顧
   - 這份清單會在訪談同學後定版（OQ-07）。主題存成設定資料，之後增減不用改程式。
   - 多數論文只有摘要，摘要通常看不出每個假設是否成立。完整的研究模型主要來自上傳的 PDF，只有摘要的論文只擷取摘要裡寫得出的部分。
   - 每條構面關係都要標示來源是摘要還是全文，並顯示覆蓋率，避免把「沒有全文」誤判成「很少人研究」。
4. **趨勢分析**：每個主題逐年的論文數、成長最快的主題、主題交叉（例如 ERP × AI），以及用突現偵測找出最近突然變熱門的關鍵字。
5. **附出處的問答**：用 RAG 回答問題，每個回答都附上引用了哪幾篇，點得回原始論文。範圍可以選自己的文獻庫、共用文獻庫，或所有追蹤的期刊。AI 只提出候選題目並附上依據，可不可行由 Kevin 和實驗室判斷。
6. **帳號與實驗室**：書目和分類全實驗室共享；筆記和 PDF 預設私人，可以選擇分享；問答紀錄只有本人看得到。
7. **匯出引用格式**：APA、BibTeX、RIS。
8. **額度管理**：問答預設用共用額度（Claude Haiku 5.5），每人每天有使用上限。想用更強模型的人可以填自己的 API key，key 加密存放，不寫進日誌，也不傳回前端。

## 和其他工具的差異

這個專案的差異不在技術門檻，而在於**為資管行為研究量身打造**，並且有一個真實的小實驗室在用：

- **研究模型層級的筆記與構面關係網**：概念取自資管學者的 TheoryOn／INN，把每篇的構面和假設累積起來，直接指出很少被研究的關係。一般論文 RAG 工具不會做到這一層。
- **用趨勢找題目**：結合主題逐年變化、主題交叉和突現偵測，回答「哪裡有偏技術的切入點」。
- **可以追溯、資料缺口看得到**：每個回答都附出處；每本期刊的摘要覆蓋率會顯示在介面和趨勢圖上，使用者知道哪裡的資料不完整。

## 成功標準

第一版要**同時**達到以下 5 點才算完成：

1. 實驗室同屆 4 人都實際用過，並蒐集到回饋。
2. 看得到追蹤期刊的主題趨勢，並幫 Kevin 收斂出候選論文題目。
3. 問答的每個回答都附出處，點得回原始論文。
4. 有線上可用的 demo，公開版只含開放取用的資料。
5. README、架構文件、ADR、自動化測試和 CI 齊全，面試時講得出每個技術決策的理由。

## 範圍

**第一版包含**：上面「解決方式」列出的 8 項功能。

**第二版之後**：

- 用 Unpaywall 找合法的開放取用全文。
- 確認學校合約允許後，評估用出版社的 TDM API（例如 Elsevier、Wiley）補摘要和全文。
- 一鍵收藏的瀏覽器擴充功能。
- 追蹤 GitHub 專案與 skill。
- 擴充研究主題。
- Notion／Zotero 整合。

**明確不做**：

- 不用程式透過學校 VPN 大量下載付費期刊全文。
- 不公開散布付費論文的 PDF。
- 不爬 Google Scholar，也不繞過 CAPTCHA，資料一律走官方 API。
- **不用 LLM 從標題推測或生成摘要**：抓不到摘要的論文就標示「缺摘要」。
- 不開放實驗室以外的人註冊，不做商業化。

## 限制與原則

- **記憶體**：正式主機只有 1 GB。api 和 worker 的 `mem_limit` 加總不超過 750 MB，本機開發時就照這個限制模擬正式環境。
- **環境**：Mac 只用來開發。測試環境用家裡的 PC＋Cloudflare Tunnel，給同學試用。正式環境預定用 Azure for Students，約 2027 年 1 月第一版快完成時才申請，讓 12 個月的免費期涵蓋求職季。最終選擇會在架構階段比較後寫成 ADR（OQ-04）。
- **LLM 費用**：用 Claude Max 每月附贈的 API 額度，預設 Haiku 5.5，不急的工作走 Batch API。在 Claude Console 為本專案開獨立工作區，每月支出上限 30 美元，之後可以調整。系統保留改用個人 key 的路。
- **向量化**：Claude API 沒有向量化功能，改用 Cloudflare Workers AI 或開源模型。全庫固定使用同一個支援中英文的模型，具體模型在架構階段決定（OQ-08）。
- **工程原則**：主題是設定資料，不寫死在程式裡；耗時的工作放背景執行，而且要冪等；請求失敗會自動重試，並遵守各來源的速率限制。
