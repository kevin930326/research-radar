## 怎麼判定

架構文件只寫「各 Story 分開做時，不約定就會做得不一樣」的規則，所以畫面文案沒被抄進來不算問題。這裡只記六類：

| 類別 | 意思 |
|---|---|
| 1 | 畫面需要、但架構的資料或 API 契約給不出來（或沒約定，兩個 Story 會各做各的） |
| 2 | 架構和 UX 文件互相矛盾 |
| 3 | 「給架構階段的事項」沒有回答 |
| 4 | 架構的規則讓 Kevin 的某項決定做不到 |
| 5 | 無障礙、響應式、減少動態、效能退場，需要架構層約定而沒約定 |
| 6 | `DESIGN.md` 的代幣或字體和前端選型衝突 |

嚴重度：

- **critical**：照現在的架構做，某個 Must 畫面做不出來，或會洩漏不該公開的資料。
- **high**：Must 畫面的核心資料或狀態沒有契約，拆 Story 之前不補，產生資料的 Story 和畫畫面的 Story 會對不起來，要重做。
- **medium**：會做出和 UX 不一樣的行為，或有一個狀態沒有人負責；補法小，但要先決定。
- **low**：補一句話就好，或等做到那個 Story 再定也來得及。

## 四、發現

### High

#### H-1 示範站論文清單每一列要顯示的欄位，`papers-index.json` 沒有；論文識別碼不在白名單；哪一篇在哪個分片沒約定

- **類別**：1
- **UX 文件**：
  - `EXPERIENCE.md`「7. 論文清單」：「示範站的每一列有標題、期刊、年份、DOI 連結、主題與方法的分類標籤，以及『● 有完整內容』或『○ 只有書目』。一次顯示 50 篇」
  - Component Patterns「論文列」：「第二行多顯示主題與方法的分類標籤（前面有 AI 標章）」
  - Interaction Primitives「網址」：「每篇論文…有固定網址」
  - 首頁規格 §5.2：「正式版還要一個論文識別碼，點星星時用來開論文頁」；§12 驗收：「星系用到的欄位只有…論文識別碼，全部在 FR-42 的白名單內」
- **架構**：
  - ADR-0007「檔案」：「`papers-index.json` 全部論文的**篩選欄位**，一欄一個陣列」「`papers/000.json …` 論文詳情，每 200 篇一個檔」
  - ADR-0007「產生」第 3 項 `DemoPaperBiblio` 的欄位清單：沒有論文識別碼。AD-20 規定這個模型「多餘欄位即報錯」
  - 哪一篇論文在哪一個分片檔：**沒有**
- **問題**：
  1. 清單一頁 50 列，每列要 DOI、分類標籤、標籤的 AI 標章、是不是有完整內容。照字面 `papers-index.json` 只有篩選欄位，其餘要去讀分片；而清單的排序和分片的順序無關時，50 列最多要抓 50 個分片檔。
  2. 訪客直接打開某一篇的固定網址（或從首頁點星星進來）時，前端要知道那一篇在第幾個分片。沒有約定的話，產生器和論文頁會各猜各的。
  3. 白名單模型不允許多餘欄位，卻沒有列識別碼，照做會連網址都組不出來。
- **建議的最小補法**（改 ADR-0007「檔案」一段與 AD-20 一句）：
  - `papers-index.json` 除了篩選欄位，再帶清單列要用的欄位：論文識別碼、DOI、主題與方法標籤、標籤是否已核對、是否只根據標題分類、是不是示範站可用且有摘要。AI 標章點開才要的模型名稱與產生日期，種類很少，放一張小對照表、每篇只存編號。
  - `papers-index.json` 的列順序固定，並寫明「第 i 列在 `papers/⌊i÷200⌋.json`」。
  - `DemoPaperBiblio` 的欄位清單補上論文識別碼，並寫明用的是哪一種（內部 ID 或 OpenAlex ID；後者在資料庫重建後網址不會變）。

#### H-2 首頁的三個讀數、發現卡、「星系載入失敗時的固定數字」沒有資料檔；發現卡的挑選條件沒寫進產生器

- **類別**：1
- **UX 文件**：
  - `EXPERIENCE.md`「1. 示範站首頁」：「發現卡顯示的關係由產生器挑選，條件是它的來源論文全部是示範站可用論文」
  - State Patterns「1. 示範站首頁」：「錯誤：星系資料載入失敗｜讀數顯示快照裡的固定數字，時間軸照常出現」
  - 首頁規格 §4.2 讀數 04：「本資料庫中少見 · ≤2 篇　◇ AI 整理／演算法透明度 → 平台信任／● 研究篇數 2　○ 證據來自摘要　期刊摘要覆蓋率 98%／看這 2 篇論文 →」
  - 首頁規格 §5.2：第一個檔案「很小，星系可以幾乎立刻出現」；§5.2 旋臂的排列順序是指定的 14 本期刊順序
  - 「3. 展示問答」「9. 資料涵蓋範圍」：「示範站有完整內容的 N 篇」「N 由產生快照的程式帶入」
- **架構**：
  - ADR-0007「檔案」：`manifest.json` 只有「目前是哪個快照、截至日期、各檔案的雜湊」；`galaxy.json`「每篇論文畫星星要用的欄位」
  - 發現卡怎麼挑、放在哪個檔：**沒有**
  - ADR-0007 自我檢查第 4 項只重算「計數方塊裡每一格」與關係，沒有提首頁讀數；AD-19 的計數方塊也沒有「本週新增」這個維度
- **問題**：
  1. 發現卡要一條關係的名稱、研究篇數、證據來源、覆蓋率、AI 標章資料、來源論文。現在首頁只能自己去讀 `relations.json`（整張排行表）再挑，既慢，也違反「由產生器挑選」。
  2. 星系檔載入失敗時，讀數要顯示「快照裡的固定數字」，但除了星系檔，沒有任何一個小檔案帶著這三個數字。
  3. `manifest.json` 是所有檔案的前提（ADR-0007：「前端先讀 `manifest.json`」），它自己載入失敗時首頁要顯示什麼，首頁規格 §8 沒有這個狀態。
  4. 旋臂順序、期刊簡稱與全名、年份範圍（時間軸刻度）要從哪裡來，沒寫。
- **建議的最小補法**：
  - `manifest.json` 加一個 `summary` 區塊：論文總數、有摘要數、本週新增數、示範站有完整內容的篇數、年份範圍。這樣一次請求就有日期列與固定數字。
  - 新增一個小檔 `data/sNN/home.json`（或併進 `manifest.json`）：發現卡的全部欄位與來源論文識別碼、期刊清單（簡稱、全名、旋臂順序；順序放 `config/` 的期刊設定）。
  - ADR-0007「產生」加一條挑選規則：研究篇數 ≤ 門檻、來源論文全部是示範站可用且有摘要、覆蓋率不觸發警告；同分時用固定的排序，讓每次產生的結果可以重現。
  - 自我檢查第 4 項加上「三個讀數等於 `papers-index.json` 重算的結果」。
  - **要 Kevin 決定**：(a) 沒有任何關係符合條件時，發現卡那一欄顯示什麼；(b) `manifest.json` 載入失敗時首頁顯示什麼。

#### H-3 AI 區塊的狀態沒有契約：`pending_kind` 只寫在 ADR-0004，架構文件本體沒有；UX 要分的五種情況裡有三種分不出來

- **類別**：1（另含一項類別 3：第 6 項的回答沒有進架構文件本體）
- **UX 文件**（`EXPERIENCE.md` State Patterns「8. 論文頁」）：
  - 「空的：這篇沒有摘要｜…沒有摘要，所以沒有中文重點」
  - 「空的：AI 產出還沒產生…｜中文重點、分類、研究模型的位置各是一行『還在產生，晚一點再回來看』，不是空白，也不是『沒有摘要』」
  - 「空的：本月 AI 額度用完…｜那一行改成『這個月的 AI 額度用完了，下個月才會產生』」
  - 「沒有依據：研究模型是空的｜『摘要裡沒有寫出可以擷取的假設』」
  - Component Patterns「論文列」：「中文重點還沒產生時，第三行顯示『中文重點產生中』；沒有摘要時沒有第三行」
- **架構**：
  - ADR-0004 第 8 項：「API 在論文的 AI 區塊回 `pending_kind`（`interactive` 或 `batch`），文案由前端決定」
  - `ARCHITECTURE-SPINE.md`：全文沒有 `pending_kind`，AD-7 只規定有內容時要內嵌 `provenance`
  - AD-8：「任一步沒過，該筆標 `rejected`，不成為有效資料」；ADR-0009：預算用完時「批次工作延到下個月」
- **問題**：論文頁、論文列（找論文、系統首頁、我的文獻庫都會用）、示範站匯出，是不同的 Story。「沒有有效的 AI 產出」背後至少有五種原因，畫面文字各不相同：
  1. 沒有輸入（沒有摘要、手填書目）
  2. 還在排隊或處理中
  3. 本月額度用完、延到下個月
  4. 跑過了，但結果是空的（例如沒有可擷取的假設）
  5. 跑過了，被閘門拒收（模型拒答、長度截斷、驗證沒過）
  
  第 3、4、5 種照現在的契約分不出來。第 5 種 UX 文件也沒有對應的文字，照現在的做法會永遠顯示「還在產生」。
- **建議的最小補法**：
  - AD-7 加一句：回傳 AI 區塊的 API 與示範站檔案，每個區塊都有 `state`，值固定為 `ready`、`pending_interactive`、`pending_batch`、`deferred_budget`、`no_input`、`empty`、`failed`；只有 `ready` 與 `empty` 帶 `provenance`。判定寫成一個 `repo` 函式，各端點共用。
  - **要 Kevin 決定**：`failed` 在畫面上寫什麼。如果不確定：先和「還在產生」顯示同一句話，同時 CLI 列出被拒收的清單讓管理者重跑。
  - 示範站：ADR-0007 寫的是「AI 處理完成（或等滿 24 小時）」才匯出，所以示範站可用的新論文可能還在 `pending`。UX 文件的示範站論文頁三種狀態裡沒有這一種，匯出時要嘛跳過這幾篇的完整內容（當成只有書目），要嘛輸出 `pending`，要寫明。

#### H-4 上傳檔案的狀態對不上：UX 有 8 種加 1 種確認，架構只有 5 種；「重試」兩邊矛盾；批次沒有實體；AD-24 的措辭會被誤讀

- **類別**：1 與 2
- **UX 文件**（`EXPERIENCE.md`「14. 上傳與匯入」第二段的狀態表）：辨認中、對到了、重複、要你確認、查不到（請填書目）、處理失敗、暫時查不到、不接受。另外：
  - 「處理失敗｜…＋『重試』。沒勾下載聲明的檔案超過 1 小時已經刪除，這時顯示『檔案已經刪除，請重新上傳』，沒有『重試』」
  - 「暫時查不到｜書目來源（OpenAlex、Crossref）暫時連不上：『暫時查不到，稍後會自動再試』。不算處理失敗」
  - 「8. 論文頁」我的檔案：「檔案讀到的 DOI 或標題和這篇對不上時，先問『這個檔案看起來是另一篇…還是要放在這一篇嗎？』」
  - 第一段：「沒勾時多一個勾選框（預設不勾）：『把追蹤範圍外的論文也加入實驗室文獻庫（不顯示是誰加入的）』」
  - 總結例句：「32 個檔案：27 篇加入你的文獻庫（其中 4 篇追蹤範圍外），2 篇重複，2 篇等你確認，1 個處理失敗」
- **架構**：
  - ADR-0004 第 2 項 `upload_item` 的狀態：「已收到 → 辨認中 → 已對到論文／等使用者確認／處理失敗」
  - AD-14：「每張狀態表的狀態轉換只經過一個 services 函式」
  - ADR-0013 三道防線第 1 道：「辨認工作**不論成功或失敗**，結束前都刪除 `tmp/` 的檔案」
  - AD-24：「上傳沒有可見範圍的參數，一律只有擁有者」；ADR-0013「辨認」第 4 項：「可見範圍依上傳時的勾選框」
  - 核心資料圖：只有 `upload_item`，沒有「一批上傳」的實體；ADR-0013 的流程第 1 步卻是「建立一批上傳，帶著有沒有勾下載聲明（整批一個值）」
- **問題**：
  1. 「重複」「查不到，請填書目」（和「可能是這一篇」是兩個不同的畫面）、「暫時查不到」、換版本時的「對不上，請確認」，在架構的狀態裡都沒有。
  2. **矛盾**：照 ADR-0013，沒勾聲明的檔案一失敗就被刪，所以這類檔案永遠沒有「重試」；UX 寫的是一小時內可以重試。
  3. 「暫時查不到，稍後自動再試」時，沒勾聲明的檔案已經刪了，再試只能靠先前讀出的 DOI 與標題。這兩樣要存在 `upload_item`，架構沒說。第三段的候選比對「左邊是從檔案讀到的標題」、而且可以隔很久才回來處理，也需要它。
  4. 整批的設定（下載聲明、分享勾選）與進度「已完成 12／32」要掛在某個實體上。
  5. AD-24 那一句的本意是「PDF 檔案一律私人」，但字面上會讓人以為批次不能帶分享勾選，和 ADR-0013 與 UX 相反。
- **建議的最小補法**：
  - ADR-0004 的表改成完整列舉：`received`、`identifying`、`matched`、`duplicate`、`needs_confirm`、`needs_manual`、`mismatch_confirm`、`lookup_deferred`、`failed`。「不接受」不建列，由 API 回固定的錯誤 `code`。
  - AD-24 加兩句：「`upload_item` 保存原始檔名與從檔案讀出的 DOI、推測標題、頁數，之後的重查與確認不需要檔案」；把「上傳沒有可見範圍的參數」改成「PDF 檔案沒有可見範圍的參數；批次有一個『追蹤範圍外也加入實驗室文獻庫』的布林值，只在沒勾下載聲明時有效，只影響論文的 `lab_visible`」。
  - 核心資料圖加 `upload_batch`（擁有者、下載聲明、分享勾選）。
  - **要 Kevin 決定**（重試的矛盾）：(a) 照架構：沒勾聲明的檔案失敗就刪，畫面一律顯示「請重新上傳」，UX 文件改一句；(b) 照 UX：失敗時先不刪，留給每小時的清理，一小時內可以重試。建議 (a)，「辨認完就刪」是授權上的承諾，越早刪越好；之後要改成 (b) 只動一個工作的結尾。

#### M-1 `titles.json` 的載入時機和首頁規格不同；「兩個檔案快照編號一致」的檢查沒有可以比的欄位

  1. 指到才載的話，每位訪客第一次指到星星一定會先看到「標題載入中…」（檔案壓縮後約 290 KB），而且這段時間點星星沒有反應；首頁規格要的是進場的 5 秒內就在背景載好。

- **建議的最小補法**：ADR-0007 把括號改成「進場動畫播放時在背景載入」；加一句「每個資料檔最外層都有 `snapshot`（`number` 與 `as_of`），前端和 `manifest.json` 比對，不同就當作載入失敗」；寫明 `galaxy.json`、`titles.json`、`papers-index.json` 的列順序相同。檔名帶編號或路徑帶編號擇一即可，請在 ADR 註明這裡用的是路徑。

#### M-3 AD-20 寫「輸出只經兩個模型」，但檔案有八種；關係與展示問答的檔案沒有白名單模型，自我檢查也沒有擋「把不可用的論文列成關係的來源」

#### M-4 「分頁寫進網址」「再載入 N 篇」「返回時停在原本的位置」，和不透明的 cursor 兜不起來

- **類別**：2
- **UX 文件**：Interaction Primitives：「篩選、排序、分頁、選取的主題都寫進網址」「從論文頁回到清單時，清單停在原本的位置與篩選條件」；「7. 論文清單」：「一次顯示 50 篇，最下面『再載入 50 篇』」；「12. 找論文」：「一次 20 篇，最下面『再載入 20 篇』」
- **架構**：AD-21：「篩選、排序、分頁全部寫進網址」；Conventions「API」：「分頁用不透明的 keyset cursor；每頁筆數來自設定」（keyset cursor：用「上一頁最後一筆的排序值」當書籤，下一頁從書籤之後接著拿）；AD-11：兩條腿「各取前 100」融合後回傳名次
- **問題**：畫面是「一直往下加」，不是「第幾頁」。網址裡如果放 cursor，重新整理只會看到那一頁之後的內容，前面載過的不見了；如果放「已經載了幾篇」，API 又只收 cursor 與固定筆數，要連打好幾次才能還原。另外，依相關程度排序的搜尋結果是「前 k 名」，本來就不適合 keyset。三個 Story（論文清單、找論文、我的文獻庫）不約定會做出三種。
- **建議的最小補法**：AD-21 加一句：「『再載入』型的清單，網址只記『目前顯示幾篇』；cursor 不進網址。資料來源層的清單函式接受筆數上限（設定值，例如 200），重新整理時一次拿回來」。Conventions 註明搜尋結果的分頁是在融合後的名次裡用位移，不用 keyset。返回時的捲動位置交給路由的捲動還原與查詢快取。

#### M-5 問答的「研究問題請求」：UX 是固定說明加兩個連結，架構是接著串流一段回答並扣一題

- **類別**：2
- **UX 文件**：State Patterns「16. 問答」：「研究問題請求｜『這個系統不產生研究問題。可以這樣做：』＋兩個連結：『整理這個方向已有的研究（附出處）』（把問題改寫成整理型再問一次）、『到關係排行表挑一條關係，產生證據簡報』」
- **架構**：ADR-0006：「研究問題請求：送出 `route`，先顯示固定的說明…與證據簡報入口，**模型接著寫的『既有研究整理』照一般回答的規則串流與驗證**」；AD-13：「只有 `answer` 與 `research_question` 正常結束才加一」
- **問題**：UX 的畫面上這一次沒有回答，使用者要再按一下才會問第二次；架構是這一次就直接給整理。兩邊扣題數的時機也不同。UX 的做法另外需要有人「把問題改寫成整理型」，架構沒有這個步驟。
- **建議**：**要 Kevin 決定。** (a) 照架構：固定說明下面直接出現附出處的整理，扣一題，UX 把第一個連結拿掉；(b) 照 UX：`research_question` 只回固定說明、不呼叫模型寫內容、不扣題數，第一個連結用固定句型（例如「整理〔原問題〕這個方向已有的研究」）帶回輸入框。建議 (a)：少按一次，也不需要改寫；之後要改成 (b) 只是前端不畫那段文字。決定後 ADR-0006 或 UX 文件擇一修改。

#### M-6 找論文的「找不到相關的論文」「沒有夠相似的論文」「找到 N 篇」，在 AD-11 的規則下產生不出來

- **類別**：1
- **UX 文件**：「12. 找論文」：「找到 N 篇。…」；State Patterns：「沒有依據：找不到相關的論文｜『在〔範圍〕裡找不到相關的論文』」「沒有依據：找相似論文沒有結果｜『沒有夠相似的論文』」
- **架構**：AD-11：兩條腿「各取前 100，用 RRF（k＝60）在一條 SQL 內融合…回傳排序後的論文 ID 與名次，不回傳內容」；ADR-0005 第 7 項：找相似論文「只用向量腿」
- **問題**：向量搜尋永遠找得到「最近的」幾篇，不管多不相關。沒有相似度的下限，這兩個狀態只會在範圍本身是空的時候出現；「找到 N 篇」的 N 也會永遠是上限值。
- **建議的最小補法**：AD-11 加一句：「向量腿有相似度下限（設定值，用 FR-26 的評估題組調）；低於下限的不算結果。回應帶 `total`（通過下限的篇數，最多到上限）」。門檻的數字留到評估時定。

#### M-7 背景工作的進度怎麼到瀏覽器沒有約定；導覽列的小圓點、問答頁一進來就要顯示的狀態，沒有資料來源

- **類別**：1
- **UX 文件**：「14. 上傳與匯入」：「狀態會自己更新；可以離開這一頁，回來還在」；Interaction Primitives「背景工作」：「完成後導覽列的『我的文獻庫』旁出現一個金色小圓點，點進去後消失」；「16. 問答」：「旁邊顯示『今天還能問 97 題』」；State Patterns：「本月額度用完（熔斷）｜**頁面最上面**訊息條…」（送出之前就要顯示）；「13. 我的文獻庫」：「有 N 篇等你確認」
- **架構**：沒有。ADR-0006 的剩餘題數只在 `done` 事件裡（問完才知道）；熔斷只在送出時由伺服器決定 `route`；Stack 有 TanStack Query，但沒說用輪詢（瀏覽器每隔幾秒問一次）還是推送。
- **問題**：小圓點在每一頁的導覽列上，所以每一頁都要知道「有沒有做完但還沒看過的上傳」；「點進去後消失」需要記「看過了」。上傳進度表、論文頁的「還在產生」、導覽列，是三個 Story。
- **建議的最小補法**：Conventions 加一列「背景進度」：一律用輪詢，間隔放設定；一個 `GET /api/v1/me/status` 回：處理中的上傳數、做完還沒看過的上傳數、等確認的篇數、今天剩餘題數、問答是否熔斷。`upload_batch` 加「看過的時間」。不用 SSE 或 WebSocket（多一條長連線，1 GB 主機不划算）。

#### M-8 架構多出四個使用者看得到的狀態，UX 文件沒有對應的畫面與文字

- **類別**：2（反方向：架構有、UX 沒有）
- **架構 → UX 文件有沒有**：
  1. ADR-0006：「回答到最後，一個通過驗證的出處都沒有：`done` 事件標記『沒有依據』，前端在回答下方加上固定的提醒」→ UX「16. 問答」沒有這個狀態。這也和 Foundation 的「問答的每個回答都附出處，沒有依據就直接說找不到」不太合：畫面上會出現一段沒有任何出處的回答，而且照 AD-13 會扣一題。
  2. ADR-0005「取捨」：「Workers AI 掛掉時，搜尋退回只用關鍵字腿，並在回應裡標示『語意搜尋暫時無法使用』」→ UX「12. 找論文」沒有。中文查詢在關鍵字腿找不到東西，這時中文搜尋會直接變成零結果。
  3. ADR-0008 第 5 步：「同一個 email 換了一個 `sub`，拒絕登入並寫稽核事件」→ UX「10. 登入」只有「登入失敗或被取消」與「不在名單」兩種。
  4. AD-8 的 `rejected`（AI 產出被拒收）→ 已併入 H-3。
- **建議**：每一項補一句 i18n 文字與錯誤 `code`。第 1 項**要 Kevin 決定**：(a) 保留文字、下面加註「這段回答沒有通過驗證的出處」、不扣題數；(b) 收到這個標記就把整段換成「找不到」的畫面、不扣題數。建議 (b)，和「沒有依據就直說」一致；架構只要把 AD-13 的扣題條件加上「至少一個通過驗證的出處」。第 2、3 項可以照既有的訊息條樣式直接補，請 Kevin 看一眼文字。

#### M-9 中文標題字的「只打包用到的字」沒有流程；發現卡的關係名稱每週會變，但字體跟著頁面殼、只在前端改版時部署

- **類別**：6
- **UX 文件**：`DESIGN.md` Typography：「正式版內嵌一套…中文字體，只打包標題用到的字（子集字型）」「例外：示範站首頁發現卡的關係名稱（`finding-zh`）是會變動的內容。示範站是事先產生的快照，**產生時把用到的字一起打包**」`[ASSUMPTION]`；首頁規格 §3.3：發現卡的關係是「宋體 300／32px」，屬於鎖定的第一屏
- **架構**：ADR-0007「放置與更新」：「頁面殼（HTML、JS、CSS、**字體**）…只在前端改版時部署」；理由第 5 點：「正式主機不用裝 Node 或部署工具」；ADR-0010 第 10 項只說字體自己放；Deferred「中文標題字體」只提到要能自己放；Stack 沒有任何做子集的工具
- **問題**：每週的資料檔是正式主機上的 Python worker 產生的。發現卡換了一條關係、出現字體檔裡沒有的字時，那幾個字會掉回系統字體，鎖定的畫面就破了。介面固定文字的子集（建置時從 i18n 文字算）也沒有人負責。
- **建議的最小補法**：Deferred 那一列補上要一起決定的事：(a) 固定文字的子集在前端建置時由 `web/src/i18n/` 產生；(b) 發現卡的字：產生器用 Python 的 fonttools（不需要 Node）另出一個小字體檔 `data/sNN/finding.woff2`，同網域所以 CSP 不用改。或者 (c) **Kevin 決定**發現卡的關係名稱改用內文字體（要改鎖定的畫面）。不確定就先記 (b)，等字體選定時一起做。

#### M-10 效能太差或瀏覽器不支援時用的「事先算好的靜態星系圖」，沒有人產生

- **類別**：5（也算 1）
- **UX 文件**：首頁規格 §8：「瀏覽器不支援或效能太差｜改放一張事先算好的靜態星系圖，並附完整的替代文字」；`EXPERIENCE.md` State Patterns「1. 示範站首頁」同一列；§9 手機：「偵測到跑不順時自動換成 §6.7 的靜止版」
- **架構**：ADR-0010：「偵測與切換成靜止版的機制照規格 §6.7、§8」；Deferred 只列門檻；ADR-0007 的檔案清單沒有圖檔
- **問題**：這裡其實有兩種退場，容易混在一起：「靜止版」（§6.7，同一張畫布畫一格就停，瀏覽器自己算）和「靜態圖」（§8，連畫布都不能用時的圖片）。後者每週資料變了就該重畫，但畫星系的程式是 JavaScript，正式主機沒有 Node。
- **建議的最小補法**：ADR-0010 加兩句：「靜止版＝同一支畫布程式只畫完成的那一格；偵測放在首頁元件裡，量前幾格的每格時間」；「靜態圖在前端建置時用同一支畫布程式產生，跟頁面殼一起部署，可以比資料舊；圖旁的替代文字用 `manifest.json` 的數字」。這樣不需要在主機上畫圖。

### Low

#### L-1 關係的幾個數字沒有定義處；自我檢查的等式在有「不計入研究篇數」的來源論文時不成立

- **類別**：1
- **UX 文件**：「6. 關係排行表」：「一行『已審合併的構念占比 N%』」；排序「最新年份」；篩選「主題」；示範站「示範站列出 N 條關係（全庫共 M 條）」；展開列「概念主張與文獻回顧的那幾篇標『不計入研究篇數』」
- **架構**：AD-16：`relation_stats` 定義「研究篇數、支持篇數、混合支持、本資料庫中少見、合併未完成、覆蓋率警告」；ADR-0007 自我檢查第 4 項：「每條關係『可列出的來源論文』數加上『另有 N 篇不在示範站』等於研究篇數」
- **問題與補法**：(a)「已審合併的構念占比」的分子分母、「最新年份」、關係的主題（從來源論文的分類來）沒有寫在那個「唯一的 view」裡，補進 ADR-0012 的清單。(b) 來源論文清單包含不計入研究篇數的論文，等式要改成「計入研究篇數的可列出來源＋另有 N 篇＝研究篇數」。(c) `relations.json` 最外層帶全庫關係總數 M。

#### L-2 問答的三個小缺口

- **類別**：1 與 2
- (a) UX：「計數題導流…＋**帶入條件的**趨勢頁連結」；ADR-0006：「計數題：送出 `route`…模型後面寫什麼都丟掉」。條件沒有地方傳。補法：v1 連結不帶條件（UX 改一個詞），或 `route` 事件帶經過清單驗證的主題。建議前者。
- (b) UX：熔斷時「送出後顯示的是找論文的結果」；ADR-0006：`retrieval_only`「直接回檢索到的論文清單」。六個事件裡用哪一個帶這份清單沒寫。補法：用 `citation` 事件，或前端收到這個 `route` 就改呼叫搜尋。
- (c) UX：我的問答紀錄「點開看當時的回答」，展示問答要顯示「找不到」與導流的例子；ADR-0006 第 6 項的紀錄內容是「問題、回答、通過驗證的出處、拿掉的數量」，沒有 `route`。固定說明是前端文字，沒有 `route` 就不知道要畫哪一種。補法：`qa_log`、`demo_qa`、`qa.json` 都存 `route`。

#### L-3 資料模型的小缺口（欄位由實作決定，但寫的人和讀的人在不同 Story）

- **類別**：1
- 「8. 論文頁」我的檔案要顯示「檔名」，上傳進度表每個檔案一列；ADR-0013 `pdf_file` 的欄位清單與物件路徑（`<SHA-256>.pdf`）都沒有原始檔名。補：`upload_item` 與 `pdf_file` 存原始檔名（不進日誌）。
- 「使用者輸入、未經 OpenAlex 驗證」標記與「刪除這筆書目」：論文要知道自己是手填的、是誰填的。AD-6 有 `create_manual`，但 `paper` 沒有擁有者。補：`paper` 記來源（追蹤／匯入／手填）與手填者。
- 「13. 我的文獻庫」篩選「我上傳的／別人分享的／我自己加入的」：`library_item` 要記加入方式。
- 「18. 帳號選單」「只顯示名稱」、修正歷史顯示姓名：ADR-0008 第 6 項的名稱是 CLI 選填。補：`--name` 必填。
- 「11. 系統首頁」「第二次以後登入，區塊 3 移到區塊 2 上面」、問答「第一次進來時」的說明：要約定記在伺服器（成員的第一次登入時間）還是瀏覽器。建議前者，換裝置才一致。

#### L-4 移出文獻庫後的「復原」

- **類別**：1
- UX：「移出一篇｜那一列原地變成『已移出』＋『復原』，離開頁面後消失」；AD-26：「刪除資料時先複製到 `deleted_record` 再刪」。復原要還原加入方式與加入時間，一般的「加入」端點做不到；而且私人的追蹤範圍外論文一移出，本人就看不到它了（AD-4）。補法：前端延後到離開頁面才真的送出刪除，或提供一個限時的還原端點。建議前者，不用新端點。

#### L-5 兩個「會有兩份實作」的計算沒有共用的驗收檔

- **類別**：1
- 引用匯出：Capability Map 寫 FR-33 在 `services/exports.py`，「示範站在前端用同樣的欄位產生」。APA、RIS、BibTeX 的格式會有 Python 與 TypeScript 兩份。補法：比照 AD-19 放 `tests/golden/exports/`，兩邊都要過；或兩種建置都只用前端那一份。
- 平均每年被引用次數：首頁規格 §5.4 的公式「累計 ÷（資料截止年 − 出版年，最少算 1 年）」，首頁和論文頁都要用。補法：放進 `web/src/stats/`，AD-19 的清單加這一項。

#### L-6 「摘要未提及」在資料裡怎麼表示

- **類別**：1
- UX：「固定的文字不可以改寫：…『摘要未提及』」；`DESIGN.md` 中文重點區塊：「『摘要未提及』用 `{colors.text-tertiary}`」。畫面要認得出這一欄是「沒提到」才能換顏色。如果資料裡存的是模型寫出來的那四個字，前端只能比對字串。補法：`domain/validators/` 規定沒提到的欄位存空值，文字由 i18n 出；AD-8 的工作驗證加這一條。

#### L-7 前端的三個全站設定沒寫

- **類別**：5 與 6
- **減少動態**：UX Interaction Primitives「系統設定減少動態時，全部改成直接顯示」，每個畫面都適用。架構沒有約定做法。補：Conventions 加一句，用一條全站 CSS 規則關掉過場，加一個共用的判斷函式給首頁與 60 秒示範用。
- **斷點**：`DESIGN.md` Layout：1200、768，有輔助欄的畫面另用 900 與 1232。ADR-0010 說清掉 Tailwind 內建的「顏色、間距、字級」，沒提斷點；內建的是 640／768／1024／1280，不改的話大家會順手用 1024。補：斷點也清掉，只留 `DESIGN.md` 的四個值。
- **CSP 與內嵌資源**：AD-22 的 CSP 是 `default-src 'self'; img-src 'self'`，不允許 `data:` 網址。Vite 預設會把很小的圖檔與字體直接內嵌成 `data:` 網址（請在第一個前端 Story 確認目前版本的預設值），在正式環境會被 CSP 擋掉，本機開發伺服器沒有 CSP 所以看不出來。補：ADR-0010 註明關掉內嵌，並讓 Playwright 跑在帶 CSP 的建置結果上。

#### L-8 無障礙測試的範圍沒寫

- **類別**：5
- UX Accessibility Floor：「目標是 WCAG 2.1 的 AA 等級」「頁面語言標成繁體中文，英文的論文標題與原文摘要標成英文」；Responsive：「瀏覽器支援最近兩個主要版本的 Chrome、Safari、Edge、Firefox」；首頁規格 §13：原型「沒有測過 Safari、Firefox、Windows、手機」。
- 架構：工具有（Stack 的 Playwright 與 axe；CI 固定檢查有「Playwright＋axe」），但沒寫：axe 用哪一組規則、掃哪些頁面（兩種建置的每個路由？）、Playwright 跑哪幾種瀏覽器引擎與哪幾個寬度、語言屬性由誰加。
- 補：Conventions「測試」那一列加一句：axe 用 WCAG 2.1 A 與 AA 的規則，兩種建置的每個路由各掃一次；Playwright 至少跑三種引擎，寬度取手機、900 上下、桌機；論文標題與原文摘要只經共用元件顯示，由它加語言屬性（手填的中文論文要看論文的語言欄位）。

#### L-9 固定網址在靜態主機上需要「找不到檔案就回首頁殼」的設定；`manifest.json` 與資料檔的快取沒寫

- **類別**：1
- UX：「每篇論文、每條關係…有固定網址」「重新整理或把網址給別人，看到的是同一個結果」。示範站是單頁應用程式放在靜態主機上，直接打開 `/papers/某篇` 時主機上沒有這個檔，要設定成回傳頁面殼（常叫 SPA fallback）；成員版由 api 容器送前端檔案，也要同樣處理 `/api/` 以外的路徑。ADR-0007、AD-21 都沒寫。
- `manifest.json` 會被覆寫，快取太久訪客會一直看到舊資料；帶編號的資料檔永遠不變，應該讓瀏覽器長期快取。補：ADR-0007 加兩句（manifest 每次重新驗證；帶編號的檔案標成不變）。

#### L-10 示範站三件沒人負責的小事

- **類別**：1
- 「4. 架構與評估」：「產生快照時要檢查這個連結打得開」。ADR-0007 的自我檢查沒有這一項；而且它是一次對外連線，照 AD-2 要經過 port。補：改成 Kevin 手動執行的 CLI 檢查，或寫明不做。
- 「2. 60 秒示範」：「示範檔隨快照一起發佈」，還要一張第一格的小預覽圖。Capability Map：FR-45「不是程式；素材放 `docs/`」。放 `docs/` 的檔案示範站讀不到（CSP 只允許同網域）。補：示範檔與預覽圖放前端的靜態資源，跟頁面殼一起部署。
- 兩個站互相連：示範站的「成員登入」、登入頁的「回示範站」、登出後「回到示範站首頁」。兩邊的網址是建置時的設定，AD-18 只講後端的環境變數。補：ADR-0010 第 3 項加兩個建置變數。

#### L-11 之後才會碰到的兩個定義

- **類別**：1
- Semantic Scholar 的摘要（Could）上線時：UX H5 說示範站的「有摘要」不含它；AD-20 說這類論文「不輸出完整內容與分類標籤」。那麼 `PublicViewer` 看到的「有沒有摘要」、示範站計數方塊裡這些論文算哪個主題、論文頁要不要第四種狀態（UX 寫「三種都顯示分類」），都還沒定義。現在不用做，建議記進 Deferred。
- AD-11 的 `tracked` 範圍是「只有追蹤範圍內的論文」，計數用的 `counted_paper` 另外排除了非研究文章與還沒發佈的快照。成員從篇數連結進到找論文、再打字搜尋時，兩邊母體差一點。補：AD-11 註明 `tracked` 等於 `counted_paper`。

#### L-12 成員確認合併後「只有管理者能更改」，要寫進權限表

- **類別**：1
- UX「15. 證據簡報」：「你的確認在按下後立即生效，之後只有管理者能更改」；AD-16：「每對取最新決定，管理者蓋過成員」。照「取最新決定」，另一位成員對同一對再送一筆就會蓋過去。畫面上不會出現這個入口，但 API 擋不擋沒寫。補：AD-27 的權限表加一列「已經有決定的配對，只有管理者能再決定」。

## 五、查過、沒有問題的（方便之後不用重查）

- **可見範圍與狀態標記**：追蹤範圍外（`in_scope`）、只有你看得到／全實驗室看得到（`lab_visible`）、沒有權限等於找不到（AD-3 同一個 404）、匯入後不能改分享（AD-4）。
- **數字**：資料日期列（AD-19 每個帶數字的回應都有 `snapshot`）、本週新增的定義、未滿一年與成長排名只在 `web/src/stats/`、每一格計數都能從論文清單查回同樣篇數（成員版有測試、示範站有自我檢查）、資料更新中不顯示（快照成功才發佈）。
- **問答**：逐字與驗證的先後、拿掉幾個出處、找不到與計數題不扣題數、逾時與中途離開不扣題數、刪除紀錄後題數不歸零（`qa_usage`）、紀錄只有本人看得到、固定說明是 i18n 文字。
- **關係與證據簡報**：關係的網址由兩個構念 ID 組成、已併入不自動跳轉、研究篇數 0 預設不列、成員確認立即生效並標「待管理者複核」、證據層級自動記、簡報不存檔每次重算、不呼叫 LLM。
