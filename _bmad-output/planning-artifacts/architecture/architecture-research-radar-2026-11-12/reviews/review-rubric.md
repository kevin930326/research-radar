## 一句總評

這份文件抓到的分歧點很準、規則大多配了測試，形式也乾淨；但有兩條「資料形狀」的規則照字面做不出來（AD-7 的單一有效版本、AD-14 的 Batch `custom_id`），分層圖比其他規則還嚴而互相矛盾，營運面（還原、保留期、部署步驟、非 LLM 的費用上限）有幾塊完全沒提，建議修完「高」的 5 項再交給拆 Story。

## 發現（依嚴重度）

嚴重度的意思：**高**＝不修的話，第一批 Story 就會卡住，或做出事後難改的資料形狀；**中**＝兩個 Story 可能做得不一樣，但改得回來；**低**＝文字或一致性的小問題。

### 高

#### H-1　AD-7「同一篇、同一工作、同一語言只有一筆 active」對多列的表做不出來

- **證據**：AD-7 寫「每張存 AI 產出的表都有 … `status`；部分唯一索引保證同一篇、同一工作、同一語言只有一筆 `active`」。但核心資料圖裡 `construct_mention`、`hypothesis` 是一篇論文多列（一篇有好幾條假設），`classification` 是多標籤也可能多列。「一篇只有一筆 active」的唯一索引在這些表上建不起來。
- **連帶的三個洞**：
  1. 沒有「候選」狀態。ADR-0009 的換模型流程是「新模型的結果先存成不是有效版本，評估過了才切換」（FR-4 的回歸門檻），但 `status` 只有 `active`／`superseded`／`rejected`，新結果沒有地方放。
  2. 哪些表算「AI 產出的表」沒列。`embedding` 在圖上有來歷（`derivation_run`），但它的主鍵是（項目, 模型），內容是覆寫的，和「內容欄位不 UPDATE」衝突；`merge_suggestion` 的前兩層不用 LLM，沒有 `run_id` 可填。schema 體檢測試要檢查哪幾張，寫的人只能自己猜。
  3. 向量的來歷與費用由誰寫沒有指定：LLM 有閘門（AD-8），embedding 只有外送檢查（AD-9），沒有對應的「記來歷、記額度」的單一入口。
- **為什麼是高**：FR-1 被 PRD 列為「事後無法重建」的資料骨架，要在第一次十年匯入之前定案；摘要、分類、擷取是不同 Story，各自解讀就會做出三種形狀。
- **建議**：把「有效」提到「一次產出」的層級。例如每個（論文, 工作, 語言）一筆產出主檔（或直接用 `derivation_run`）帶 `status`，明細列（假設、構念提及、標籤）只指向它；`status` 加一個 `candidate`；在 AD-7 列出適用的表名，並寫明 `embedding` 與 `merge_suggestion` 是例外以及它們各自的規則。

#### H-2　AD-14 的 Batch `custom_id` 少了輸入雜湊，合法的重跑會被唯一約束擋住

- **證據**：`custom_id`＝論文 ID＋工作代碼＋prompt 版本，而且「有唯一約束」。但 AD-25 規定摘要更新時（`source_hash` 變了）要重新處理，AD-7 規定重跑是「新增一筆」。同一篇、同一工作、同一個 prompt 版本第二次送 Batch 時，`custom_id` 一模一樣，會撞唯一約束（或被當成「做過了，跳過」）。被驗證拒收（`rejected`）之後想重送，也是同一個情況。
- **另外**：`merge_judge` 這個工作的對象是「一對構念」，不是論文，格式裡的「論文 ID」套不上。
- **建議**：`custom_id` 加上輸入雜湊的前幾碼（例如 `input_sha256` 前 12 個字元，仍在 64 字元內），唯一約束的意思才會是「同一份輸入不重送」；把「論文 ID」改成「對象 ID」。修的時候順便把 Batch 的規則從 AD-14 拆成獨立一條（見「Rule 過長」）。

#### H-3　AD-1 的依賴圖比其他規則嚴，照圖寫不出 import-linter 契約

- **證據**：圖下寫「圖上沒有的箭頭就是不可以」。但其他規則需要圖上沒有的箭頭：
  - api 要建立 `MemberViewer`（AD-3）、services 把 `radar.domain` 的型別回給入口（AD-2）→ 需要 entrypoints → domain，圖上沒有。
  - `bootstrap` 要建立資料庫連線，而 `sqlalchemy` 只能出現在 `radar.repo`（AD-1）→ 需要 bootstrap → repo，圖上沒有。
  - worker 用 Procrastinate 定義工作，而排入的實作在 `adapters/jobs`（AD-1 自己列的例外）→ 需要 worker → adapters，圖上只有 bootstrap → adapters。
  - `radar/config.py` 不在圖上，誰可以 import 它沒說。
  - ADR-0001 的表格寫入口「可以 import 以上全部」，和圖直接矛盾；AD-3 又單獨寫「api 不得 import `radar.repo.models`」，暗示 api 可以 import repo 的其他模組。三處說法不同。
- **連帶**：`Viewer` 型別放在哪個模組沒寫（原始碼結構的 domain 清單裡沒有）。AD-27 說會改資料的 services 函式第一個參數是 `actor`，AD-3／AD-11 說讀取的第一個參數是 `viewer`；兩者是不是同一個物件、worker 呼叫時傳什麼（系統身分的 actor？）沒有定義。這是每個 services 函式的簽名，各 Story 一定會碰到。
- **建議**：補上缺的箭頭（或把那句話改成「下列是禁止的方向」並逐條列出）；在 AD-3 或 AD-27 寫一句「`Viewer` 與 `Actor` 定義在 `domain/…`，關係是 …，worker 用 …」。圖、AD-1、ADR-0001 三處對齊。

#### H-4　交易與外部呼叫的關係沒定；重試由誰負責沒定

- **證據（交易）**：Conventions 寫「一個 services 函式一個交易；repo 的函式不 commit」。AD-8 的閘門在一次呼叫裡依序「寫 `derivation_run` → 呼叫 LLM → 寫 `llm_call`」。照字面做有兩個問題：(1) 交易開著等一次幾秒到幾十秒的網路呼叫，佔住連線；(2) 之後驗證失敗或外層回滾時，`llm_call` 這筆費用紀錄跟著消失，帳本少算，預算熔斷（NFR-3）會失準。AD-14 對「排工作」有寫清楚（先完成交易再排入），對「呼叫外部服務」沒有。
- **證據（重試）**：Stack 有 stamina（重試函式庫），ADR-0004 說工作失敗會自動重試，ADR-0009 說連線錯誤自動重試；脊柱裡搜尋不到「重試」「逾時」「速率」任何一個字。重試放在 adapter、閘門還是工作層沒定，兩層都做就是次數相乘；FR-10 的 409／429 退避、AGENTS.md 的「遵守速率限制」也沒有落到任何一條規則。
- **證據（三種呼叫方式）**：AD-8 的固定順序是照「一次同步呼叫」寫的。串流問答是邊送邊驗（AD-13），Batch 是「送出」與「匯入結果」分在兩個工作；這兩種情況「寫 `llm_call`」與「驗證」各發生在哪一步沒說。
- **建議**：在 Conventions 加兩列。「外部呼叫」：不在開著的交易裡呼叫外部服務；來歷與帳本用自己的短交易寫入，外層回滾不影響。「重試與逾時」：只在 adapter 做（次數、退避、逾時放設定），工作層的重試只處理整個工作失敗。AD-8 補一句三種呼叫方式各自的步驟對應。

#### H-5　營運面有幾塊完全沒提

逐項狀態見第 6 條的表。沒提、而且會影響 Story 的有：

1. **還原**：只有 `radar backup`，沒有還原的指令或步驟；FR-48 要求上線前實際還原一次，ADR-0003 還把「還原到 Oracle」當成搬家演練。
2. **備份保留期與金鑰**：FR-31 說問答紀錄的備份「隨保留期到期自然消失」，但保留幾天沒定；age 的解密金鑰放哪裡沒定（正式主機上只該有加密用的公鑰）。
3. **物件儲存本身的備份**：`pg_dump` 只備資料庫。R2 裡的原始資料（FR-2 說是「事後無法重建」的）和成員的 PDF 沒有備份策略，也沒有寫「不備份、接受風險」。
4. **心跳會互相蓋掉**：AD-15 說「每個排程工作成功後送心跳」，AD-20 也用「不送心跳」當告警；Deferred 卻寫「`Heartbeat` 只需要一個網址」。每 15 分鐘成功一次的 `sweep` 會一直報到，每週更新或備份失敗時監看服務看不出來，AD-15 想防的事防不住。
5. **部署怎麼做**：映像推到哪裡（GHCR 只寫在 ADR-0003）、誰在主機上換版、`radar migrate` 在換版的哪一步跑、怎麼退回上一版，脊柱都沒有；也沒有列進 Deferred。
6. **資料庫角色**：AD-10 要求應用程式的角色對兩張表沒有 UPDATE／DELETE 權限，代表至少要有「遷移用」和「應用程式用」兩個角色；AD-17 卻說只有一個 `DATABASE_URL`。遷移用哪組帳密、本機與 CI 怎麼建這兩個角色沒定。
7. **非 LLM 的費用與容量上限**：LLM 有預算檢查；OpenAlex 每日免費額度（1 美元）、Workers AI 每日免費額度（10,000 neurons）、R2 免費 10 GB 都只在 memlog 裡。特別是 AD-25「每筆回應都存」：OpenAlex 的指標每晚重算，「雜湊沒變就不重存」幾乎不會成立，每週約一萬個新物件。我粗估一年 1.5～4 GB（**沒有實測，只是量級**），加上 PDF 配額（4 人 × 1.5 GB）與每晚備份，第一年就可能碰到 10 GB。需要一個保留規則或上限。
8. **日誌大小上限**：NFR-15 明寫要有，Conventions 的日誌那一列沒有。

- **建議**：AD-17 的備份拆成獨立一條並補上還原、保留期、金鑰、R2 物件四件事；`Heartbeat` 的方法帶「檢查名稱」，一個排程一個網址；「部署步驟與退版」「資料庫角色」「非 LLM 額度」各自寫成一條規則，或明確放進 Deferred 並寫上什麼時候決定。
