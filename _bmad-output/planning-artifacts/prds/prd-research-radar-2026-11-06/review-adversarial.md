# 對抗式審查：PRD Research Radar

## 總評

這份 PRD 的骨架很好：定位句清楚、資料骨架（FR-1～FR-7）抓對了「事後救不回」的東西、誠信與授權規則比多數學生專案嚴格。但它還不能安全交給架構與拆 Story，主要卡在三件事：**（1）Must 工時的基準是一個看不到明細的數字，新加項目的增量又明顯偏小，導致第 8.5 節的範圍控制規則實際上無法執行；（2）核心價值主張「每個引用有原句、可驗證」在 Must 層只做到「引用存在」，驗收條件沒有量「引用是否真的支持該主張」；（3）幾條安全與授權的關鍵承諾（權限函式不可繞過、示範站只放「開放取用」）寫成了意圖，不是可驗收的機制。**

嚴重度統計：Critical 1、High 6、Medium 13、Low 8，共 28 項。標「待確認」的項目是我沒有把握、需要 Kevin 回答事實的。

## Critical

### A-1　Must 工時的基準不透明，且新增項目的增量不合理地小，第 8.5 節的觸發規則因此無法執行
- **類別**：3 Must 範圍與工時預算
- **PRD 位置**：§8.1「樂觀約 121 h／中位約 152 h／悲觀約 184 h」「計算過程見 addendum」；addendum「Must 工時重算」表：起點「報告：現有 Must＋M01–M12 138／163／188」、「＋FR-50 個人文獻庫 +1／+1.5／+2」、「＋FR-49 推薦清單匯入＋下載聲明 +0.5／+0.75／+1」；§8.5「重估後若 Must 超過 150 h，依序啟動 K6 → K8 → K9」。
- **問題說明**：
  1. 整條計算鏈的起點是研究報告 §6.3 的「現有 Must 估計 120／142／164」，報告裡沒有逐功能明細，PRD 與 addendum 也沒有。沒有明細，拆 Story 時無法知道每個 FR 分到多少時數，重估時也無法知道「超過 150 h」是哪裡超的；K6／K8／K9 各自省幾小時的說法沒有基準可以對照。
  2. FR-49＋FR-50 合計中位 2.25 h，但內容包含：上傳頁兩種模式與下載聲明 UI、從 PDF 第一頁讀 DOI／標題（ARCH-9，v1 不用 GROBID，要另選 PDF 文字庫）、單篇 DOI 向 OpenAlex 補書目與摘要（和期刊列表匯入是不同的程式路徑）、追蹤範圍外旗標在趨勢／覆蓋率／排行表所有查詢中一致排除（ARCH-14）、追蹤範圍外論文進完整 LLM 流程、「換成我自己下載的版本」、手動確認書目的介面、暫存檔刪除測試、個人文獻庫表與增刪 UI、問答範圍過濾、批次開啟 DOI。合理估計是 8–15 h，不是 2 h。
  3. 和原始輸入矛盾：brief「解決方式」第 5、6 項（`brief.md`）與 brief-input F5、F6 本來就有「自己的文獻庫／個人文獻庫」。PRD §8.1 卻說 FR-50 是「定稿階段加入」。要嘛原本的 142 h 已含個人文獻庫（則 +1.5 h 是重複計算，問題小），要嘛原本估計漏掉 brief 的 Must 項目卻沒有說明（問題大）。兩種情況都說明基準不可信。
  4. 有幾塊 Must 工作在任何地方都找不到時數：金標準標註的人力（見 A-6）、OA 全文 TEI 管線（見 A-5）、靜態快照產生器（FR-42 是獨立的建置流程，不是現有頁面的副產品）、每週更新的排程與重試、前端十幾個畫面（論文頁至少 8 個動作：修正分類、加入文獻庫、找相似、複製 APA、RIS／BibTeX、OA 連結、換成自己的版本、AI 標章）。
- **後果**：拆 Story 時每個 Story 的大小沒有依據；重估時若發現超支 30 h，不知道該砍哪裡；最壞情況是「不砍驗證」的底線被迫破功。
- **修改建議**：
  1. 在 addendum 加一張「Must 逐 FR 工時表」（FR-1～FR-50 的 Must 項各一列，樂觀／中位／悲觀），總和要對得上 §8.1 的數字；對不上的差額要寫出來是什麼。
  2. 把 FR-49、FR-50 的估計改成逐項列出的子工作（至少 8 個子項），重新加總。
  3. 把「金標準標註人力」「OA 全文 TEI 管線」「靜態快照產生器」「前端畫面」列成獨立列，不能隱含在別的 FR 裡。
  4. §8.1 刪掉「FR-50 為定稿階段新增」的說法，改寫成「FR-50 來自 brief F5／F6，原估計是否包含待核對」。
  5. §8.5 的觸發規則加一句：「重估以逐 FR 工時表為基準，每次重估更新該表」。

## High

### A-2　支柱一承諾「每個引用有原句」，Must 只做到「引用存在」；「引用正確率」沒有定義
- **類別**：1 前後矛盾、2 無法驗收、6 作品集面試弱點
- **PRD 位置**：§1 支柱表「每個引用有原句」；FR-28「引用到論文層級」；FR-29「不存在的引用不得顯示」；FR-41「問答：量引用正確率」；SM-3「引用 100% 存在於資料庫」；S06（Should）「原生引用……顯示原句」；FR-28「依據是摘要＋中文結構化摘要＋研究模型」。
- **問題說明**：
  1. 支柱一在 Must 層沒有兌現：原句引用是 S06（Should，寒假第三梯）。v1 的引用只到論文層級，使用者只知道「答案引用了論文 X」，不知道 X 的哪一句支持這個說法。研究報告 §1 第 4 點明說「引用存在不等於引用正確」，PRD 的 Must 驗收只量了存在。
  2. FR-41「引用正確率」沒說定義：是「引用的論文存在」（那和 SM-3 重複，必然 100%，因為是程式過濾），還是「引用的論文確實支持答案裡歸給它的主張」（這才是面試官與老師在意的）。沒有定義就沒有通過／不通過。
  3. FR-28 把兩種 AI 產出（中文結構化摘要、研究模型）當成問答依據。答案可能引用論文 X 來支持一個只存在於 AI 摘要、不存在於論文原文的說法；引用驗證（FR-29）抓不到這種錯。這是「AI 產出被當成論文內容使用」的典型路徑，和 §4.4「中文摘要只供篩選」的定位矛盾。
  4. 面試追問「你怎麼知道回答沒有張冠李戴？」目前 PRD 只能答「引用的論文都存在」。
- **修改建議**：
  1. §1 支柱表改成 v1 能兌現的句子：「每個引用點得回原始論文；原句層級的引用列為 S06」。或把 S06 升為 Must（報告估 S–M，約 4–8 h）。
  2. FR-41 問答一節改寫為兩個指標：「引用存在率」（程式驗證，目標 100%）與「引用支持率」（人工抽檢 30–50 題，每個引用判定「支持／部分支持／不支持」，報告比例，不設門檻但公開）。
  3. FR-28 加一條規則：問答的檢索與引用依據只用「原文摘要」與「研究模型的假設原句」（原句本身已由 FR-3 驗證存在於輸入）；中文結構化摘要只用於檢索排序，不進入生成的上下文。若 Kevin 決定仍要放進上下文，PRD 要明寫這個取捨與風險。

### A-3　FR-7「繞過權限函式的查詢會被體檢測試抓出」沒有可實作的機制；授權規則只涵蓋讀取
- **類別**：5 資安、2 無法驗收
- **PRD 位置**：FR-7「所有讀取權限都經過同一個權限判斷函式；繞過它的查詢會被體檢測試抓出」；NFR-2「可見範圍的過濾由程式強制，不依賴提示詞」；addendum R7 `policy.can_read(user, resource)`。
- **問題說明**：
  1. 「體檢測試抓出繞過它的查詢」是結論不是機制。一個普通的 schema 體檢（檢查欄位存不存在）抓不到「某條 SQL 沒有經過 can_read」。架構階段拿到這句話無法落地；拆 Story 時也寫不出驗收步驟。
  2. 只定義了讀取。v1 有多種寫入會跨使用者：任何成員可修正任何論文的分類（FR-16，全實驗室生效）、移出個人文獻庫、上傳與刪除 PDF、構念合併（管理者）。誰能刪誰的 PDF、誰能改誰的文獻庫、成員能不能刪別人的修正事件，PRD 沒寫。NFR-16 只記稽核，不是授權。
  3. 這是整個「私人資料」邊界的唯一防線，又是面試官最會追問的點（「權限檢查在哪一層？怎麼保證沒漏？」）。
- **修改建議**：
  1. FR-7 第一條改成可驗收的機制，三選一並寫進 PRD：(a) 所有資料存取函式必須接收 `viewer` 參數，架構測試（import-linter 或自訂 AST 檢查）禁止 API 層直接 import ORM 模型或 session；(b) 以 PostgreSQL 的 row-level security 在資料庫層強制，應用層只設定目前使用者；(c) 每個回傳使用者資料的 API 端點都有「以另一位成員身分呼叫應得 403／空集合」的測試，並用 OpenAPI 清單自動檢查每個端點都有這種測試。
  2. 加一條「寫入權限」規則：列出 v1 所有跨使用者的寫入動作（分類修正、合併、文獻庫、PDF 刪除、修正事件撤回），逐一標明誰可以做；至少規定「只有本人能刪自己的 PDF 與文獻庫項目；修正事件不可刪除，只能新增」。

### A-4　示範站的「開放取用」沒有定義；出版社摘要與其 AI 衍生物會被公開且永久保存
- **類別**：4 授權與學術誠信
- **PRD 位置**：FR-42「只放開放取用論文……主機到期後照樣可以看」；FR-43「只用 OA 論文」；§3 名詞表「OA 全文：OpenAlex 標示為 CC 授權、可合法自動抓取的全文」；addendum R7「bronze OA 不視為可再利用」；FR-45「對比用的論文挑 CC BY 授權的」。
- **問題說明**：
  1. 名詞表只定義了「OA 全文」，沒有定義「開放取用論文」。OpenAlex 的 `is_oa` 包含 bronze（可免費讀但沒有授權）與 green（只有典藏版預印本，正式版仍付費）。如果示範站用 `is_oa:true` 當篩選，會公開 bronze 論文的出版社摘要與 AI 衍生物，和 addendum「bronze 不視為可再利用」矛盾。
  2. 示範站會公開什麼內容沒寫：只有書目？還是含原文摘要、中文結構化摘要、構念與假設原句？原文摘要的著作權屬出版社（OQ-02b §7 自己也這樣寫）；中文結構化摘要是摘要的衍生作品。對 CC BY-NC-ND 的論文，公開衍生作品（ND＝禁止改作）有疑慮；對 NC 的論文，放在求職作品集算不算商業用途也有解讀空間。FR-45 挑 CC BY 做 GIF 是對的，但這個謹慎沒有延伸到整個示範站。
  3. 不可逆：靜態快照是公開、永久、不需後端的，一旦放上去就很難收回（會被快取、被面試官截圖）。這是 PRD 裡最公開的輸出，卻是授權規則寫得最鬆的地方。
  4. 這是法律判斷，我不確定；但 PRD 至少要讓規則可執行。**待確認**。
- **修改建議**：
  1. 名詞表新增「示範站可用論文」：`best_oa_location.license` 屬於明列的 CC 清單（建議 CC BY、CC BY-SA；CC BY-NC 與含 ND 的授權要 Kevin 決定，並寫理由），排除 bronze 與無授權的 green。
  2. FR-42 列出示範站公開的欄位清單（例如：書目、OpenAlex 連結、分類、覆蓋率統計、構念關係計數；原文摘要與中文結構化摘要是否公開要明寫）。原則建議：示範站的「發現卡」與展示問答只引用示範站可用論文；趨勢數字可用全庫計數（計數不是著作）。
  3. 加一條驗收：「示範站產生器以白名單欄位輸出，單元測試確認沒有白名單外的欄位、沒有 bronze／無授權論文的摘要與衍生物」。

### A-5　FR-13 把 OA 全文擷取列為 Must，但數量未知、OpenAlex 全文費用未入預算、授權變體未處理
- **類別**：3 工時預算、4 授權、1 前後矛盾
- **PRD 位置**：FR-13 表「摘要、OA 全文｜送雲端 Haiku｜Must」；FR-13「v1 的 OA 全文來源是 OpenAlex 已解析的全文（GROBID TEI，每篇約 0.01 美元），只取 CC 授權者」；§11.2「OQ-10 spike……決定 v1 OA 全文有多少」；§6「費用」只列 LLM；研究報告 §4.2 表把 OpenAlex TEI 標為「Must（規則）／Should（使用）」。
- **問題說明**：
  1. 研究報告把「只用 CC 授權 TEI」當規則列 Must、實際使用列 Should；PRD 把使用也升成 Must，但沒有對應的工時增量（addendum 重算表沒有這一列）。全文管線和摘要管線不同：抓 TEI、解析 XML、切塊（addendum R5 說 4,096 token）、全文向量、全文萃取的 prompt、證據來源標示、頁碼。這是一條新管線，不是摘要管線的參數。
  2. 數量未知：OQ-10 spike 還沒做（§11.2），14 本期刊有多少 CC 授權全文沒人知道。OQ-02 顯示 Elsevier 4 本 OA 比例 38%（979／2,573）但那是 `is_oa`，不是 CC。全部 9,643 篇若 30% 有 CC 全文，TEI 費用約 $29，剛好是整個月的 LLM 上限，§6 完全沒提。
  3. 授權變體：「CC 授權」沒說哪些。CC BY-ND 的全文送 LLM 產生中文摘要與研究模型再全實驗室共享，是否算改作，和 A-4 同一個問題；至少要指定清單。
  4. 和 §8.5 的刪減槓桿矛盾：K5 縮小版號稱省 4–6 h（不跑 GROBID），但同時加進了 TEI 管線，淨效果可能是負的。
- **修改建議**：
  1. FR-13 表的第一列拆成兩列：「摘要｜Must」「OA 全文（CC 清單內）｜Must（規則：只有這種全文能自動送雲端）／實作時機：OQ-10 結果 ≥N 篇才在 v1 做，否則 Should 第一順位」。N 由 Kevin 定（建議 300 篇以下不值得在 v1 建管線）。
  2. addendum 重算表加「OA 全文 TEI 管線」一列（建議 6–10 h）。
  3. §6 費用加「OpenAlex 全文 TEI 約 $0.01／篇，預算上限 $X，超過只取近 N 年」。
  4. 名詞表「OA 全文」補上 CC 清單（同 A-4）。

### A-6　金標準標註的人力沒有入帳，且和 schema 定版、分類清單定版、主題抽樣形成循環依賴
- **類別**：3 工時預算（依賴順序）、2 無法驗收
- **PRD 位置**：FR-41「50 篇……同時標註主題、方法與研究模型（構念、假設）」「Kevin 和同學各自試標 5 篇」「另請一位同學獨立標註其中 15 篇」「抽樣涵蓋各期刊與主題」「摘要可見欄位」；FR-3「schema 在第一次十年批次與金標準標註前定版」；§11.5「OQ-07 分類清單……要改必須在 50 篇金標準標註前改」；§4.1「順序：FR-6 → FR-2 → FR-1 → FR-3／FR-4 → FR-5 → FR-7」。
- **問題說明**：
  1. 人力：要算「只看摘要的漏失率」，標註者必須讀全文標出所有假設。資管 SEM 論文一篇 30 頁、5–15 條假設，加上主題、方法、研究情境欄位，每篇 40–90 分鐘是合理估計。50 篇 ＋ 試標 10 篇 ＋ 同學 15 篇 ≈ 40–70 小時人力，其中 Kevin 自己至少 35–55 小時。這些時數不在 120–150 h 的功能預算，也不在 30–40% 的非功能預算裡，PRD 沒說它算在哪裡。同學的 15 篇也要同學願意花 15 小時，§11 沒有列為待確認。
  2. 循環依賴：(a) 試標 → 修訂標註規則與 schema → 定版 → 十年批次；(b) 抽樣要「涵蓋各主題」，主題是 LLM 分類後才有的 → 需要先跑分類批次；(c) 分類清單（OQ-07）要在標註前定版，但 §11.5 說還沒和同學定，而 OQ-03 顯示同學沒有方向、給不出意見。三件事互相等。
  3. 標註要讀付費全文，標註者各自用學校權限下載屬個人使用，沒問題；但 50 篇全文的取得與保存也要走 FR-12 的下載聲明流程，順序上 FR-12 必須先於 FR-41。PRD 沒寫。
- **修改建議**：
  1. §8.1 或 §8.4 加一列「金標準標註人力：Kevin 約 40 h、同學約 15 h，不計入功能預算，排程在 1 月上旬，和實作並行」。§11 加「同學願不願意標 15 篇、何時」。
  2. 明寫順序：「OQ-07 清單定版（以老師的範圍為主，不等同學）→ 試標 10 篇（依期刊／年份分層抽樣，不依主題）→ schema v1 定版 → 分類批次 → 用分類結果檢查 50 篇是否各主題都有，不足再補抽 → 正式標註」。把「涵蓋各主題」改成「事後檢查，不足補抽」。
  3. FR-41 加一句「標註者各自以學校權限取得全文，依 FR-12 上傳並勾選下載聲明；標註介面可以是試算表」。

### A-7　「實驗室文獻庫」沒有定義；追蹤範圍外論文的可見範圍與個人文獻庫的隱私邊界不清
- **類別**：1 前後矛盾、5 資安（隱私邊界）
- **PRD 位置**：FR-28「範圍可選個人文獻庫（FR-50）、實驗室文獻庫或所有追蹤期刊」；FR-26「依……範圍篩選」；FR-35「書目、分類與 AI 擷取的衍生事實全實驗室共享」「個人文獻庫只有本人看得到」；FR-49「追蹤範圍外的論文照常產生中文結構化摘要與分類，可以被搜尋，也可以在問答中被引用」；§3 名詞表沒有「實驗室文獻庫」。
- **問題說明**：
  1. 名詞表是「全文用語的唯一定義」（§0），但「實驗室文獻庫」不在裡面。v1 沒有 lab 可見的個人內容（FR-35），那「實驗室文獻庫」和「所有追蹤期刊」差在哪？唯一合理的解釋是「追蹤期刊 ＋ 所有成員帶進來的追蹤範圍外論文」，但 PRD 沒寫。架構（ARCH-6、ARCH-14）與 UX 沒辦法做範圍選單。
  2. 隱私邊界：小安匯入學長的資料夾，裡面有追蹤範圍外的論文 X。依 FR-49，X 的書目與 AI 摘要全實驗室可搜尋；依 FR-35，「X 在小安的文獻庫」這件事是私人的。那麼 X 出現在實驗室搜尋結果，等於告訴大家「有人在讀 X」。4 人實驗室裡這幾乎等於指名。PRD 沒有討論這是否可接受。
  3. 手動確認書目（FR-49「OpenAlex 也查不到的，才請使用者手動確認書目」）：使用者手打的標題會變成全實驗室可見的書目。沒有說是 private 還是 lab。
- **修改建議**：
  1. 名詞表新增「實驗室文獻庫：追蹤期刊論文 ＋ 任何成員帶進系統的追蹤範圍外論文，書目與 AI 產出全實驗室可見；不含誰加入了哪篇」。
  2. FR-49 加一句明確的決定（二選一）：「追蹤範圍外論文的書目與 AI 產出為 lab 可見，PRD 接受『有人在讀這篇』的弱洩漏」或「追蹤範圍外論文預設只對匯入者可見，第二位成員也匯入時才升為 lab」。建議前者（簡單），但要寫出來。
  3. 手動確認的書目：寫明可見範圍與是否標示「使用者輸入、未經 OpenAlex 驗證」。

- **類別**：5 資安、3 工時預算
- **PRD 位置**：FR-12「一次上傳多個檔案或整個資料夾」；FR-49「辨認完就丟棄檔案」「驗收：處理完後儲存空間裡找不到該檔案」；NFR-1 1 GB。
- **問題說明**：整個資料夾可能是上百個 PDF；PDF 解析器在 750 MB 的 worker 裡處理大檔或惡意檔（zip bomb 類 PDF）會 OOM；R2 免費 10 GB 沒有每人配額。FR-49 的驗收只涵蓋「處理完」的正常路徑，worker 中途當掉的暫存檔沒有人清。
- **修改建議**：FR-12 加「單檔 ≤50 MB、單次 ≤100 檔、只接受 `application/pdf` 且檔頭驗證、每人儲存配額 X GB」；FR-49 加「暫存檔有 TTL，排程清理超過 1 小時的暫存檔；驗收含 worker 中斷的情境」。

### A-21　FR-2 每次抓取都保存原始 JSON：每週重抓的儲存成長沒有估算（待確認）
- **類別**：3 工時預算
- **PRD 位置**：FR-2「每次抓取 OpenAlex 的原始 JSON 都連同抓取日期保存，不只第一次匯入」；FR-9「每週抓取新論文與變動」。
- **問題說明**：若每週重抓全部約 9,600 篇以捕捉指標變動，每篇原始 JSON 約 20–50 KB，一年約 10–25 GB，超過 R2 免費額度，放 jsonb 更不可能。若每週只抓 `from_updated_date` 的變動則很小。PRD 沒說是哪一種，而這決定 FR-2 的儲存設計。
- **修改建議**：FR-9 明寫「每週只抓新增與 `updated_date` 變動的論文」；FR-2 加「原始 JSON 以 sha256 去重，同內容不重複存」。
