## 二、主要缺口

### G1（高）排除非研究文章的規則不見了

- **輸入位置**：`oq-02-abstract-coverage.md` §6 觀察 2、§7 第 4 點第 2 項。
- **輸入怎麼說**：OpenAlex 的 type 不夠準，MISQ、ISR 缺摘要的條目約一半是「Editor's Comments」「Research Spotlights」「About Our Authors」等非研究文章，仍被標成 article。要再用標題規則（含 Erratum）或 Crossref 的類型過濾。
- **PRD 現況**：FR-8 只寫 type 為 article 或 review、有 DOI、主要出處為該期刊。全文找不到 Editor／Erratum／非研究等字眼。memlog 也沒有刻意拿掉的紀錄。
- **影響**：這類條目會灌進論文數、主題趨勢、成長最快主題、突現偵測，也會壓低 MISQ／ISR 的覆蓋率，並浪費 Batch 費用（產生中文摘要、做分類）。
- **建議**：FR-8 加一條驗收條件：「依設定檔的標題規則（Editor's Comments、Research Spotlights、About Our Authors、Erratum／Corrigendum 等）或 Crossref 類型，把非研究文章標為排除。排除的條目保留原始資料（FR-2），但不計入論文數、趨勢與覆蓋率，也不送 LLM。」規則清單放設定檔（NFR-9）。design-principles §3.3 的入庫流程「清理（資料品質規則）」就是放這一步的地方，具體做法留給架構。

### G2（高）Semantic Scholar 授權條件沒寫進 PRD

- **輸入位置**：`oq-02b-semantic-scholar.md` §6 第 2–3 點、§7；brief addendum F1 也有同樣內容。
- **輸入怎麼說**：(1) 摘要的版權仍屬原出版社；(2) 限非商業使用；(3) 公開顯示時要標示 Semantic Scholar，並連回 Semantic Scholar 網站；(4) 條款禁止 share，實驗室共用算不算不明確，要寫信問，**得到書面答覆**才實作，不允許就不用。
- **PRD 現況**：FR-11 Could 只寫「實作前必須先確認授權，示範站不得使用」；§11 第 3 點只寫「實驗室共用算不算 share，要寫信詢問」。標示並連回、版權歸屬、非商業、「書面」答覆都沒寫。§7「不做商業化」只算間接涵蓋非商業。
- **建議**：FR-11 的 Could 段補上：「顯示 Semantic Scholar 來源的摘要時，標示『摘要來源：Semantic Scholar』並附連回 S2 論文頁的連結；取得 S2 的書面答覆，確認實驗室內部共用允許後才實作，不允許就不使用；限非商業用途。」§11 第 3 點改成「需取得書面答覆」。

### G3（中）S2 摘要的衍生產出無法追溯和移除

- **輸入位置**：`oq-02b-semantic-scholar.md` §6 第 3 點（「日後授權有變，可以只移除特定來源的摘要」「覆蓋率依來源分開計算」）。
- **PRD 現況**：FR-11 有記錄摘要來源，也依來源算覆蓋率，但沒有「依來源移除」的驗收條件。FR-1 記錄輸入種類（標題／摘要／全文）與輸入雜湊，**沒有記錄摘要來源**。用 S2 摘要產生的中文結構化摘要、分類、研究模型、向量，日後無法一併撤下。FR-42「不含 Semantic Scholar 的摘要」也沒說清楚：OA 論文（OQ-02b 中有 325 篇 OA 論文是靠 S2 補回的）根據 S2 摘要產生的中文摘要和研究模型，算不算要排除。
- **建議**：
  - FR-11 加驗收條件：「可以用一個 CLI 指令移除某來源的全部摘要，連同從它衍生的 AI 產出與向量（標為 superseded 或刪除），並重算覆蓋率（有測試）。」
  - FR-1：輸入種類細分到摘要來源（例如 `abstract:openalex`／`abstract:s2`），或者由 input_sha256 對回來源。具體做法留給架構。
  - FR-42 改成：「不含 Semantic Scholar 的摘要，**也不含從它衍生的 AI 產出**。」

### G4（中）第二版評估 Elsevier TDM API 被拿掉

- **輸入位置**：`oq-02-abstract-coverage.md` §7 第 3 點；`oq-02b-semantic-scholar.md` §6 第 4 點（「根本解法仍是第二版評估 Elsevier TDM API，前提是學校合約允許；OQ-02b 的結果讓這件事更重要」）；brief §78、brief memlog。
- **PRD 現況**：Later（§8.3）、待確認事項（§11）、不做的事（§7）都沒有。PRD 只寫「不用 Scopus API 補 Elsevier 摘要並公開顯示」，這是不同的事。memlog 的「不寄信給圖書館」講的是付費全文送雲端，不是 TDM API，所以不算刻意推翻。
- **影響**：2022–2025 年的 Elsevier 4 本，合併後覆蓋率也只有 27%（OQ-02b），而且這正是找題目最需要的近年資料。PRD 沒有留下任何後續的路。
- **建議**：§8.3 Later 加「評估出版社 TDM API（Elsevier、Wiley）補近年摘要，前提是確認學校合約允許」。也可以在 §11 加一條「何時、向誰確認 TDM 合約」。

### G5（中）Elsevier 降級處理中的「上傳 PDF 補」，在 v1 實際上補不到

- **輸入位置**：`oq-02-abstract-coverage.md` §7 第 2 點（沒摘要的論文仍收進書目與趨勢；標記「無摘要」、不做結構化筆記；**重要論文靠使用者上傳 PDF 補**）；`oq-02b` §6 第 1 點。
- **PRD 現況**：FR-11 把「使用者上傳的 PDF」列為摘要來源。但 FR-13 規定其他成員上傳的付費全文只存不擷取，Kevin 的要等本機模型（Should）。Elsevier 非 OA 論文正是付費全文，所以在 v1，「上傳 PDF 補」對這 1,594 篇幾乎沒有作用。PRD 沒有把這個後果寫出來。另外也不清楚：「只存不擷取」是否包含從 PDF 第一頁讀出**原文摘要**（不送 LLM、只做文字擷取）。
- **這是 memlog 的刻意決定**（付費全文只存不擷取），所以不算矛盾。但它的後果需要明寫，也要請 Kevin 決定一個邊界問題。
- **建議**：
  - FR-11 或 FR-25 加一句：「v1 中，Elsevier 非 OA 論文的摘要缺口無法靠上傳補回（付費全文只存不擷取），覆蓋率提示不應暗示『上傳就能補』。」
  - 請 Kevin 決定：從付費 PDF 用程式（不經 LLM）讀出原文摘要、存成摘要來源「使用者上傳的 PDF」，算不算「擷取」？如果可以，Elsevier 的覆蓋率可以靠同學上傳逐步回升。這一點建議列入 §11。

### G6（中）「待讀清單」沒有 FR，UJ-1 卻用到它

- **輸入位置**：`prd-pending-notes.md`「使用體驗」第 2 點；`oq-03-interviews.md`（一篇一篇下載很煩 → DOI 清單、批次開啟）。
- **PRD 現況**：§10 列為 UX 輸入，符合任務設定。但 UJ-1 的結果是「把有興趣的論文加入待讀清單」，卻沒有對應的 FR。最接近的 S17 合集是 Should，§10 新手路徑的「加入合集」也依賴 S17。這樣一來，UX 階段會拿到一個沒有資料模型、沒有優先順序的功能。OQ-03 的「DOI 清單」也沒有落到任何 FR（S02 批次匯出是 Should）。
- **建議**：二選一，請 Kevin 決定：
  1. 新增一個小 Must FR：「個人待讀清單（加入／移除），可以一次開啟清單中的 DOI 連結」（約 1–2 h）。
  2. 維持 Should，把 UJ-1 的結果改成「下載 RIS 匯入 Zotero」，並在 §10 註明待讀清單和合集屬於 S17。

### G7（中）JAIS DOI 篩選的理由與數量檢查；覆蓋率的重算

- **輸入位置**：`oq-02-abstract-coverage.md` 開頭、§6 觀察 3、§7 第 4 點第 1、3 項，§2 表格。
- **PRD 現況**：FR-8 有寫「有 DOI、主要出處為該期刊」，addendum 寫 `journals.yaml` 綁 source ID。**沒寫為什麼**：不加 DOI 條件，JAIS 會從約 680 篇膨脹到 9,898 篇（約 9,200 篇 AMCIS、ICIS 研討會論文被錯掛）。日後有人放寬條件（例如想收沒有 DOI 的論文）就會踩雷。覆蓋率「要定期重算並記錄日期，因為 OpenAlex 的資料會變動」也沒寫進 FR-11（FR-40 只要求顯示截至日期）。
- **建議**：
  - FR-8 加理由一句，以及一條驗收條件：「第一次匯入後，各刊論文數與 OQ-02 基準表（合計 9,643 篇，2026-11-06）的差距在合理範圍內；JAIS 不得出現沒有 DOI 的研討會論文（有測試）。」差距門檻請 Kevin 定，或留給架構。
  - FR-11 加：「每次每週更新後重算覆蓋率，並以日期／快照編號保存歷史。」
  - addendum 可以附 OQ-02 的 ISSN → source ID 對照表（含 DATABASE 名稱不符、已人工確認），當作 `journals.yaml` 的初始值。

### G8（低～中）學長分享的 PDF 在 FR-13 找不到類別

- **輸入位置**：`oq-03-interviews.md` 第 4 題、結論表（學長的論文資料夾 → 批次上傳重要性提高）。
- **PRD 現況**：UJ-2 和 §4.3 都把「上傳學長的資料夾」當主要情境。但 FR-13 的類別是「Kevin **自己下載**的付費全文」和「其他成員**自己下載**的付費全文」。別人轉給你的付費 PDF 不屬於任何一類。FR-7 的「使用者聲明」要聲明什麼也因此不清楚；如果 Kevin 上傳的是學長的檔案，能不能走本機模型，也沒有答案。
- **建議**：FR-13 把「自己下載」改成「使用者上傳的付費全文（不論來源）」，規則照舊（Kevin 的走本機模型、其他人的只存不擷取）。FR-7 的聲明文字交給 UX，但要涵蓋「這份檔案的取得方式」。是否允許 Kevin 對他人轉來的付費 PDF 跑本機模型，請 Kevin 決定。
