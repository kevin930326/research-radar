## 背景與動機

我是中央大學資管所碩一，還沒有論文題目，想用這個系統幫自己找題目，這是最主要的痛點。

- **指導教授**：王存國教授，研究領域為資訊經濟、電子商務、供應鏈管理、ERP、IT 專案管理，研究多屬行為與管理類（問卷、訪談、SEM）。
- **想解決的問題**：我想在教授的範圍內找偏技術的題目，但手動找論文、閱讀和分類很花時間，也看不出哪些主題正在成長。
- **實驗室**：同屆共 4 人（含我），大家都還沒開始管理論文，這個系統可以從一開始就給大家用。
- **求職作品集**：這是作品集的主力專案（目標：台積電、聯發科、Google、NVIDIA 的 IT／軟體職缺），要補足目前缺少的三塊：部署上雲的後端系統、資料 pipeline、LLM 應用（RAG）。

## 產品定位

一個專為資管研究生設計的文獻研究助理：自動追蹤指定期刊的新論文，分類並呈現研究趨勢，再用問答協助找論文題目，實驗室成員共用。

和一般「論文 RAG 問答」的差異：

- **結構化筆記**：自動擷取研究問題、方法、理論、主要發現，貼合資管行為研究的閱讀方式，可以直接用在文獻回顧。
- **用趨勢找題目**：看各主題逐年的變化與交叉（例如 ERP × AI），找出偏技術的切入點。
- **實驗室共用**：個人文獻庫加上共用文獻庫，有真實使用者與真實回饋。
- **本質是資訊系統**：重點在資料 pipeline 的正確性、可追溯的回答與工程品質，而不只是聊天機器人。

## 使用者與角色

第一版的使用者是我和實驗室同屆的 3 位同學，另外提供一個給面試官看的公開 demo。

| 角色 | 是誰 | 可以做什麼 |
| --- | --- | --- |
| 實驗室管理者 | 我 | 管理成員與追蹤主題的設定，並可使用所有成員功能 |
| 實驗室成員 | 同屆同學（含我共 4 人） | 個人文獻庫、上傳 PDF、筆記、問答、查看共用文獻庫 |

## 第一版功能範圍（MVP）

第一版的目標是「幫我找到論文題目」，以下 8 項要在寒假結束前完成。

1. **F1 追蹤指定期刊**：定期（例如每天）從 OpenAlex、Semantic Scholar、Crossref 抓指定期刊的新論文，只存書目資料與摘要。第一次匯入近 10 年的資料（年數待確認）。
2. **F2 上傳 PDF**：可以一次上傳多個檔案，由系統在背景解析。從 PDF 讀出 DOI 或標題，自動補齊作者、期刊、年份；用 DOI 加檔案雜湊值去重，同一篇不會重複存。中文論文（例如資管學報、臺灣博碩士論文）第一版用上傳的方式納入，不自動追蹤。
3. **F3 自動分類與結構化筆記**：用 LLM 依主題與研究方法分類，並擷取研究問題、方法、理論、主要發現，以及研究模型（構念、假設、假設是否成立）。所有論文的研究模型累積成一張構念關係網，標出很少被研究的關係，作為題目候選。使用者可以修正分類與筆記。
   - 主題（初版）：ERP、供應鏈、電子商務、IT 專案管理、資訊經濟、AI／資料分析
   - 研究方法（初版）：問卷／SEM、訪談／個案、實驗、資料分析／機器學習、文獻回顧
4. **F4 趨勢分析**：每個主題逐年的論文數、成長最快的主題、主題交叉（例如 ERP × AI），並用突現（burst）偵測找出最近突然變熱門的關鍵字。
5. **F5 問答找題目**：用 RAG 回答問題，每個回答都附出處（引用了哪幾篇）。例如「這個主題近年有哪些偏技術的方向」、「比較這幾篇的研究方法」。範圍可選自己的文獻庫、共用文獻庫或所有追蹤的期刊。
6. **F6 帳號與實驗室**：登入、角色、個人文獻庫、實驗室共用文獻庫。書目與分類全實驗室共享；筆記與 PDF 預設私人，可選擇分享；問答紀錄只有本人看得到。
7. **F7 匯出引用格式**：APA、BibTeX、RIS（EndNote 可直接匯入）。
8. **F8 API 額度與個人 key**：問答預設用共用額度（Claude Haiku 5.5），每人每天有使用上限，同學不用自己申請 key。想用更強模型的人可以選填自己的 API key；個人 key 加密存放，不寫進日誌，也不傳回前端。

## 第二版與之後

以下功能不在第一版，等第一版完成、同學試用過後再排。

- **自動找全文**：用 Unpaywall 以 DOI 找合法的開放取用版本；確認學校合約後，再串接出版社的 TDM API（例如 Elsevier、Wiley）。
- **一鍵收藏擴充功能**：連著學校 VPN 看論文時，按一下就把正在看的 PDF 存進文獻庫。
- **GitHub 專案與 skill 追蹤**：依星數、星數成長速度、指定作者或組織，追蹤並分類 app、Claude skills、MCP server 等專案。GitHub 沒有官方的 Trending API，要自己定期記錄星數才算得出成長速度。
- **擴充研究主題**：例如 AI／LLM、半導體／製造。主題設計成可設定的資料，新增一筆設定即可，不用改程式。
- **外部整合**：同步到 Notion 的論文筆記資料庫、串接 Zotero。

## 明確不做

- **不用程式透過學校 VPN 大量下載付費期刊全文**：違反期刊授權，可能害整個學校被出版社封鎖。
- **不公開散布付費論文的 PDF**：PDF 只在使用者帳號或實驗室內可見。
- **不爬 Google Scholar**：沒有官方 API，而且會封鎖爬蟲。
- **不繞過機器人驗證（CAPTCHA）**：驗證代表網站不允許程式自動抓取，繞過會違反使用條款；資料一律走官方 API，付費全文走 TDM API 或使用者自己的瀏覽器。
- **不開放實驗室以外的人註冊**：公開 demo 只供唯讀瀏覽。
- **不做商業化**：沒有付費方案。

## 設計原則與限制

- **只用官方 API**：遵守各資料來源的速率限制，請求失敗要能自動重試。
- **主題是資料，不寫死**：每個追蹤主題是一筆設定（關鍵字、期刊、作者），之後擴充不用改程式。
- **耗時工作放背景**：抓論文、解析 PDF、向量化都交給背景工作佇列；同一件工作重複執行也不會產生重複資料（冪等）。
- **記憶體預算**：正式主機只有 1 GB 記憶體，docker-compose 裡的 api 和 worker 要設定 `mem_limit`，加總不超過 750 MB，在本機就模擬正式環境；開發時用 `docker stats` 檢查用量。
- **LLM 費用與額度**：用 Claude Max 每月附贈的 API 額度（100 美元，當期用完即作廢），預設 Haiku 5.5，不急的工作走 Batch API；在 Console 為本專案開獨立工作區並設支出上限（同組織的校園小幫手共用餘額）。Claude API 沒有向量化功能，向量化改用 Cloudflare Workers AI 或開源模型，全庫固定同一個支援中英文的模型。額度綁在 Max 訂閱上，系統要保留改用個人 key 的路。
- **版權與隱私**：PDF 只在帳號或實驗室內使用；公開 demo 只用開放取用的論文與示範資料。
- **回答可追溯**：問答一定附出處，不給沒有依據的答案。
- **講得出為什麼**：這是作品集，重要的技術決策都寫成架構決策紀錄（ADR），面試時要能解釋每個選擇。

## 技術方向（初步建議）

以下是初步建議，會在 bmad-architecture 階段逐一確認。

&#91;embedded content: 系統架構 · 2 個資料來源、1 條背景處理線\]

論文從期刊 API 和使用者上傳兩個來源進來，耗時的處理都在背景工作佇列完成，網頁只負責查詢與問答。

| 部分 | 建議 | 理由 |
| --- | --- | --- |
| 後端 | Python＋FastAPI | 抓論文、解析 PDF、串接 LLM 的工具多屬 Python 生態 |
| 資料庫 | PostgreSQL＋pgvector | 一般資料與向量搜尋放在同一個資料庫，一條查詢就能同時篩期刊、年份與語意相似度 |
| 背景工作 | 工作佇列＋排程器 | 定時抓論文、處理上傳，使用者不用等待 |
| 前端 | React | 與 PetVerse 相同，可以沿用經驗 |
| 檔案 | Cloudflare R2（免費 10 GB，下載不收流量費） | PDF 不放進資料庫，資料庫只存路徑 |
| 部署 | Docker／Docker Compose，部署到雲端 | 開發在本機免費；上線主機見 OQ-04 |
| 品質 | 自動化測試＋GitHub Actions CI | 延續 AI Usage Monitor 的做法 |

Cloudflare 免費方案的容量夠用，但每次執行只有 10 毫秒 CPU，解析 PDF 這類吃 CPU 的工作不能放在 Workers 上。因此採混合架構：PDF 放 R2、向量化用 Workers AI，FastAPI＋PostgreSQL 的核心放在自己的主機或學生額度主機。全部改用 Cloudflare 會和 AI Usage Monitor 的技術重疊，作品集少了 Python 後端與 PostgreSQL。

## 可借鏡的專案

以下是可參考的工具、開源專案與研究，依對應功能排列；最有可能帶來差異化的是構念關係網、突現偵測與主動學習篩選。構念關係網（F3）與突現偵測（F4）已納入第一版，其餘在寫 PRD 時決定。

| 專案 | 是什麼 | 可以借鏡的地方 | 對應功能 |
| --- | --- | --- | --- |
| [OpenAlex 主題分類](https://help.openalex.org/data/topics/) | 自動把論文分到約 4,500 個主題，也能分類自己提供的文字 | 當免費的基本分類，LLM 只做資管專屬分類 | F3 |
| [Semantic Scholar API](https://freeapihub.com/apis/semantic-scholar-api) | 免費 API，提供 TLDR 與 SPECTER2 論文向量 | 補充摘要與論文相似度；社會科學收錄較少，只當輔助 | F1、F4 |
| [GROBID](https://arxiv.org/pdf/2303.09957) | 解析科學論文 PDF 的業界標準，只用 CPU | 上傳 PDF 的解析；要實測 1 GB 主機跑不跑得動 | F2 |
| [Elicit](https://theaiagentindex.com/compare/researchrabbit-vs-elicit) | 系統性文獻回顧與結構化擷取 | 用「論文 × 欄位」表格呈現筆記 | F3 |
| [TheoryOn](https://par.nsf.gov/servlets/purl/10282376)、[INN](https://theorizeit.org/resources) | 資管學者做的構念搜尋引擎，可直接查構念與構念之間的關係（發表於 MIS Quarterly） | 擷取每篇的研究模型（構念、假設、是否成立），畫成構念關係網，找很少人研究的關係當題目 | F3、F5 |
| [BERTopic、BERTrend](https://alphaxiv.org/overview/2411.05930v2) | 主題模型，追蹤主題逐年變化，BERTrend 專門偵測新興趨勢 | 找出正在冒出來的新主題 | F4 |
| [CiteSpace](https://bibsonomy.org/bibtex/7c93cd7c2d93ec5a09091a42f875143c) | 文獻計量工具，用突現（burst）偵測找研究前沿 | 關鍵字突現偵測；也是論文常用的方法 | F4 |
| [ASReview](https://link.springer.com/10.1038/s42256-020-00287-7) | 開源的主動學習篩選工具，標幾篇相關或不相關，系統就排序其餘論文 | 從上千篇摘要快速篩出候選文獻 | F4、F5 |
| [arxiv-sanity-lite](https://awesome.ecosyste.ms/projects/github.com%2Fkarpathy%2Farxiv-sanity-lite) | Karpathy 的論文推薦站，依使用者標籤用 SVM＋tf-idf 推薦新論文並寄每日信 | 便宜、只用 CPU 的每週新論文推薦 | F1 |
| [Litmaps](https://paperguide.ai/blog/litmaps-vs-researchrabbit/) | 監看存好的文獻地圖，有新論文就寄信 | 每週新論文摘要 | F1 |
| [PaperQA2](https://github.com/future-house/paper-qa) | 科學論文 RAG，回答附段落引用 | 問答流程：檢索 → LLM 重排並摘要 → 回答 | F5 |
| [OpenScholar](https://allenai.org/blog/openscholar-nature) | Ai2 的開源文獻綜整模型，登上 Nature；研究指出 GPT-4o 單獨使用時引用 78～90% 是捏造的 | 回答一定附出處，再檢查引用是否真的存在 | F5 |
| [Consensus](https://aarontay.substack.com/p/a-2025-deep-dive-of-consensus-promises) | 對是非題統計研究支持或反對的比例 | 對某個假設顯示支持比例；但只是計票，不等於統合分析，要標明限制 | F5 |
| [Stanford 研究：LLM 能否產生研究點子](https://arxiv.org/pdf/2409.04109) | AI 點子被評為更新穎，但可行性略弱 | AI 只提候選題目並附依據，可行性由你和實驗室判斷 | F5 |
| [Langfuse＋Ragas](https://langfuse.com/resources/engineering/evaluation-of-rag-with-ragas.md) | 開源的 LLM 追蹤與 RAG 評估（忠實度、答案相關性） | 量化問答品質、追蹤費用，面試加分 | 工程品質 |
| [ResearchRabbit、Connected Papers](https://intuitionlabs.ai/articles/ai-literature-mapping-tools-guide) | 引用網路圖 | 論文關係圖 | 第二版 |
| [scite](https://scite.ai/features) | 把每次引用分成支持、反駁、提及 | 顯示一篇論文後來被支持還是被質疑 | 第二版 |
| 自己的 TOEIC Cards | SM-2 間隔重複 | 把論文重點做成複習卡，避免讀過就忘 | 延伸 |
| 自己的校園小幫手 | Discord 定時推播 | 每週新論文摘要直接推到實驗室的 Discord | F1 |

## 成功標準

第一版要同時達到以下 5 點才算完成。

- [ ] 實驗室同屆 4 人都實際用過，並蒐集到回饋
- [ ] 看得到追蹤期刊的主題趨勢，並幫我收斂出候選論文題目
- [ ] 問答的每個回答都附出處，點得回原始論文
- [ ] 有線上可用的 demo（公開版只含開放取用資料）
- [ ] README、架構文件、ADR、自動化測試與 CI 齊全，面試時講得出每個技術決策的理由
