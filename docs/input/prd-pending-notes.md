## 找題目的品質與評估的嚴謹度
- [x] Must：關係排行表多一種排序「結果不一致」（同一關係有成立也有不成立的研究），列為獨立清單。
- [x] Should：從 PDF 擷取論文的「研究限制與未來研究建議」，可依構念或主題查詢。
- [x] 評估題組：抽樣涵蓋各期刊與主題；分成調整用與最終測試用兩份；另請一位同學獨立標註其中 15 篇，計算標註者間一致性（Cohen's kappa），作為正確率的參考基準。
- [x] 構念歸併：除了名稱，也比對構念定義（有定義時），參考 Larsen & Bong (2016, MISQ) 的 construct identity 做法。具體方法列入待架構決定。
- [x] 篩選條件：「很少人研究的關係」×「正在爆紅的技術關鍵字」的交集。

## 免費合法版本（綠色 OA、預印本）（2026-11-07）
- [x] 論文頁顯示所有合法免費版本：用 OpenAlex `locations`／Unpaywall 取得，標示版本（預印本 submittedVersion／作者接受稿 acceptedVersion／正式版 publishedVersion）、來源（機構典藏、arXiv、SSRN、作者個人頁、AISeL）、授權。和報告的 S13「取得連結」、C13「用綠色 OA 補覆蓋」合併，建議 Should 前段。
- [x] 處理規則：CC 授權的版本可以自動抓取並送 Haiku；沒有授權的版本只放連結，使用者自己下載後走付費論文的規則（只存、自己的用本機模型）。
- [x] 版本差異：預印本的假設與結果可能和正式版不同。擷取結果要記錄來自哪個版本；有正式版時優先；引用一律引正式版。
- [x] 不做：爬 ResearchGate、Academia.edu、Google Scholar，或沒有官方 API 的平台（SSRN 只放連結）。

## 擴充基礎資料（2026-11-10）
- [x] OQ-10 資料擴充評估 spike（寒假前）：量 14 本期刊的 OA／CC 比例，以及各擴充選項的篇數、摘要與 CC 全文比例，用數據決定要擴充哪些。
- [x] 擴充方向（依優先順序，待 spike 結果與老師意見定案）：
  1. 引用擴展：資料庫內論文引用很多次的「外部經典論文」（例如 TAM），自動補書目與摘要。
  2. 增加期刊：依老師的領域（電子商務、供應鏈、ERP、IT 專案管理、資訊經濟）挑，期刊清單是設定檔，不改程式；和老師看 brief 時一起問。
  3. 拉長年份：14 本期刊延伸到 20 年，補經典理論與構念的源頭。
  4. 研討會論文：AISeL（ICIS、PACIS、ECIS、AMCIS）與 HICSS，多數可免費取得全文，但授權要先確認。
  5. 實驗室自己的知識：共享的筆記、修正、證據簡報也納入 RAG（依可見範圍）。
- [x] 原則：擴充後仍要依來源分開報告覆蓋率；擴充範圍以老師的研究領域為主，避免灌進不相關的論文增加雜訊。
