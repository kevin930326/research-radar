# ADR-0014：原始資料先存再解析；每週更新把 14 本期刊整本重掃

- 狀態：提議（等 Kevin 在 PR 確認）
- 日期：2026-11-12
- 對應：PRD FR-2、FR-6、FR-8、FR-9、FR-10；addendum R2；架構文件 AD-2、AD-6、AD-25、AD-29

## 背景

PRD 對匯入有三個要求，合在一起才有這份 ADR：

- **FR-2**：每次抓到的 OpenAlex 原始 JSON 都要保存；之後要加欄位時，只靠已經存下來的原始資料就能重新解析，不用重抓。
- **FR-9**：每週抓「新論文與變動」。變動指摘要補上或更新、撤稿標記、書目更正；被引用次數這種每晚重算的數字不算變動。
- **FR-10**：遵守 OpenAlex 的額度與速率限制，記錄每次呼叫花了多少額度。

查證到的事實（2026-11-12，OpenAlex 官方文件）：

| 項目 | 事實 |
|---|---|
| 「只給我某天之後有更新的論文」（`from_updated_date`、`from_created_date`） | 要付費方案 |
| 免費額度 | 每天 1 美元；清單查詢每次 0.0001 美元 |
| 14 本期刊的論文數 | 2016–2025 年共 9,646 篇（2026-11-11 量的），另加當年度；每頁 100 筆，全部抓一次約 100 次出頭的請求，約 0.01 美元 |

所以「每週只抓有變動的」這條最省事的路，免費方案走不了。

另外，審查時發現一個會讓各 Story 做出不同東西的地方：論文來源的轉接器（`PaperSource`）要回傳「解析好的論文」還是「原始內容」，兩種寫法都說得通，但只有一種能保證「先存再解析」。

## 考慮過的選項

**每週怎麼抓**

- **A. 用 `from_updated_date` 只抓有更新的。** 最省請求數，但要付費方案。
- **B. 每週把 14 本期刊從 2016 年起整本重掃，自己比對哪些變了。**
- **C. 只抓最近出版的論文。** 請求數最少，但舊論文後來補上的摘要、撤稿、書目更正都抓不到，FR-9 的「變動」做不到。

**原始資料放哪裡**

- **甲. 放資料庫（`jsonb` 欄位）。** 查起來方便，但每天的資料庫備份都會帶著它，而且資料庫是租來的小型方案，空間比物件儲存貴。
- **乙. 壓縮後放物件儲存，資料庫只記「哪一筆、什麼時候抓的、內容指紋」。**

**`PaperSource` 回傳什麼**

- **一. 解析好的論文。** 轉接器裡自己解析。寫起來直覺，但「原始內容有沒有先存」變成每個轉接器自己要記得做的事，欄位也可能在轉接器裡就被丟掉。
- **二. 原始紀錄，不解析。** 存檔與解析是流程裡固定的下兩步。

## 決定

**B＋乙＋二。**

1. **`PaperSource` 只負責抓，回傳原始紀錄**：來源、外部鍵（例如 OpenAlex ID）、原始位元組、抓取時間。不解析，也不挑欄位；引用清單（`referenced_works`）等現在用不到的欄位都留著（FR-8）。
2. **每一筆（一篇論文一筆）先存起來**：壓縮後放物件儲存，路徑是 `raw/<來源>/<內容的 SHA-256>.json.gz`；資料表 `raw_fetch` 記一筆（來源、外部鍵、SHA-256、抓取時間）。內容和上次一模一樣時不重存檔案，只多記一筆抓取時間（FR-2）。
3. **解析是純函式**，放在 `domain/parsers/`，輸入只有已經存下來的原始內容。每個來源一個解析函式，輸出同一種資料型別 `ParsedPaper`。論文只能用 `ParsedPaper` 寫進資料庫（`repo.papers.upsert_by_external_id`，架構文件 AD-6），所以沒有「跳過解析直接寫」的路。
4. **流程固定四步**：抓 → 存原始 → 解析 → 寫入。`radar reparse` 可以不連網路，只重跑後兩步；這就是 FR-2「加一個欄位不用重抓」的驗收方式。
5. **怎麼判斷一篇論文變了**：從解析後的摘要、撤稿標記、書目欄位算一個指紋（`source_hash`）。指紋變了才重新跑摘要、分類、擷取。被引用次數不算在指紋裡，它每週直接覆寫論文上的欄位，不觸發任何重新處理。
6. **每週更新＝14 本期刊整本重掃。** 用量記在 `api_call`；每日額度寫在設定檔，用到設定的比例就停下，留到下一次排程續跑，不算失敗（架構文件 AD-29）。
7. 每週更新什麼時候建立快照、哪些論文算進數字，見 ADR-0011。

## 理由

1. **整本重掃是免費方案下唯一抓得到舊論文變動的做法**，而且一次約 0.01 美元、約 100 次請求，幾分鐘跑完，不值得為了省這些去付費。
2. **原始資料寫一次、幾乎不讀。** 放物件儲存便宜，也不會讓每晚的資料庫備份變大。資料庫只留查詢需要的那一行索引。
3. **回傳原始紀錄，「先存再解析」才是結構保證的，不是靠人記得。** 轉接器手上沒有解析的程式，丟不掉欄位；解析函式不連網路，可以直接拿存下來的真實回應當測試資料（FR-10 的離線測試）。
4. **加一個資料來源＝一個轉接器加一個解析函式**，流程不用改（設計原則的情境 C1）。

## 取捨

- **FR-2「內容沒變就不重存」幾乎不會成立。** OpenAlex 的被引用次數等指標每晚重算，所以每週大部分論文的原始內容都和上週不同，等於每週多存約一萬個小檔。這是照 PRD 的意思（PRD 明講這些指標「當時的快照事後無法重建」，所以要存），不是多做的。
- **容量只有粗估，沒有實測**：每個檔壓縮後估 2–4 KB，一年約 1–4 GB。R2 的免費空間是 10 GB，還要放成員的 PDF（每人上限 1.5 GB）與資料庫備份。**第一次匯入後要量一次實際大小**，再決定保留規則（例如每篇只留第一份、最新一份、每月一份）；在那之前什麼都不刪。這一項列在架構文件的 Deferred。
- **`raw/` 只有 R2 上的一份**，不在每晚的備份裡（架構文件 AD-28）。萬一遺失，論文目前的資料可以重抓回來，丟掉的是「過去每一週的指標長什麼樣」。
- **每週重掃比只抓更新慢**（幾分鐘對幾秒），而且每一篇都要算一次指紋。量很小，接受。
- **什麼時候重新考慮**：OpenAlex 改變免費額度或收費方式；或追蹤的期刊數增加到一次重掃接近每日額度（現在約用掉 1%）。

## 和 PRD 不一致的地方

- PRD FR-9 的標題是「每週**增量**更新」。這裡的做法對外的效果相同（只有新論文與有變動的論文會被重新處理），但抓取本身是整本重掃，不是增量。
- addendum R2 寫原始 JSON 存「R2 儲存空間（或 jsonb）」，這裡定為物件儲存。LLM 的原始回應比較小、而且要和費用帳本一起查，存在資料庫的 `llm_call`；問答是例外，原始回應只存在問答紀錄裡，隨使用者刪除而消失（ADR-0006）。

## 名詞

- **原始資料**：外部服務回傳的內容，一個位元組都不改地存下來；相對於「解析後」只留我們要的欄位。
- **解析**：把原始內容轉成系統自己的資料格式。
- **純函式**：只看輸入、不連網路也不碰資料庫的函式；同樣的輸入永遠得到同樣的輸出，所以很好測。
- **指紋（雜湊）**：把一段內容算成一串固定長度的字；內容一樣指紋就一樣，用來快速判斷「有沒有變」。
- **整本重掃**：不問「哪些變了」，每次都把整本期刊的論文清單重新抓一遍，自己比對。
- **gzip**：一種常見的壓縮格式；JSON 文字壓縮後通常只剩原本的一兩成。
