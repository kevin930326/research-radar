# ADR-0016：關鍵字統計只有一個來源；爆紅關鍵字當場算，空年從序列拿掉

- 狀態：提議（等 Kevin 在 PR 確認）。「空年怎麼接」（含演算法第 1 步）Kevin 2026-11-13 已確認：把空年拿掉、前後接起來。「已經結束的爆紅」Kevin 同一天也決定了：排行只列還在爆紅的，查到已經結束的另外標出來。「正在爆紅時『看全部 N 篇』用哪幾年」也決定了：最下面的連結一律是全部年度。成員版的規則到這裡都定了；示範站那一半還沒定
- 日期：2026-11-13
- 對應：PRD FR-9、FR-19、FR-22 (c)、FR-24（R5、R7）；addendum ARCH-5；UX 文件「5. 趨勢」「6. 關係排行表」與「給架構階段的事項」；架構文件 AD-5、AD-19、AD-31
- 範圍控制：FR-24 預期會觸發 K6（延後）。**跟著 FR-24 一起延後的**是偵測、排行、查關鍵字、看出處、留底、斷層檢查。**不跟著延後的**是「關鍵字的來源只有一個」與 `paper_keyword` 這張表的約定：每週更新現在就會寫這張表，關係排行表的「構面或關鍵字」輸入框（FR-19）也會讀它

## 背景

爆紅關鍵字（PRD 的突現偵測）在設計階段多了三件事（PRD R5）：表格先列 20 個、可以查任何一個關鍵字（沒有爆紅的也查得到）、每個關鍵字可以點開看出處（逐年篇數、期刊、主題、最近的論文）。R7 又改了年度的規則：當年度滿 6 個月之後算進來。UX 文件留給架構四件事：

1. 查關鍵字需要全部關鍵字的清單與逐年篇數；如果之後改用自家正規化的關鍵字，排行、查詢、點開的出處要一起換，不可以排行用一份、查詢用另一份。
2. 數字跟著每週更新重算；畫面要標示關鍵字的快照日期。
3. 篩選期刊之後某一年一篇論文都沒有（空年）時，PRD 只寫了「不拿那一年來判斷」。基準要不要跨過空年累計、爆紅狀態要不要延續、空年的隔年能不能是開始爆紅的年份、相鄰兩年的關鍵字分布比較遇到空年怎麼辦，要架構提出可以驗證的算法。
4. 演算法與關鍵字來源要分開、可以替換，結果要記錄來源與參數（ARCH-5）。

## 考慮過的選項

**關鍵字資料怎麼讀**

- **A. 各功能自己查關鍵字表。** 排行、查詢、點開的出處、論文清單的關鍵字條件、關係的篩選各寫一段查詢。換來源時要改五個地方，漏一個就是 UX 文件說不可以的情況。
- **B. 一個模組、一個「目前用哪個來源」的設定。** 所有讀關鍵字的查詢都在同一個模組，每個函式都必須帶來源。

**什麼時候算**

- **甲. 每週更新後算好存起來，畫面只讀存好的。** 最快，但「自己選期刊」有上萬種組合，沒辦法事先算完；存好的結果也會在資料變動後過期。
- **乙. 畫面要的時候當場算。** 一定是最新的；每次要花一點時間。
- **丙. 當場算，算過的存起來重複用。** 快，但要處理什麼時候作廢（重算追蹤範圍、重新解析、換來源）。

**空年怎麼處理**

- **一. 當成 0 篇的年度照算。** 那一年的分母是 0，占比算不出來；硬算等於把「沒有論文」當成「這個關鍵字沒人寫」，PRD 明講不可以。
- **二. 把空年從序列拿掉，前後的年度接起來。** 基準用全部有論文的年度一起算；空年兩邊都在爆紅時算同一段。
- **三. 空年把序列切成兩段，各算各的。** 基準不跨過空年，爆紅狀態也不延續。

## 決定

**B＋乙＋二。**

### 關鍵字的來源只有一個（不跟 K6 走）

1. `config/keyword_sources.yaml` 的 `active` 指定目前用哪個來源（v1 是 `openalex`）。
2. **`paper_keyword` 的約定**（匯入的 Story 現在就要建這張表，讀它的 Story 之後才做，所以先定）：
   - 每列至少有：論文、來源代號、`key`、顯示名稱。對（論文, 來源, `key`）唯一。
   - `key` 是這個關鍵字在它的來源裡的代號。來源是 `openalex` 時，是 OpenAlex 關鍵字網址的最後一段（小寫英文加連字號，例如 `artificial-intelligence`）。
   - 只由 `repo/papers.py` 寫（一張表一個寫入者）。
   - 來源是 `openalex` 的列**只在每週更新套用時整批覆寫**（ADR-0014）；單篇查詢（上傳、推薦清單）不寫。所以這個來源的關鍵字一定和目前的快照同一天。單篇查詢進來的論文在下一次每週更新整本重掃時補上；在那之前它們也還不算數。
3. **讀 `paper_keyword` 的查詢只放在 `repo/keyword_stats.py`**，每個函式都必須帶來源（和向量查詢必須帶模型一樣，架構文件 AD-12）；架構測試檢查其他模組沒有讀這張表。它是統計查詢的模組，和 `repo/stats.py`、`repo/relations.py` 一樣只能從 `counted_paper` 出發（架構文件 AD-5）。
4. **別的查詢要加關鍵字條件時，不自己接這張表。** `repo/keyword_stats.py` 提供一個函式，回傳「帶有這個關鍵字的論文」的一段查詢條件（做法和 `repo/visibility.py` 提供可見條件一樣），論文清單、檢索（`repo/retrieval.py`）、關係（`repo/relations.py`）把它組進自己的 SQL。條件有兩種：用 `key` 完全相符（「看全部 N 篇」這類連結用）；用名稱裡的字比對（輸入框用）。
5. **名稱怎麼比對只有一個函式**（也在 `repo/keyword_stats.py`）：不分大小寫，從關鍵字名稱裡每個英文字的開頭比對（UX 文件的假設，設定值）。查關鍵字的候選、關係排行表的「構面或關鍵字」輸入框都用它；驗收情境寫成 `tests/golden/keywords/` 的資料檔。關係排行表用同一個比對規則是架構的假設 `[ASSUMPTION]`。
6. 下面這些地方都經過這個模組，所以一定用同一份關鍵字：爆紅排行、查關鍵字的候選、點開一列的出處、論文清單與檢索的關鍵字條件、關係排行表的「構面或關鍵字」、畫面最下面那一行的來源名稱。
7. 關鍵字在 API 與網址裡用它在目前來源裡的 `key`；每個回應都帶 `keyword_source` 與 `keyword_as_of`。**網址裡的 `key` 可能失效**（換來源，或 OpenAlex 把關鍵字合併、拆分）：查不到時回一般的 404，畫面照 UX 文件「沒有這個關鍵字」那一種顯示，不當成系統錯誤。
8. **換來源的流程**（上線前發現斷層、改用自家正規化的關鍵字時，PRD FR-24、M12）：先把新來源的關鍵字寫進 `paper_keyword`（另一個來源代號）→ 改 `active` → 之後才清掉舊的。和換向量模型同一個做法，中間不會有一半新一半舊的畫面。
9. 統計只算 `counted_paper` 的論文（架構文件 AD-5）：成員自己加進來的追蹤範圍外論文不算。**分母不由這個模組自己數**：每一年的全部論文篇數用 `repo/stats.py` 的計數方塊 `total`（同一個查詢函式），不可以數成「有關鍵字的論文數」。

### 關鍵字的快照日期

- `keyword_as_of` 是日期（`YYYY-MM-DD`），用設定的時區（`Asia/Taipei`）。
- 來源是 OpenAlex 時：就是資料截止日（目前快照的截至時間換成台北時間的日期，ADR-0011），因為這個來源的關鍵字只在每週更新時整批覆寫。
- 來源是自家正規化時：是那一次正規化執行完成的日期。
- 畫面那一行（「關鍵字來自 OpenAlex，快照日期 YYYY-MM-DD」）的來源與日期都來自回應，不寫死；來源的顯示名稱照來源代號放 i18n。
- 爆紅關鍵字這個分頁的圖下也有「另有 N 篇出版年是 YYYY，還沒列入」那一行（Kevin 2026-11-13 決定）：N 算目前選的期刊的全部論文，不分關鍵字，和主題趨勢用同一個函式（ADR-0011），這裡的回應不另外帶這個數。出版年比當年度晚的論文本來就不進偵測（`domain/trend_years.py`）。

### 什麼時候算、怎麼留紀錄（跟著 FR-24）

1. **畫面要的時候當場算**（`services/keyword_trends.py`），不讀存好的結果。所以每週更新一發佈新快照，數字就是新的；人工修正分類不影響爆紅結果，只影響點開之後「主題」那一段。
2. 排行一次回完整清單（上限是設定值，預設 500 個），「先列 20 個、再載入」由前端分段顯示，不用為了下一段重算一次。回應的外層照全站的清單形狀：`items` 加 `total`，`next_cursor` 一律是空的。
3. **留底**：每週更新發佈快照後，排一個工作（`record_burst_run`，`maintenance` 佇列），替「全部 14 本」與「AIS 核心 11 本」各算一次，存成 `burst_run` 與 `burst_result`。`burst_run` 記：快照編號、關鍵字來源、關鍵字快照日期、期刊組合、參數與它的雜湊、納入了哪些年度、程式版本。這是 PRD 要求的「結果記錄來源與參數，方便重算」，也是之後比較不同來源或演算法的依據（ARCH-5）。**留底不拿來回應畫面**，所以沒有過期的問題。
   - **重跑不會多一筆**：`burst_run` 對（快照, 關鍵字來源, 期刊組合, 參數雜湊）唯一；工作發現已經有那一筆就跳過。這個工作沒有狀態表，靠這個唯一鍵做到重跑不出事。
   - **晚跑就不跑**：工作開始時先確認參數裡的快照仍是目前已發佈的那一個；不是（排到下一週才輪到）就直接結束。不然會算到新資料、卻記成舊快照。
   - 排入失敗、執行失敗都不補：只少一週的留底，下一週照常。不擋每週更新，也不影響心跳。
4. 回應本身也帶同一組資訊（來源、快照日期、快照編號、參數、納入的年度、當年度有沒有納入與原因）。

### 三個端點（成員版，跟著 FR-24）

| 用途 | 內容 |
|---|---|
| 排行 | 參數：期刊。每列：關鍵字、開始爆紅年份、強度、相關論文數、其中只有標題的篇數 |
| 查關鍵字的候選 | 參數：輸入的字、期刊。最多 6 個候選（設定值），每個帶篇數；比對方式見上面第 5 點；依篇數由多到少，再依名稱 |
| 一個關鍵字的出處 | 參數：關鍵字、期刊。逐年篇數（每年帶兩個標記，見「空年怎麼接」）、出現最多的期刊、落在哪些主題（用有效分類）、最近 3 篇、相關論文的篇數；爆紅的狀態（還在爆紅、爆紅過、沒有爆紅）、全部的爆紅區間、畫面那一列要用的是哪一段（見「已經結束的爆紅」） |

- 候選是打字時即時回應的：端點只做一次名稱比對與加總，不跑偵測。前端等使用者停一下才送（間隔是設定值）；回應時間第一次匯入後量。

### 每個篇數算的是哪幾年

畫面上有三個地方出現篇數。它們算的年份不一定相同，所以每個篇數都要講清楚是哪幾年：

| 篇數 | 算哪幾年 |
|---|---|
| 候選右邊的篇數 | 全部納入的年度 |
| 沒有爆紅的關鍵字的「相關論文數」 | 全部納入的年度（PRD FR-24） |
| 爆紅過、已經結束的關鍵字的「相關論文數」 | 全部納入的年度（它現在沒有在爆紅，照沒有爆紅的算；Kevin 2026-11-13 同意） |
| 正在爆紅的關鍵字的「相關論文數」 | 還在爆紅的那一段的區間內年度（UX 文件：算進相關論文數的年份是白色）。有兩段時只算最後一段，和那一列的開始年份、強度是同一段；前一段的年度圖上也是白色，但不算進這個數（Kevin 2026-11-13 同意） |

- 例：下面的情境 A，全部納入的年度有 42 篇，爆紅區間內有 34 篇。候選寫 42，排行那一列寫 34。
- **每個顯示出來的篇數，回應都帶它算的那幾年**；篇數旁的連結帶同一組條件：關鍵字的 `key`、期刊、那幾年、範圍固定是追蹤範圍（`tracked`，等於 `counted_paper`）。所以點下去列出來的篇數一定等於那個數字。不固定範圍的話，成員先上傳、還沒進快照的論文會出現在清單裡，卻不在統計裡。
- 測試：對測試資料裡的每個關鍵字，用回應帶的條件查論文清單，篇數相等（和計數方塊同一種測試，ADR-0011）。沒有爆紅的、爆紅過已經結束的關鍵字，候選的篇數、相關論文數、「看全部 N 篇」三個相等。
- **兩個連結各連到自己的清單**（Kevin 2026-11-13 決定；兩個連結設計稿本來就有，不多加）：
  - 那一列的「相關論文數」：連到它算的那幾年。正在爆紅時是爆紅期間的論文，其他情況是全部納入的年度。
  - 點開之後最下面的連結：一律連到全部納入年度的論文，N 是全部納入年度的篇數，和候選右邊的篇數是同一個數。
  - **最下面那個連結的字**：兩個數字不同時寫「看全部年度 N 篇」；相同時寫「看全部 N 篇」（沒有爆紅、爆紅過，或爆紅期間以外的年度剛好都沒有這個關鍵字的論文）。用哪一句由前端的一個函式比回應裡的兩個篇數決定；兩句各是 i18n 的一個鍵。
  - 回應替兩個篇數各帶一組條件，兩個連結各用自己那一組，所以點下去的篇數一定對得上。
  - 測試：情境 A，那一列 34 篇連到 2023–2025、最下面寫「看全部年度 42 篇」連到全部納入的年度；情境 J，34 篇與「看全部年度 68 篇」；情境 F（爆紅過），兩個都是 32，寫「看全部 32 篇」；情境 P（爆紅期間以外都是 0 篇），兩個都是 14，寫「看全部 14 篇」。

### 年度的規則和主題趨勢是同一份

哪些年度算進來（完整年度；當年度滿 6 個月而且有論文才算；空年是哪幾年）不在這裡重新定義，用 ADR-0011「趨勢的年度規則」。那一份規則的正本在前端的統計模組；偵測在後端，所以後端有一份 Python 的實作（`domain/trend_years.py`），兩邊通過同一批測試資料檔（`tests/golden/stats/years/`）。這一份 Python 實作與 `years/` 資料檔由 FR-24 的 Story 建；K6 觸發時不建，主題趨勢的 Story 不用替它準備。

### 演算法（Kleinberg 兩狀態模型）

放在 `domain/burst.py`，是純函式，不碰資料庫。輸入是一個關鍵字逐年的兩個數字與參數：

- `r`：那一年納入的期刊裡，帶有這個關鍵字的論文篇數（只有標題的論文也算，另外回報其中有幾篇只有標題）。
- `d`：那一年納入的期刊的全部論文篇數。

步驟：

1. 把 `d` 是 0 的年度（空年）從序列拿掉。剩下 n 個年度，照年份排，當成相鄰的時段。**n 是有論文的年度數，不是全部年度數。**
2. 基準比例 `p0` ＝ 全部時段的 `r` 加總 ÷ `d` 加總。高峰比例 `p1` ＝ `s × p0`（`s` 預設 2）。
3. **這三種關鍵字不偵測**，結果是「沒有爆紅」加原因代碼：`r` 加總是 0（`no_occurrence`）；有論文的年度少於 2 個（`too_few_years`；只有一個年度時基準就是那一年自己，沒有別的年度可以比）；`s × p0` 大於或等於 1（`baseline_too_high`；這個關鍵字平常就占一半以上，「高峰」沒有意義，公式也算不下去）。
4. 每個時段在兩種狀態（平常、高峰）各有一個成本：`−ln[ C(d, r) × p^r × (1−p)^(d−r) ]`，`p` 分別代入 `p0` 與 `p1`。意思是「如果這個關鍵字的比例是 p，這一年剛好出現 r 篇有多不意外」。
5. 從平常進入高峰要多付 `γ × ln(n)`（`γ` 預設 1）；從高峰回到平常不用付。這一項讓單獨一年的小波動不會被當成爆紅。序列開始之前當成平常狀態，所以第一個時段就在高峰也要付這一筆。
6. 找出總成本最小的一串狀態。**成本相同時一律選平常**：每一步有兩條路走到同一個狀態、成本相同（差距小於 10⁻⁹）時，選從平常來的那一條；最後兩種狀態成本相同時，選平常。
7. 連續處在高峰的時段是一個爆紅區間。**強度**＝區間內每個時段「平常的成本 − 高峰的成本」的加總。**開始爆紅年份**＝區間第一個時段的年份。**區間內的篇數**＝區間內各年 `r` 的加總。一個關鍵字可以有不只一個區間。

**排行的順序**：強度由大到小；強度相同時區間內的篇數多的在前；再相同照 `key` 的字母順序。超過清單上限時留排在前面的。

**和常見套件的差別**：Python 的 `burst_detection` 套件在第一個時段不收第 5 步的成本；這裡照 Kleinberg 的論文會收。第一年就偏高的關鍵字兩邊結果不同，實作時不要直接拿那個套件的輸出當答案。

`s`、`γ`、清單上限放 `config/`；「強度用演算法輸出的權重」「預設用 Kleinberg」是 PRD 標了 `[ASSUMPTION]` 的，參數的預設值要等第一次匯入後用真的資料調。

### 空年怎麼接（Kevin 2026-11-13 確認）

Kevin 選「把空年拿掉、前後接起來」（考慮過的選項二）。照上面第 1 步，UX 文件問的四件事的答案是：

| 問題 | 答案 | 為什麼 |
|---|---|---|
| 基準要不要跨過空年累計 | **要。** `p0` 用全部有論文的年度一起算 | 基準代表「這個關鍵字平常占多少」，年度越多越穩；空年沒有論文，加進去也不改變加總 |
| 爆紅狀態要不要跨過空年延續 | **要。** 空年前後的兩個年度當成相鄰；兩邊都在高峰時是同一個區間。空年本身不算區間裡的年度，圖上顯示「這一年沒有論文」 | 中間沒有論文不是關鍵字退燒的證據 |
| 空年的隔年能不能是開始爆紅的年份 | **可以。** 開始爆紅年份一定是有論文的年度，不會是空年 | 隔年的資料是真的 |
| 相鄰兩年的關鍵字分布比較（斷層檢查）遇到空年 | **跳過空年，拿前後最近的兩個有論文的年度相比**，並在輸出標出中間跳過了哪一年 | 見下面「斷層檢查」；這個檢查不套期刊篩選，正常不會遇到空年 |

**爆紅期間跨過空年時，空年那一年在畫面上照樣標成沒有論文，不可以看起來像那一年也在爆紅**（Kevin 2026-11-13 補）。做法：

- 爆紅區間回傳的是「區間內有論文的年度」的清單，不是只有開始與結束兩個年份。情境 C 的區間是 2022、2024、2025，沒有 2023。
- 出處端點的逐年資料，每一年各帶兩個標記：是不是空年、在不在爆紅區間內。空年一律是「不在區間內」，篇數是「沒有值」加 `empty_year`，不是 0。
- **「在不在爆紅區間內」看的是任何一段**（2026-11-13 補清楚；原本沒寫是哪一段）：這一年屬於這個關鍵字的任何一個爆紅區間就是真，不管那一段還在爆紅還是已經結束。標記由後端從偵測結果的每一段各自的年度清單合起來，不從「開始年份」推。
- 前端只照這兩個標記畫：標成在區間內的年度套白色，其他的不套；空年畫成「這一年沒有論文」。不可以自己用開始年份到結束年份把中間塗滿，也不可以把「開始之後」全部塗白。
- 相關論文數的連結帶的年份也是這份清單，不含空年。
- 測試：情境 C 的 2023 是空年、不在區間內；前端的元件測試檢查那一年沒有爆紅的樣式。
- 空年在小長條圖上的畫法設計已經補上（2026-11-13）：那一年畫斜線、不寫篇數、年份不亮，圖下一行「YYYY 年沒有論文」。

**可以驗證的例子。** 沒有另外寫的都是 2019–2025 七個年度、每年 `d` ＝ 100、`s` ＝ 2、`γ` ＝ 1。數字用兩種寫法各算一次（一種逐步推、一種把全部狀態組合列出來比），結果相同；三位審查者也各自重算過 A–G。實作時寫成 `tests/golden/burst/` 的測試資料檔，強度比到小數兩位。

### 已經結束的爆紅、爆紅不只一次（Kevin 2026-11-13 決定）

設計稿的表格只有「開始爆紅年份」一欄，點開的小長條圖把「開始爆紅之後」的年份都畫成白色，沒有「結束」的畫法。但演算法會找出已經結束的區間（情境 F），也會找出同一個關鍵字的兩個區間（情境 J）。Kevin 決定：**排行只列還在爆紅的；查到已經結束的，另外標出來。**

1. **資料上每個區間都留著**（`burst_result` 一個區間一列：區間內有論文的年度清單、強度、區間內篇數、有沒有延續到最後一個納入的年度）。
2. **一個關鍵字的爆紅狀態有三種**，由後端判定、放在回應裡，前端不自己從區間推：
   - `bursting` 還在爆紅：有一段延續到最後一個納入的年度。這樣的區間一個關鍵字最多一個。
   - `ended` 爆紅過：有區間，但沒有一段延續到最後一個納入的年度。
   - `none` 沒有爆紅：沒有區間（含三種不偵測的，帶原因代碼）。
3. **畫面那一列用哪一段也由後端指定**（回應裡指出是哪一個區間）：還在爆紅的用還在爆紅的那一段；爆紅過的用最近的那一段；沒有爆紅的沒有。
4. **排行只列 `bursting` 的**，一個關鍵字一列，開始年份、強度、相關論文數都是還在爆紅的那一段的。情境 J 列的是 2024 開始的那一段，不會出現兩列。
5. **查關鍵字查到 `ended` 的**：原本寫「沒有爆紅」的那一格改寫「YYYY–YYYY 爆紅過」，年份是最近那一段的第一個與最後一個有論文的年度；只有一年時寫「YYYY 爆紅過」。強度寫「–」（回應最上層的強度是空值；每一段自己的強度仍然在區間清單裡）。相關論文數算全部納入的年度（見「每個篇數算的是哪幾年」）。兩句文字各是 i18n 的一個鍵。
6. **點開的逐年篇數圖**：只有標成「在爆紅區間內」的年度套白色，不是開始之後全部白色（標記的定義見「空年怎麼接」下面的畫面規則）。
   - 已經結束的（情境 F）：只有 2020、2021 是白色，2022 以後不是。
   - 兩段、最後一段還在爆紅（情境 J）：2016、2017、2024、2025、2026 是白色，中間六年不是。
   - 兩段都結束（情境 N）：2017、2018、2022、2023 是白色；那一格寫「2022–2023 爆紅過」。
7. **測試**（寫進 `tests/golden/burst/`，拆 Story 時帶進驗收條件）：

   | 情境 | 狀態 | 排行 | 那一格、強度、相關論文數 | 標成在區間內的年度 |
   |---|---|---|---|---|
   | A | `bursting` | 列，2023 開始 | 強度 6.02，34 篇 | 2023、2024、2025 |
   | C（區間中間有空年） | `bursting` | 列，2022 開始 | 強度 3.85，34 篇 | 2022、2024、2025；2023 是空年、不在區間內 |
   | F | `ended` | 不列 | 「2020–2021 爆紅過」，強度「–」，32 篇 | 2020、2021 |
   | J | `bursting` | 列一列，2024 開始 | 強度 5.44，34 篇 | 2016、2017、2024、2025、2026 |
   | N | `ended` | 不列 | 「2022–2023 爆紅過」，強度「–」，58 篇 | 2017、2018、2022、2023 |
   | O | `ended` | 不列 | 「2022 爆紅過」，強度「–」，24 篇 | 2022 |
   | H | `none` | 不列 | 「沒有爆紅」，強度留空，全部納入年度的篇數 | 沒有 |

8. 畫面由設計補（架構文件 Deferred）：「爆紅過」那一格的樣子、圖上兩段白色的畫法。

### 斷層檢查

PRD FR-24 要求上線前比較各出版年的關鍵字分布，在 OpenAlex 換演算法的地方出現斷層時改用自家關鍵字。

- 是一個指令：`radar keywords check-drift`。只算、只輸出報告，不改任何設定；要不要換來源由 Kevin 看報告後決定。
- 只看完整年度、整個追蹤範圍（不套期刊篩選）。每個年度的關鍵字集合 ＝ 那一年算數的論文用到的全部關鍵字。相鄰兩年的 Jaccard 相似度 ＝ 兩年都有的關鍵字數 ÷ 兩年合起來的關鍵字數。
- 判定：某一對的相似度，低於「更早的各對的平均 − 2 個標準差」就標成斷層；更早的不到 3 對時不判定，只列數字。（門檻是 PRD 標了 `[ASSUMPTION]` 的；標準差用樣本標準差。）
- 遇到空年：跳過，拿前後最近的兩個有論文的年度相比，報告裡標出跳過的年份。
- 報告另外列一個數字：有摘要與沒有摘要的論文，平均各有幾個關鍵字（原因見下面假設表的最後一列）。

## 理由

1. **一個模組、一個來源設定**，換來源時才不會漏。這是 UX 文件明講不可以發生的情況，用架構測試擋比靠人記得可靠。
2. **當場算就沒有「存好的結果過期」這件事。** 資料量很小：一萬篇論文、每篇通常五、六個關鍵字（OpenAlex 文件，2026-11-13 查；約一成的論文沒有關鍵字）、十一個年度，一次查詢加總之後在記憶體裡算。
3. **把空年拿掉**是照 PRD「不拿那一年來判斷」最直接的做法。空年的 `d` 是 0，兩種狀態的成本都是 0，留著它也不會改變哪幾年比較像高峰；差別只在時段數 n 少一個，進入高峰的成本跟著小一點，所以落在邊界上的關鍵字結果會不同（情境 I）。規定 n 只算有論文的年度，兩份實作才會一致。
4. **留底和回應分開**：留底是給之後比較用的紀錄，畫面永遠用當下的資料。

## 取捨

- **每次打開爆紅關鍵字分頁都要算一次。** 粗估（沒有實測）幾百毫秒。第一次匯入後量一次；超過 NFR-19 的頁面 1 秒時，退路是兩組預設期刊改讀留底、只有「自己選」當場算，那時要補上作廢的規則（重算追蹤範圍、重新解析、換來源之後要重算留底）。
- **年度規則有兩份實作**（前端一份、後端一份），用同一批測試資料檔約束。如果之後把偵測搬到前端（為了示範站的「自己選期刊」），後端那一份可以拿掉。
- **示範站那一半還沒定**：示範站沒有後端，查關鍵字、點開看出處、自己選期刊都要靠事先算好的檔案，或在瀏覽器裡再寫一份演算法。資料檔要多帶多少、做到哪一項，見 ADR-0007 的粗估表；FR-24 開工前要 Kevin 決定（架構文件 Deferred）。
- **關鍵字太少的年度會讓基準不穩。** PRD 明講不另外加最低篇數的門檻（Kevin 只決定了 6 個月）。這裡保留一個設定值，預設是關的；要打開之前由 Kevin 決定。
- **同一個關鍵字會在畫面上出現兩個不同的篇數**（候選與最下面的連結是全部納入的年度，爆紅的那一列是區間內），見「每個篇數算的是哪幾年」。兩個數不同時最下面的連結寫「看全部年度 N 篇」來區分。

## 要回頭補 PRD、UX 文件的地方

這次沒有動 PRD 與 UX 文件，列在這裡等回頭補：

- UX 文件「算進相關論文數的年份才是白色」：同一個關鍵字有兩段爆紅時不成立。白色看的是每一年「在不在爆紅區間內」（任何一段）；相關論文數只算還在爆紅的那一段（Kevin 2026-11-13 同意）。
- UX 文件還沒有：爆紅過的關鍵字那一格寫「YYYY–YYYY 爆紅過」、強度寫「–」；最下面的連結兩個數字不同時寫「看全部年度 N 篇」；圖下「另有 N 篇出版年是 YYYY，還沒列入」（ADR-0011）。

## 名詞

- **空年**：套用期刊篩選之後，納入的期刊在那一年一篇論文都沒有。那一年的占比算不出來，不是 0%。
- **基準比例**：一個關鍵字在全部年度合起來占全部論文的比例；偵測時拿每一年的比例和它比。
- **爆紅區間**：演算法判定這個關鍵字連續處在「高峰狀態」的那幾年。
- **進入成本**：演算法規定「從平常變成高峰」要多付的一筆代價；有了它，只冒出一年的小波動不會被當成爆紅。
- **關鍵字來源**：關鍵字是誰標的。v1 用 OpenAlex 標的；備案是自己用 LLM 整理過的。
- **關鍵字的快照日期**：這批關鍵字是哪一天的版本。OpenAlex 的演算法改版時，同一篇論文的關鍵字會變，所以要標日期。
- **斷層**：相鄰兩年用到的關鍵字突然很不一樣，通常代表標關鍵字的方法換了，不是研究主題真的變了。
- **留底**：把某一次算出來的結果連同當時的來源與參數存起來，之後可以拿來比較；畫面不讀它。
