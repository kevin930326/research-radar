# ADR-0032：中文重點的內容、輸出驗證與 `plan_for`

- 狀態：提議
- 日期：2026-11-15
- 對應：epics Story 2.4；PRD FR-14、NFR-4；架構文件 AD-7、AD-8、AD-30；ADR-0015（表頭表、哪一種論文做哪些處理）、ADR-0030（閘門、prompt 登記）、ADR-0031（預算）

## 背景

2.2 的閘門只寫表頭、沒有正式 prompt；也還沒有 `plan_for`。要讓每篇有摘要的論文產生可以存的中文重點，需要：

- 一個地方回答「這篇論文做哪些處理」（AD-30 的四列）。
- 四欄內容（研究問題、方法、理論、發現）存在哪裡、怎麼保證被拒收的列沒有內容。
- 模型的輸出當成使用者輸入驗證：逐句翻譯、編造、超長、寫「摘要未提及」、夾標記、不是繁中，都要擋下並帶原因代碼（NFR-4）。

這份 ADR 記錄 spec 留給實作決定、或文件沒寫清楚的地方，以及判準抓不到的情況。

## 考慮過的選項

### 1. 四欄內容存在哪裡

| | 做法 | 優點 | 缺點 |
|---|---|---|---|
| A | `zh_summary` 加四個可為 NULL 的 `text` 欄位 | 每欄可以各自是 NULL；CHECK 寫得出「拒收沒有內容」「有值不是空白」；之後的有效值 view 與「回報某一欄有誤」直接用欄位名稱 | 欄位名稱改了要遷移 |
| B | 一個 `jsonb` 欄位 | 加欄位不用遷移 | 「某欄是 NULL」「有值不是空白」要寫 JSON 路徑的 CHECK；四欄是固定的，彈性用不到 |

### 2. 輸出長度怎麼限制

| | 做法 | 優點 | 缺點 |
|---|---|---|---|
| A | schema 寫 `maxLength` | 模型端就限制 | 結構化輸出不支援 `maxLength`（claude-api skill 查證），送出會失敗 |
| B | schema 只管形狀；長度由 domain 驗證，門檻放 `config/zh_summary.yaml` | 門檻可以改設定、不改程式；和其他判準放在一起 | 模型可能寫超過，要花一次呼叫的錢才知道 |

### 3. 逐句翻譯怎麼認

| | 做法 | 優點 | 缺點 |
|---|---|---|---|
| A | 比對輸出與摘要的語意相似度 | 準 | 要另一個模型或向量（跨語言），不能離線、要花錢 |
| B | 句數：摘要夠長時，輸出的句數不少於摘要就算翻譯 | 離線、可測、便宜 | 短摘要分不出來；摘要 5 句而某欄寫兩句的合格輸出會被誤擋（見取捨） |

### 4. 編造怎麼認

| | 做法 | 優點 | 缺點 |
|---|---|---|---|
| A | LLM 評審判斷每欄是不是摘要裡有的 | 抓得到中文寫的編造 | 每篇多一次呼叫；評審本身也要驗證（Epic 8 的評估才做） |
| B | 只核對輸出裡的阿拉伯數字與英文詞都出現在輸入（標題＋摘要） | 離線、確定、可測 | 中文寫的編造、中文數字抓不到（見取捨） |

## 決定

1. **`plan_for`（`radar/domain/processing.py`）**：只看 `ProcessingFacts` 的三件事：`excluded_reason`、`origin`、目前的摘要內容（`repo/papers.find_paper_processing_facts` 讀）。由上往下：被排除 → 四項都 `not_applicable`；`origin = manual` → 只做標題向量，其他 `not_applicable`；摘要去掉空白後不是空的 → 四項都做（向量用標題＋摘要）；否則只做標題分類與標題向量，中文重點與研究模型 `no_input`。每項工作回一個 `TaskPlan`：要做時是 `input_kind`（`title` 或 `abstract`），不做時是 `skip`（`not_applicable`／`no_input`），剛好一個有值。向量（`embed`）也用 `InputKind` 表示「只有標題」或「標題＋摘要」。呼叫端只問它，`services/zh_summary.py` 不做的論文不呼叫閘門、不寫任何列。
2. **內容欄位（選項 1A）**：遷移 0011 在 `zh_summary` 加 `research_question`、`method`、`theory`、`findings`（`text`，可為 NULL），`lang` 一律 `zh-Hant`。兩個 CHECK：`rejected` 四欄全是 NULL；有值時至少有一個非空白字元（`~ '[^[:space:]]'`）。可降版（降版會丟掉內容）。
3. **內容只由 `services/ai_results.py` 寫**：`record_llm_result` 多收閘門驗證過的 `output`；不是拒收、工作是 `zh_summary`、輸出是 `ZhSummaryOutput` 時，用 `normalize_zh_summary` 得出 `ZhSummaryContent` 交給 `NewAiResult`；呼叫端給不了內容。`ZhSummaryContent` 定義在 `domain/ai_outputs.py`（`NewAiResult` 要用、validators 又要 import 那個模組，放在 validators 會互相 import）。`NewAiResult` 是 `rejected` 時帶內容丟 `ValueError`；`repo/ai_outputs.create_ai_result` 收到不是 `zh_summary` 的工作卻帶內容也丟 `ValueError`。`candidate`、`superseded` 照樣存內容（歷史要查得到）。
4. **schema（選項 2B）**：`ZhSummaryOutput` 四欄都是 `str | None`、沒有預設值（四欄都要給，沒提到給 null）、`extra="forbid"`；欄位說明寫成字面值。多欄、缺欄、型別錯沿用 `llm_output_invalid`，不是 JSON 沿用 `llm_malformed_response`，截斷沿用 `llm_truncated`。
5. **正規化**：每欄 NFC、連續空白（含全形空白、換行）縮成一個半形空白、去頭尾。結果是空的，或整欄（在檢查用副本上拿掉開頭的「欄位名稱＋冒號」如「理論：」、空白與標點、不分大小寫）只是「摘要未提及／未提及／無／不詳／N/A／none／not mentioned」這類字，存 NULL，不算拒收。長度＝正規化後的字元數。
6. **拒收規則與順序**（`radar/domain/validators/zh_summary.py`）：第一個不過的就是原因代碼，不寫內容。
   1. 存不進資料庫（NUL、單獨的代理字元）→ `llm_output_unstorable`。先擋這個，後面做 `ZhSummaryContent` 時才不會丟非預期的例外（非預期例外會讓 run 停在 `llm_result_pending`、每次接續都再失敗）。
   2. 夾標記或連結：輸出含雙向控制字元（U+202A～202E、U+2066～2069、U+200E／200F、U+061C）、tag 字元（U+E0000～E007F）或 HTML 實體（`&名稱;`、`&#數字;`、`&#x…;`）直接拒收（Opus 確認後補：這些字檢查時看不出來、顯示時卻會倒轉或藏字，拒收才讓存的等於檢查的）。接著先把完整的比較式換掉（比較符號後面接數字，如 `p < .05`、`>50%`、`β > 0`；或兩邊各一個英文字母，如 `x<y`、`a > b`，右邊後面不能再接字母、到下一個漢字前 40 字內不能有 `>`），再找：後面接標籤樣字元（`/`、`!`、`?`、英文字母）的 `<`、欄位開頭的 `>`、反引號、粗體與刪除線（`**`、`__`、`~~`）、行內連結 `](`、參照式連結（`][`、`[名稱]:`）、任何 `://`、`www.`、`mailto:`、`javascript:`、裸網域（常見頂級網域，例如 `osf.io`、`example.org`、`data.gov.tw`，小寫的即使摘要裡也有照樣擋；首字大寫、而且輸入裡有一模一樣字樣的品牌名稱如 `Amazon.com` 放行）→ `zh_summary_unsafe_text`。在佔位字判斷之前，所以「`<b>無</b>`」也是拒收，不是 NULL。
   3. 夾講摘要本身的句子 → `zh_summary_placeholder_text`。主詞分兩種：「摘要」後面 8 個字內接否定詞（未、沒有、並未、不…）、再 4 個字內接「提及、提到、說明、描述、指出、交代…」；原文、文中、本文、本研究、研究、作者、文章、論文可能是研究材料或研究結果的開頭（Codex 主審查：「原文未揭露姓名時仍可推得作者身分」是隱私研究的發現），所以要否定詞緊接在後面（只能隔「中／裡／內」「並／均／皆／也」「明確／特別」）、再接那些動詞、再接研究要素（樣本數、方法、理論、研究問題、發現、結果、資料來源、變數、假設、模型、研究設計、研究對象、細節…）或直接斷句才算。另外「未在摘要中…」、「未在原文（文中）中提及…」（後面要接「提及、說明…」，所以「姓名未在原文中出現」不算）、英文 `not mentioned`、`n/a` 也算；動詞包含「提供」，研究要素前可以有「所用、所使用、使用、採用」。只寫「未提及」不算（「受訪者未提及隱私疑慮」可能是研究結果）。整欄比對（決定 5，存 NULL）用同一份主詞清單。
   4. 任一欄超過 `max_chars_per_field`（原本 80，2026-11-16 先改 100、再改 150，見文末的更新）→ `zh_summary_field_too_long`。
   5. 不是繁中：沒有漢字；漢字數 ×100 < `min_cjk_percent` ×（漢字數＋英文詞數）（預設 50）；含簡體專用字（94 個常用字，每個都不在 Big5／CP950 裡，單元測試核對）→ `zh_summary_not_zh_hant`。
   6. 逐句翻譯（選項 3B）：摘要句數（一串 `.!?` 後面接空白切；只從一串的開頭試、用佔有式量詞，一長串句點只掃一次，不會平方級回溯）≥ `translation_min_abstract_sentences`（預設 5），而且輸出句數（每欄以 `。！？!?` 切、數有字的段落，每個非空欄位至少一句）≥ 摘要句數 → `zh_summary_sentence_translation`。
   7. 編造（選項 4B）：輸出的每個數字都要出現在輸入的數字裡。數值是（`Decimal`, 是不是百分比）：正負號（各種破折號 Unicode Pd、減號 `−`、粗減號 `➖` 在副本裡都換成 `-`；前面不是字母、數字、`.`、`)` 才算，所以 `3‒5` 是 3 與 5、`‒0.35` 是 -0.35）、千分位合併、APA 寫法的 `.05` 當成 0.05、指數（`1e-3`）、單位（萬、億、兆、千、百萬、千萬…與 thousand、million、billion 乘進去；輸入另外留下沒乘的數字，所以摘要「12 million」對輸出「1200 萬」或「12」，輸出「12 萬」是 120000 對不上）、百分比（`%`、`percent`、`per cent`）都算進去，所以 0.50 等於 0.5、1e-3 等於 0.001，但 -0.35 ≠ 0.35、0.35 ≠ 0.35%、1e-3 ≠ 1e3。輸出用了不支援的數字寫法（數字後面或單獨的上標、下標數字、分數字元、`^`、千分比、`×10` 科學記號、不是十進位也不是漢字的數字字元如 `፱`）直接拒收；拉丁或希臘字母後面的 `¹²³`（`R²`、`χ²`、`η²`）是統計符號，照 NFKC 當成 `R2` 比對。輸入的英文數字詞也換成數字（zero～nineteen、twenty～ninety、first～tenth、hundred、thousand、million、billion）：一整個詞組只留它的值，「three hundred」只有 300（不會連帶允許 3、100）、「three hundred and twenty」是 320、「twenty-five」是 25；詞組後面接 `percent` 是百分比。輸出的每個英文詞（2 個字母以上）要在輸入出現（不分大小寫、容許 s／es／ies 字尾差異），或是輸入裡連續幾個詞的首字母（去掉 of、and、the 等虛詞也算，例如 TPB、UTAUT）；`PLS-SEM` 這種連字號串每一段都認得、或整串是首字母縮寫都算 → `zh_summary_unsupported_content`。
   - 第 2～7 條都在「檢查用副本」上做（Codex 主審查後補）：HTML 實體解碼（最多三層；輸出有實體已在第 2 條拒收，這一步實際上只作用在輸入）、拿掉零寬空白等格式字元（Unicode Cf）、全形逗號換成頓號、NFKC、各種文字的十進位數字（例如 `٩`、`१`）換成 0～9、各種破折號與減號換成 `-`、空白縮成一個。所以「摘\u200b要未提及」「＜ｂ＞」和看起來一樣的寫法結果一樣。整欄佔位字的判斷（決定 5）也用這份副本。長度與存進去的值仍是決定 5 的正規化結果，不是副本。
   - 驗證函式只收 `ZhSummaryOutput`，收到別的型別丟 `TypeError`（是 prompt 的 schema 設錯，程式的錯）。拒收訊息只有欄位名稱與規則，不含輸出內容。
7. **門檻放 `config/zh_summary.yaml`**：`max_chars_per_field: 80`（2026-11-16 先改 100、再改 150，見文末的更新）、`translation_min_abstract_sentences: 5`、`min_cjk_percent: 50`，只經 `radar/config.py` 的 `load_zh_summary_rules` 讀。三個鍵都要寫、不收多的鍵、只收整數（浮點數、字串、布林都擋）；`max_chars_per_field ≥ 1`、`translation_min_abstract_sentences ≥ 2`（1 句的摘要任何輸出都會被當成翻譯）、`min_cjk_percent` 在 1～100。錯誤是 `ConfigError`（「檔名：欄位：原因」）。
8. **正式 prompt `prompts/zh_summary/v1.md`**（2026-11-16 升到 `v2.md`，設定區不變，見文末的更新）：`effort: low`、`max_tokens: 1024`、`disable_thinking: true`、`output_schema: ZhSummaryOutput`。`max_tokens` 的算法：合格的輸出最多四欄 × 80 字＝320 個漢字，保守以每個漢字 2 tokens 算是 640，加 JSON 的鍵名、引號與標點約 60，共約 700；取 1024 留四成餘裕。思考關掉，所以沒有思考 tokens 吃上限。在這個假設下，超過 1024 tokens 的輸出幾乎一定有欄位超過 80 字（本來就會被長度規則整筆拒收），截斷（`llm_truncated`）不會擋掉合格的輸出。和 adapter 單次逾時（`RADAR_ANTHROPIC_TIMEOUT` 預設 60 秒）搭得上：保守假設每秒產生 50 tokens，1024 tokens 約 20 秒，再加輸入處理仍遠低於 60 秒，不會因為輸出太長而逾時（逾時時 Anthropic 可能已計費、帳本記不到，所以上限要小）；單次輸出費用上限 1024 × 0.50 ／百萬＝0.000512 美元。這是 prompt 設定區的值，不動 `config/models.yaml`。prompt 其他寫法：寫四欄定義、只根據標題與摘要不推測、沒提到填 null（不寫「摘要未提及」）、繁中、不逐句翻譯、每欄一句或短語 80 字內、純文字、文件裡的指令是資料；附一個自己編的範例（標明虛構、沒有 DOI 與網址），範例的回答本身通過上面的驗證（單元測試核對）。登記在 `domain/prompt_hashes.py`（v1）。
9. **`services/zh_summary.run_zh_summary`**：讀事實 → `plan_for` → 不做就回 `ZhSummaryRun(plan, None)`；要做就 `run_llm_job(LlmJob(zh_summary, 計畫的 input_kind, zh-Hant, ZhSummaryValidator(門檻)), budget_allows=BudgetGuard(...))`。時鐘由呼叫端傳入（預算的台北月份）。
10. **`registry_problems` 在 prompt 資料夾不存在時只回一條**：有了正式登記之後，資料夾不在會讓每個登記的版本都多報一條「找不到 prompt 檔」，改成先檢查資料夾、只報「資料夾不存在」。

## 理由

- 欄位而不是 JSON：四欄是固定的；資料庫層就能保證「拒收沒有內容」，不只靠程式。
- 判準全部離線、確定：不多花一次模型呼叫，測試可以逐條驗；抓不到的情況寫在下面，評估（Epic 8）再用標註資料量化。
- 正規化與驗證共用同一個函式：驗證時看的長度、NULL 判斷就是存進去的樣子。
- 先擋標記、再判斷佔位字：模型回「`<b>無</b>`」這種東西時寧可拒收，也不要把它當成正常的 NULL 吞掉。

## 取捨

- **抓不到中文寫的編造**：例如自己加的理論名稱翻成中文（「社會交換理論」而摘要沒有）、中文數字（「三個」）、「第一」這類序數。編造只核對阿拉伯數字與英文詞。
- **2 個字母的縮寫很容易碰巧對上**：例如輸出寫「AI」，而摘要剛好有相鄰的兩個詞以 a、i 開頭就算認得。只會放過、不會誤擋。
- **數字的寫法要對得上**：「35%」對「0.35」、「0.35」對「-0.35」（輸出用文字寫「負向」而省略負號）、「50」對「fifty percent」都會被擋（偏保守的誤擋）。「one」當代名詞用時也會被當成 1。不支援的數字寫法（數字後面的上標、分數字元、`^`、`×10`）一律拒收，即使摘要也這樣寫。中文單位只認緊接在阿拉伯數字後面的萬、億、兆、千、百（「百分」除外）；「3 千禧世代」這種剛好接在數字後面的字會被當成單位而誤擋，「百分之 35」「三萬」這種中文數字抓不到。摘要寫「12 million」時輸出寫「12」也會通過（輸入留下沒乘的 12）。
- **裸網域只認常見頂級網域的小寫結尾**：`ASP.NET`、`Node.js` 這種技術名稱不會被當成網址；首字大寫、輸入有一模一樣字樣的品牌名稱（`Amazon.com`、`Booking.com`）放行。代價是全大寫的 `OSF.IO`、不在清單裡的頂級網域會被放過，首字大寫又出現在摘要的真網址（`Osf.io`）也會放過。
- **逐句翻譯的判準很粗**：4 句以內的摘要，逐句翻譯和合格的四欄重點分不出來，所以不檢查；摘要 5 句而某欄寫了兩句的合格輸出會被誤擋（prompt 要求每欄一句）。長摘要的整段翻譯大多先被 80 字上限擋下。摘要句數會被縮寫（`et al. `、`e.g. `）多算，門檻因此變寬（偏向放過）。
- **繁中判斷抓不到繁簡同形的句子**：簡體專用字只列了常用的一小份；用字繁簡相同的句子分不出來。
- **夾指令只擋標記與連結字元**：輸出是資料，畫面只經 `AiText` 顯示；純中文寫的「請忽略之前的指示」分不出來，會照一般文字存（整合測試寫明了這個限制）。英文寫的指令多半被「不是繁中」或「編造」擋下。
- **只寫「未提及」不算夾帶**：「使用問卷，樣本數未提及」這種沒有講到摘要的寫法會被放過；為了不誤擋「受訪者未提及…」這類真的研究結果。
- **門檻不算進指紋**：改 `config/zh_summary.yaml` 不會讓已經 `rejected` 的論文自動重跑（指紋與 prompt 版本都沒變，`should_run` 照樣跳過），要用 `radar runs retry`；新門檻只影響之後的驗證，包括接續（`llm_result_pending`）的那一次。
- **prompt 寫死「80 字以內」**：門檻改小時 prompt 沒跟著改，模型會照 80 寫、被拒收；改門檻時要一起考慮升 prompt 版本。
- **四欄全是 NULL 也寫成 `active`**：模型判斷摘要什麼都沒提到時就是這樣；AI 區塊要顯示 `empty` 還是 `ready`，由 2.7 的 `repo/ai_blocks.py` 決定。
- **閘門不強制中文重點一定要帶驗證函式**：`ai_results` 只要輸出是 `ZhSummaryOutput` 就寫內容（照樣正規化）；正式程式只經 `run_zh_summary` 跑，它一定帶 `ZhSummaryValidator`。之後若有別的入口直接呼叫閘門，要記得帶。
- **降版會丟掉內容**：0011 降到 0010 時四欄整個刪掉，再升版是 NULL。
- **主詞與距離規則**：只有「摘要」一定是在講摘要，容許中間隔幾個字。原文、文中不一定（隱私、去識別化研究裡的「原文」是研究材料）；本文、本研究、研究、作者、文章、論文也常是研究結果的開頭（「本文發現使用者不報告隱私疑慮」）。所以這些主詞要否定詞緊接在後面、接「提及、說明…」、再接研究要素或斷句才算夾帶。代價是「本文對樣本數並沒有說明」這種隔開的寫法、「原文未提及個人資訊」（資訊不在研究要素清單裡）會被放過；「原文未提及樣本數」這種研究要素剛好是研究主題的句子仍會被擋。
- **`<` 與 `>` 什麼時候算標記**：先認出完整的比較式（比較符號後面接數字，或兩邊各一個英文字母），`p < .05`、`>50% 的受訪者`、`x<y`、`β > 0` 都不會被擋；剩下的 `<` 只在後面接 `/`、`!`、`?` 或英文字母時算（`<b>`、`</div`、`<!--`），`>` 只在欄位開頭算（Markdown 引言）。沒有閉合的 `<b` 前面沒有字母時算標記；前面剛好是一個英文字母（`x<b 很重要`）會被當成比較式 `x<b` 放過。單星號斜體（`*問卷*`）與開頭的 `# 標題` 不擋（畫面只經 `AiText` 以純文字顯示，這些字不會變成格式）。抓不到：用英文詞寫的比較（`usefulness<intention`）會被當成標記而誤擋；`x<y and a>b` 這種同一段英文裡前後都有比較符號的寫法也會被誤擋。
- **檢查用副本與存的值不同**：全形英數字、零寬字元、各種破折號照原樣存（畫面只經 `AiText` 以純文字顯示），只有檢查時換掉。這些字只會讓檢查「更嚴」或不改變意思；會讓顯示和檢查看到的不一樣的雙向控制字元、tag 字元與 HTML 實體不進副本，直接拒收。
- **APA 小數與全形逗號**：`.05` 讀成 0.05，所以輸出寫 0.05 對得上、寫 5 會被擋；NFKC 會把全形逗號「，」變成半形逗號，「120，350」就會被當成千分位的 120350，所以先把「，」換成頓號，讀成 120 與 350。半形逗號照樣當千分位（「120,350」是 120350）。
- **每欄都要有中文**：沒有漢字的欄位（例如 theory 只寫「TAM」）會被當成不是繁中而拒收；prompt 第 3 條因此要求每欄用中文寫、英文縮寫放在中文名稱後面的括號裡（「科技接受模型（TAM）」）。
- **3 個字母的編造縮寫也可能碰巧對上**：自己編的縮寫只要剛好是輸入裡連續三個詞的首字母（虛詞可以跳過）就算認得。
- **只有「未發現／沒有發現」的發現欄存 NULL**：整欄比對把「沒有＋發現」當成佔位字，所以模型想表達「沒有發現顯著效果」卻只寫這四個字時，會存成 NULL（畫面顯示「摘要未提及」）。
- **`GatewayResult.output` 是模型原本的輸出**：閘門回傳的是 Pydantic 驗過的原始輸出，資料庫存的是正規化後的內容（空白縮掉、佔位字變 NULL）；要顯示或比對時以資料庫為準。
- **呼叫途中被排除的論文照樣寫成 `active`**：`ai_results` 寫入時核對的是輸入指紋、prompt 版本、模型，沒有重問 `plan_for`；所以模型呼叫期間論文被標成排除，結果仍會寫成 `active`。互動呼叫的時間窗很短；Batch（最長 24 小時）影響最大，做 2.9／2.10 時要決定寫入前是否重問 `plan_for`。

## 2026-11-18 更新：把輸入讀得更完整（救回誤擋）

### 發生什麼事

上限改 150 之後重跑，中文重點仍有 424 篇被拒收。逐篇看拒收原因，約 240 篇是誤擋：模型寫的數字或英文詞其實在標題或摘要裡，只是驗證把輸入讀得不夠完整，例如摘要用空白當千分位（`131 978`）、用英文月份（`September 2014`）、寫 `10–40%` 或 `-4.40%`、詞形不同（摘要 `theory`、輸出 `theoretical`）、OpenAlex 的摘要少了空白（幾個詞黏在一起）。另外逐句翻譯擋下的 12 篇（2026-11-17 查全庫），摘要都只有 5～6 句，輸出都是分欄的重點，不是翻譯；「中文名稱（英文）」這種 prompt 規則 3 要求的寫法，英文名稱長的時候會被漢字比例擋下。

原則不變（Kevin 2026-11-18）：輸出的數字與英文詞都要在標題或摘要裡有依據。這次只是把輸入讀得更完整；每一項放行都有「仍然擋得住編造」的反例測試，拿不準的維持拒收。

### 考慮過的選項

| | 做法 | 好處 | 代價 |
|---|---|---|---|
| A | 維持原判準，被擋的論文一篇篇人工看 | 不動程式 | 約 240 篇沒有中文重點；之後每批新論文都會再擋一樣的寫法 |
| B | 放寬判準（例如數字只要差不多、英文詞只看前幾個字母） | 救最多 | 編造也一起放過，違反原則 |
| C | 原則不變，只把輸入讀得更完整：每種寫法各寫一條窄規則，並列出每條帶來的已知漏網 | 救回大部分誤擋，編造判準照樣有效 | 規則變多；仍有少數擋不住的編造（見下面） |
| D | 研究模型（`research_model.py`）一起改 | 兩邊一致 | 研究模型的結構化數值比對更嚴格、另有規則；一起改風險大 |

### 決定

選 C，只改中文重點；研究模型不動（D 不選）。共用函式（`numbers`、`structured_numbers`、`InputVocabulary`）的行為一個字都沒改，新的讀法寫成 `text_checks.ExtendedVocabulary`，只有 `zh_summary.py` 用（單元測試固定共用函式對這些新寫法的結果和以前一樣）。

下面的規則已經照 PR 審查（Codex 與兩個 Opus 視角）修過三輪。數字規則共同的原則：**一律以既有讀法讀到的「完整數字」為單位**。完整數字就是原本的數字讀法（`numbers`：科學記號與含 `^` 的整段先換成空白、隔空白的負號併上去，再找數字）讀到的每一個數字，連同它的正負號、千分位、小數、指數、量詞（萬、million…）、百分比。新規則只看這些完整數字和它們之間的文字，不另外用正規式找數字，所以不會從科學記號、指數、千分位、帶量詞或百分比的數字中間讀出片段（第一輪改成「開頭不能接在某些字元後面」，第二輪審查又找到別的寫法，所以改成這個結構性的做法）：

- 輸入這一側只從完整數字取值，而且只取沒有指數、沒有量詞的。另外，原本讀法沒認出整段的科學記號裡的片段也不取（原本的讀法照樣讀得到，只是新規則不用），不論前面是不是字母：乘號（`×`、`x`（前面不是字母）、`*`、`·`、`⋅`、`∙`、`✕`、`✖`、`⨯`）後面緊接的「10＋次方」（`K1.2 × 10-3`、`1.2 ⋅ 10-3`）、`^` 或 `**` 後面的次方（可隔空白、正負號含 `±`、`∓`：`K10^ -3`、`10^ ±3`、`10**-9`）、數字後面 `E` 前後有空白的指數（`1.2 E -3`、`7.7e - 90`）。
- **白名單**（第三輪）：輸入這一側新規則的「起點」數字——空白千分位的第一段、`10-40%` 的前半、`10% points` 的數字——從它的開頭（含正負號）往前跳過最多一個空白，那個字元必須是文字開頭（含標題與摘要之間的換行）、字母（含中文）、數字，或一般標點（`( [ { ) ] } , ; : . ? ! = < > ≤ ≥ ~ ≈` 引號 `/ $ £ € ¥ % # & |` `、。`）。沒列到的符號預設不放行，所以 `-`、`+`、`±`、`*`、`×`、`⋅`、`^`、`⊗` 這類乘號、次方、正負號後面的數字不當起點——上面那張科學記號的清單補不完，白名單讓沒看過的符號也擋得住。這個條件只會讓新規則少認：第一段沒過白名單時整串都不用，也不從第二段重新開始。`%-` 那條（`2.84%-38.94%` 的後半另加正的值）不加這個條件：輸出的正數本來就能對輸入同值的負數，它沒有多放行什麼。年代也不加（前面是連字號照樣算），只有四位數年代的後兩位要前面乾淨（見第 5 項）。
- 輸出這一側（英數詞、月份、年代換成 `Q`）只能把完整數字整個換掉；換完再核對一次（第三輪改成比位置）：替換後的每一個完整數字都必須是替換前同一個位置、各部分一模一樣的完整數字（切出來的值即使剛好在別處出現過也不行），換之前讀不懂（科學記號、`^`）的換完也要讀不懂，不是的話整欄照原本的方式讀。「讀不懂」也看替換前的文字。
- 單元測試用組合的方式（各種帶指數、科學記號、量詞、百分比、千分位、負號的寫法 × 每條規則會看的前後文）固定這兩件事。

數字（輸入這一側多認得）：

1. **空白當千分位**：一個 1～3 位的整數（可以帶正負號），後面接一組以上「一個空白（不換行空白、窄空白在檢查用副本裡已經是一般空白）／逗號＋空白／LaTeX 的 `$\,$`＋剛好 3 位、沒有正負號與指數的整數」才合併（`131 978`、`387, 000`、`150$\,$000`）；只有最後一組可以帶量詞或百分比（`54 000 million`）。第一段要是獨立的數字：前一段是 4 位數（`in 2019 300 firms`）、`COVID-19 300`、`1e+3 100`、`1e-3 100`、`K12 345` 都不合併；第一段前面也要過白名單（`⋅ 1 200`、`± 1 200`、`- 131 978` 不合併）。整串後面還接著「空白或 `$\,$`＋沒有正負號的數字」卻不是 3 位整數時，整串不合併（`1 234 5678`、`1 234 567.89`、`1 300.5`、`1 000 000e3`）；「逗號＋空白＋不是 3 位整數的數字」是列舉，前面那串照樣合併（`n = 12 345, 51.2% female`、`1 200, 3 400 and 5 600`、`54 000, 2019`，第三輪）。合併後的值與沒合併的各段都留在輸入的數字裡。
2. **月份英文名**：全名與常見縮寫（`Jan`…`Sept`／`Sep`…`Dec`，可接 `.`）對應 1～12。全名要首字大寫或全大寫（`March`、`MARCH`）；三、四個字母的縮寫只認首字大寫（`Mar`、`Sept.`），全大寫的 `MAR`（missing at random）、`APR`（年利率）不算。`May` 另外要緊鄰數字（`May 2015`、`5 May`）。**只用來讓輸出裡後面接「月」的數字對得上**（「9 月」「7–8月」「7 至 8 月」「9、10 月」「2014 年 9 月至 2015 年 5 月」）；那個數字要剛好是一個完整數字、沒有正負號的整數（`3e-1 月`、`-3 月`、`1.5 月` 不算），前面也不能是字母、數字、`.`、`,`、連字號（`K3 月`、`2014-9 月`）或 `±`、`∓`（`±3 月`：原本的讀法把 `±3` 讀成 3）。數字、`.` 只是讓比對不要從某個數字的中間開始（第三輪：否則 `COVID-19 至 3 月`、`Web2.0至8月` 會從 `19` 的 `9`、`2.0` 的 `0` 配成範圍、整段放棄，後面獨立的「3 月」也一起放棄）。第一個數字前面隔一個空白是 `±`、`∓`、`+` 時也不算（`前後 ± 3 月`，第三輪）；隔一個空白是 `-` 時，只有那個 `-` 前面（隔最多一個空白）是另一個「月」才當範圍（`12 月 - 3 月`、`2014 年 12 月 - 2015 年 3 月`），其他（`前後 - 3 月`、欄位開頭的 `- 3 月`）不算；同一段裡的範圍（`7 - 8月`、`7 至 8 月`）不受影響。輸出裡別的位置的 9 不因此放行，「3 個月」也不算。
3. **範圍與百分點**：`10-40%` 的前半 10 也是百分比；`2.84%-38.94%` 另讀一次，`%` 後面的 `-` 不當負號（原本的讀法照樣留著）；`10% points`、`10 percent points` 讀成不是百分比的 10，對得上輸出的「10 個百分點」（輸出這樣寫本來就讀成不是百分比的 10；`10 percentage points` 本來就對得上）。前半與百分點的數字都要是獨立、沒有指數與量詞的完整數字，可以帶負號（`-10-40%` 的 -10、`-10% points` 的 -10），前面要過白名單；`1.2e-3% points`、`1e-10-40%`（帶指數的完整數字）、`1.2 × 10-3% points`、`10^ -3% points`、`1.2 ⋅ 10-3% points`、`1.2 E -3% points`、`10^ ±3% points`（科學記號）、`1.2 ⊗ 10-3% points`（沒看過的符號）都讀不出新的值。
4. **正負號**：輸出的正數可以對輸入同值的負數（輸入 `-4.40%`、輸出「下跌約 4.40%」）。反過來（輸出寫負數、輸入只有正數）照樣擋。百分比與否仍要一致。
5. **年代**：輸入 `1960s`、`1960's`、`60s`、`'60s`（最後一位是 0）只讓輸出裡後面接「年代」的數字對得上（「60年代」「1960 年代」）；輸出「60 名」照樣擋。輸入那一側，年代要是一個 2 位或 4 位、沒有正負號的完整整數，後面緊接 `s` 或 `'s`：`3e-10s`、`2E+10s` 是帶指數的完整數字，`1.2 × 10-10s`、`10 ^ - 10s` 是科學記號，都不算；前面是連字號照樣算（`pre-1960s`、`late-1960s`、`mid-1960s`、範圍的後半 `1950s-1960s`）。四位數年代的後兩位（1960s 的 60，原本的讀法讀不到的值）另外要前面乾淨：過白名單，或前面緊接的連字號接在字母或一個過白名單的數字後面（`pre-1960s`、`1950s-1960s`、`1950-1960s`）；所以 `1.2 ⊗ 10-1960s` 不讓「60 年代」對得上（第三輪）。輸出那一側的條件和月份一樣（`3e-60 年代`、`-60 年代`、`±60 年代`、`前後 ± 60 年代` 不算；`50 年代 - 60 年代` 算）。

### 取捨與還不知道的事

抓不到的情況（每一項放行帶來的已知漏網）：

- **空白千分位**：「數字＋空白＋3 位數字」一律多認一個合併的值，所以「Study 2 150 participants」會讓 2150 也對得上；更常見的還有 `Wave 1 312 firms` → 1312、`Table 3 312 employees` → 3312、`Group 5 250 adults` → 5250；`387, 000` 這種逗號＋空白也會把「120, 240, and 360」這種列舉多認成 120240；`-1 300` 會多認 -1300。逗號列舉照樣合併（第三輪），所以混用兩種分隔的 `1 234, 567.89` 會多認 1234、`1 000, 000e3` 會多認 1000（真的這樣寫一個數字的很少）。合併只會多認，不會少認。反過來，整串後面又接空白＋不是 3 位整數的數字（`1 000 5G sites`、`1 234 567.89`）整串不合併（偏保守的誤擋）。第一段是 4 位以上的整數或黏在詞上時，從下一個數字重新開始：`COVID-19 300 000`、`In 2019 300 000` 會認 300000（和上一版一樣）；第一段在科學記號裡（`**1 200 000**`、`1.2E -1 200 000`）、帶指數（`1.2E-1 200 978`、`1e-1 200 978`）或量詞、百分比、小數，合併起點前面緊接著被既有讀法整段換成空白的科學記號或 `^`（`10^ 12 345 000`、`10^ 1 200 000`、`2 x 10-1 200 978`），或沒過白名單時，整串都不用，也不從第二段重新開始（下一節的 PR 1 審查 V1 修正與它的第一輪修正）。
- **月份**：輸入有某個月份時，輸出把任何「N 月」寫成那個月都對得上，不管是不是同一件事（輸入「September 2014」，輸出「9 月上線」）；「每 3 月」「前 3 月」這種沒有「個」的期間寫法也會被當成月份。`Jan`、`Mar`、`Jun` 這種首字大寫的縮寫是人名或別的字時也會被當成月份。句首大寫的助動詞 `May` 剛好緊鄰數字時（「May 5 groups differ?」）也會被當成五月；反過來，`between April and May` 的 May 沒接數字，不算五月（偏保守的誤擋）。
- **範圍與百分點**：`10-40%` 讓輸出「10%」對得上，即使原意是「10 到 40%」以外的寫法；`2019-20%` 會讓「2019%」對得上（前半沒限制位數）。`%` 後面的 `-` 兩種讀法都留，輸出寫 `-38.94%` 仍對得上（和修改前一樣）。`A 10% point estimate` 的 10 也會被當成百分點（`point` 後面接的是別的名詞）。`10 to 40%` 的 10、`10-40% points` 的 40、`pre-10-40%`（前面是連字號）的 10 不算（偏保守）。
- **正負號**：輸出把負的效果寫成正數（漏掉「下降」這類方向詞）時抓不到；輸出的方向寫反（輸入 -0.35、輸出「提高 0.35」）也抓不到。
- **年代**：輸入有 `1960s` 時，輸出把別的事寫成「60 年代」也對得上；`participants in their 60s` 這種年齡、`each 30s video ad` 這種秒數也會被當成年代。
- **原本的數字讀法認不出的科學記號**：原本的讀法把 `1.2 ⋅ 10-3`、`1.2 E -3`、`10^ ±3`、`10**-9` 這類寫法讀成片段（1.2、10、3），修改前輸出「10」「3」就會過，這次沒有收緊。新規則在片段上多加百分比、百分點、空白千分位的讀法時，會多出原本沒有的值（例如 `1.2 ⋅ 10-3% points` 讓「提高 10%」對得上），所以用兩層擋：認得出的寫法由上面那張科學記號清單標出來、新規則不用；沒看過的符號（`1.2 ⊗ 10-3% points`）由白名單擋。剩下的漏網是前面是一般的詞時：`1.2 times 10-3% points` 會讓「10%」對得上（和 `2019-20%` → 2019% 是同一類）；年代本身也是（`1.2 E-10s`、`K1.2 × 10-10s` 讓「10 年代」對得上，但修改前輸出「10」本來就會過，年代沒有多出新的值）。
- **英數詞**：輸入剛好有用空白隔開的兩段（`N 120`）時，輸出 `N120` 會對得上。「一個字母＋一位數字」與數字開頭的英數詞照原本的方式讀，所以輸入寫 `Hypothesis 1`、輸出寫 `H1` 仍會過，輸出寫 `5G` 而輸入只有 5 也會過（和修改前一樣）。英數詞前面緊接 `.`（`研究.N120`）時不當成英數詞，照原本的方式讀（和修改前一樣）。
- **詞形變化**：只看字尾、不查字典，字尾剛好對得上的不同詞擋不住：universe／university、organ／organic、digit／digital、execution／executive、conservation／conservative、personal／personality、institute／institution、integral／integrity、physical／physician、ration／rational、policy／policing、mean／meaning、mind／mindset、Victor／Victorian（前六組單元測試寫成已知漏網）。審查後收緊，individual／individualism、posit／positive、object／objective、minor／minority、author／authority、organ／organism、commune／community 這類已經擋下。
- **黏字**：子字串不分詞義，輸入有 `information` 時輸出的 `format` 也算認得；`international` 讓 `national`、`asymmetric` 讓 `symmetric`、`interpersonal` 讓 `personal`、`overconfidence` 讓 `confidence` 認得（字首不是單一否定字首，或是 a-、inter-、over- 這種不在清單裡的）。輸入是變化形、輸出是 6 個字母以上的原形時，也由這條認得（輸入 `individualism`、輸出 `individual`；輸入 `authority`、輸出 `author`），所以詞形變化收緊的那幾組只擋「輸入原形、輸出變化形」這個方向。單元測試寫成已知漏網。
- **繁中比例**：一個漢字帶一個 8 個詞以內的英文括號（「研（八個英文詞）」）仍不會被比例擋（英文詞仍然要在摘要裡出現，不是編造；單元測試寫成已知漏網）。

其他：

- **門檻不算進指紋**：已經 `rejected` 的論文要用 `radar runs retry` 重跑才會用新判準；重跑是重新呼叫模型，實際救回幾篇要跑了才知道（約 240 篇是照上次的輸出估的）。
- **英數詞變嚴**：字母開頭、輸入沒有同一個詞、而且不是「一個字母＋一位數字」的英數詞，原本只要數字在輸入裡就會過，現在擋：`H2b` 對 `Hypothesis 2b`、`H12` 對 `twelve hypotheses`、`B2C` 對 `business-to-consumer`、`Web3` 對 `Web 3.0`、`v2.1` 對 `version 2.1`、`SDG13` 對 `Sustainable Development Goal 13`、`FY2020` 對 `fiscal year 2020`、`SP500` 對 `S&P 500`、`P2P`／`B2B` 對 `peer-to-peer`／`business-to-business`（輸入別處剛好有 2 或 two 時）。數字開頭的（`2x2` 對 `2 × 2`、`2020Q1` 對 `Q1 2020`）照原本的方式讀，不會變嚴。
- **詞形變化收緊的代價**：審查後收緊（-ism、-ist、-ive、-ively 不和原形配；-ity 和原形配要 7 個字母）也讓意思相同、資管常見的 collaborate → collaborative、interact → interactive、innovate → innovative、institutional → institutionalism、capital → capitalism、secure → security 認不得（偏保守）。可選的救法：只在原形以 -ate 結尾時讓 -ive 和原形配（collaborate、innovate、create；posit、object、product 不受影響），由 Kevin 決定。
- **研究模型沒有跟著改**：同一份摘要，研究模型的英文名、繁中標籤仍用原本的判準，會比中文重點嚴。要不要跟著放寬另外決定。
- **偏保守的誤擋**（這些寫法修改前也擋，這次沒救回來）：科學記號清單不看前面是什麼，`Group X 10-40%`、`2 × 10-40%`、`Weights * 10-40%` 的 10 不當百分比；白名單讓 `±10-40%` 的 10、破折號後面的 `- 131 978`、`@ 1 200`、中文引號裡的 `「1 200」` 不當起點；`1950s – 1960s`（破折號前後有空白）的 60 不算年代；`mid -1960s` 的 `-1960` 是原本讀法的負數，不算年代；月份、年代前面是「`-`＋空白」而 `-` 前面不是另一個「月」「年代」時不換（`前後 - 3 月`）。

## 2026-11-18 更新：通用縮寫的允許清單與整欄說明存成空值

### 發生什麼事

上一節之後，剩下的誤擋裡有兩類是「把輸入讀得更完整」救不回來的：

- **通用縮寫**：摘要寫全名（`decision making trial and evaluation laboratory`），模型照 prompt 規則 3 在中文名稱後面加了通用縮寫（「決策試驗與評估實驗室法（DEMATEL）」）。縮寫不在標題或摘要裡，也不是全名的首字母，被當成編造擋下。全庫約 75 篇。
- **整欄只有說明**：模型在欄位裡寫「摘要未明確說明具體研究方法與資料來源」這種講摘要本身的話（prompt 要它填 null，它沒照做）。原本整欄比對（決定 5）只認得很短的句型，認不得的落到夾帶規則（決定 6 第 3 條），整筆拒收。

原則不變（Kevin 2026-11-18）：輸出的數字與英文詞都要在標題或摘要裡有依據；每一項放行都有「仍然擋得住編造」的反例測試，拿不準的維持拒收。Kevin 2026-11-18 決定 3：只處理「整欄都是說明」；前面有內容、後面多一句說明的維持拒收，不刪句子。

### 考慮過的選項

| | 做法 | 好處 | 代價 |
|---|---|---|---|
| A | 縮寫只要在清單裡就放行 | 最簡單 | 模型憑背景知識多寫的縮寫（「TAM 等接受理論」）也會過，違反原則 |
| B | 縮寫在清單裡，**而且**輸入有它登記的全名才放行 | 縮寫有依據（全名在摘要裡），編造照樣擋 | 清單要人維護；全名的寫法要登記齊 |
| C | 不用清單，猜縮寫和全名的對應（例如字母依序出現在全名裡） | 不用維護 | 猜錯就放過編造（`DEMATEL` 的字母也依序出現在很多不相干的詞組裡） |
| D | 整欄說明：把夾帶規則放寬，夾了說明的句子刪掉再存 | 救最多 | 違反決定 3（刪句子會改變模型的輸出） |
| E | 整欄說明：用封閉的詞表認「整欄都是說明」，認得的存 NULL；其他照舊 | 不刪句子；詞表外的字一出現就不算，保守 | 詞表外的說明寫法認不得，照舊拒收 |

### 決定

縮寫選 B，整欄說明選 E。

**通用縮寫的允許清單**（`config/zh_summary_acronyms.yaml`）：

1. 檔案最上面是 `version`（正整數），`acronyms` 是清單，每一筆是 `acronym`（縮寫）與 `full_names`（英文全名，可以有多個寫法）。只經 `radar/config.py` 的 `load_zh_summary_rules` 讀：和 `config/zh_summary.yaml` 一起讀、合成一個 `ZhSummaryRules`（門檻＋`acronyms`），所以 worker、CLI、啟動檢查（`entrypoints/startup.check_ai_config`）、services 的呼叫端都不用改，啟動時就驗證。`zh_summary.yaml` 照舊只收三個門檻鍵（允許清單不能寫在那裡）。驗證不過的錯誤格式和其他設定檔一樣（「檔名：欄位路徑：原因」）：缺檔、不是合法 YAML、鍵寫兩次、缺鍵或多鍵、`version` 不是正整數（字串、浮點數、布林都擋）、縮寫不是「英文字母開頭、只有英文字母與數字、至少 2 個字元」、縮寫重複（不分大小寫）、全名是空的或有詞表外的字元（只能是英文詞，詞與詞之間一個空白或一個連字號）、同一筆的全名重複（不分大小寫，空白、連字號、連在一起算同一種寫法）。第一輪修正另外加上下限：每個全名最多 12 個詞（現有最長的是 MULTIMOORA 的 11 個詞）、至少兩個詞（只有一個詞時至少 10 個字母，`electroencephalography` 照樣可以登記）；每筆最多 12 個全名；清單最多 200 筆；不同筆登記同一個全名（照同一種寫法的算法比）也擋（同一筆裡兩個不同的全名照樣可以，例如 SDT）。直接建 `ZhSummaryRules` 時清單預設是空的（沒有任何縮寫因為清單放行）。
2. **放行的兩個條件都要成立**：
   - （a）輸出寫的英文詞（`_ENGLISH_TOKEN`）或英數詞（`P2P`、`B2B`，`ExtendedVocabulary.knows_alnum`）和登記的縮寫**一模一樣**，大小寫也要一樣（`GloVe`、`fNIRS`、`BiLSTM` 照寫；`Glove`、`GLOVE`、`FNIRS`、`p2p` 都不算；後面多一個字的 `DEMATELs` 也不算）。`PLS-SEM` 這種連字號串每一段各自照規則（原本的 `knows_token`）。
   - （b）輸入（標題或摘要）裡出現了那個縮寫登記的某一個全名：不分大小寫；全名的詞要**連續**出現（只有一部分、或分散在各處、中間隔了逗號、括號、別的詞都不算；摘要裡的換行、tab 在檢查用副本裡會縮成一個空白，所以和空白一樣算連續——斷行的全名是同一個詞組；標題與摘要的接縫不算連續，因為兩份副本是做完之後才用換行接起來的）；詞與詞之間一個空白、一個連字號、或連在一起都算一樣（`decision-making`＝`decision making`；`multi-criteria`＝`multi criteria`＝`multicriteria`；摘要少了空白黏成一串的 `decisionmakingtrialandevaluationlaboratory` 也算），但全名要從輸入的詞頭開始、在詞尾結束（`xdecision making…`、`…laboratoryx`、黏在前一個詞後面的 `Weapplythedecisionmaking…` 都不算）；全名開頭的詞前面不能用連字號接著別的詞（`non-leader-member exchange` 不算）；只有全名的**最後一個詞**容許上一節的複數與詞形變化（`model`／`models`／`modeling`／`modelling`、`autoregression`／`autoregressive`），而且那個詞要剛好是輸入的一個詞；前面的詞要一模一樣（第一輪修正，審查 A3：每個詞都能變的時候，`team members exchange knowledge` 這種一般句子會對上 `team member exchange`）。前面的詞是複數的常見寫法要另外登記（`differences in differences`、`areas under the curve`）。黏字規則不用。英式美式拼法（`optimisation`／`optimization`）詞形規則蓋不到，在設定檔多登記一個寫法。
   - 只有縮寫在清單裡、輸入沒有全名的照樣擋。輸入有 A 的全名、輸出寫 B 的縮寫也擋（`decision making trial and evaluation laboratory` → `TOPSIS`、`leader-member exchange` → `TMX`、`peer-to-peer` → `B2B`）；清單外的縮寫照原本的規則（`business-to-business` → `B2C` 擋）。
   - 實作：`text_checks.ExtendedVocabulary.build(text, acronyms)` 先算出「輸入有全名」的縮寫（`_allowed_acronyms`），`knows_word`（英文詞）與 `knows_alnum`（英數詞）多認這些縮寫。所有全名拿掉空白與連字號後建成一棵字母樹，從輸入每個可以當開頭的詞走一次、同時比對所有全名（第一輪修正，Codex X2：原本逐一全名、逐一起點試，全名很長或清單很大時是平方級）；最後一個詞的詞形變化在「走完前面的詞」的節點上查，同一個節點、同一個輸入詞只查一次。耗時對輸入長度是線性；另外和清單大小（全名的詞數、每筆的全名數、清單筆數）成正比，這三個由設定檔驗證限制上限（清單用到上限、輸入 20 萬字元的測試在 3 秒內）。研究模型不用 `ExtendedVocabulary`，不受影響。
3. **初版清單**（27 筆）：DEMATEL、VAR、SEM、PLS、DID、EEG、fNIRS、MLP、BiLSTM、MDS、MCDM、AUC、SHAP、GloVe、IPFS、TOPSIS、COPRAS、WASPAS、MULTIMOORA、LMX、TMX、RBV、SDT、XAI、QCA、P2P、B2B；每一筆的全名寫法見設定檔。SDT 登記兩個意思（self-determination theory、signal detection theory），輸入要有其中一個全名才放行。需求列的 MICMAC、VIKOR 沒有放：原文是法文、塞爾維亞文（有變音符號，比對不到），英文的譯法有好幾種，拿不準要登記哪幾個（全名寫法另列給 Kevin）。
4. **怎麼維護**：加一筆就是在 `acronyms` 加 `acronym` 與 `full_names`（寫英文摘要裡實際會出現的寫法，常見的幾種都登記；拿不準的不要放：全名寫錯只會救不回來，寫成別的東西的全名會放過編造），並把 `version` 加一；改全名寫法、刪一筆也加一。`version` 是給人看「清單改過了」，沒有雜湊登記（和分類表、情境值清單不同：那兩份會改變模型的輸入，這份只改變驗證）。設定檔的檔頭寫了放行條件與加一筆的方法；`tests/unit/test_zh_summary_acronyms.py` 對清單裡每一筆的每一個全名寫法都跑一次「輸入有全名就放行」、對每一筆跑一次「輸入沒有全名就擋」，加一筆不用另外寫測試。
5. **不算進輸入指紋**：和 `config/zh_summary.yaml` 一樣（見取捨的「門檻不算進指紋」）。輸入指紋 `domain/fingerprints.input_sha256` 只算算法版本、工作代碼、每個區塊的文件種類、來源與文字，加上分類表版本（`classify`）、情境值清單版本（`extract_model`）兩個參數；中文重點帶任何一個版本都會丟 `ValueError`，閘門（`services/llm_gateway.py`）只從 `LlmJob` 的那兩個欄位傳版本，允許清單只在 `ZhSummaryValidator` 的 `rules` 裡，不會進到指紋。理由：清單只改變「怎麼驗證輸出」，不改變送給模型的內容；算進指紋會讓每次加一筆就把全部有摘要的論文重跑一次模型（花錢、輸出也會變）。代價同門檻：已經被拒收的論文要用 `radar runs retry` 重跑才會用新清單。反方向也一樣：刪掉一筆或把全名改窄，已經靠它通過、存下來的結果不會重新驗證，會一直留著；要清掉得另外處理（結果沒有記是用哪一版清單驗證的）。單元測試固定 `input_sha256` 的參數只有這四個。

**整欄說明存成空值**（`zh_summary.is_placeholder` 的 `_whole_field_meta`）：

6. 整欄比對（決定 5）多認一種：整欄（拿掉開頭的「欄位名稱＋冒號」、空白與標點、不分大小寫之後，所以外層括號、句尾標點不影響）**只由**一句或幾句講「摘要沒寫什麼」的子句組成，每個字都來自封閉的詞表：
   - 否定子句：主詞＋地點（在／於＋摘要、原文、文中、本文、文章、論文＋中）＋否定（未、沒有、沒，前面可接並、均、皆、也、亦、尚）＋程度（明確、具體、清楚、詳細、特別、直接，可接「地」，最多兩個）＋後設動詞（一定要有）＋研究要素（可省略；研究方法、分析方法、計量方法、資料來源、資料、數據、實證資料、理論、理論框架、理論基礎、解釋框架、概念框架、分析框架、研究問題、研究設計、研究對象、研究假設、假設、樣本、樣本數、變數、發現、結果…；可用與、或、及、和、以及、或是、跟、暨並列，前面可接其、任何、相關、具體、明確、所使用的…）。
   - 主詞沿用（第一輪修正，Codex X1、審查 A2、A7；原本沒寫主詞的子句一律當成主詞是摘要，所以「僅提出概念框架（摘要未說明具體研究方法）」「未提出假設」「在本文中未提出假設」「本研究未說明理論，也未提出假設」都變成 NULL）：每一欄從「還不知道主詞」開始。子句裡明寫了摘要、原文、文中（當主詞，或當地點「在／於摘要中」，地點在否定詞前後都算）→ 這個子句與之後沒寫主詞的子句是「摘要類」；明寫了本文、本研究、研究、作者、文章、論文（當主詞，或當地點「在／於本文、文章、論文中」）→「論文類」；兩類都寫了算論文類；之後又明寫另一類就換過去。
   - 否定子句的動詞：講「寫了什麼」的說明類動詞（說明、提及、提到、描述、指出、交代、列出…）三種狀態都收；「提出、提供、報告、揭露、涉及、呈現」只有摘要類才收——「未提出假設」「作者未提出假設」「在本文中未提出假設」「本研究未說明理論，也未提出假設」可能是在講研究本身（探索性研究、概念性論文），照修改前的規則處理（當內容存，或夾了講摘要本身的句子就拒收）。
   - 「僅／只＋提出、提及、說明、描述、指出、呈現＋研究要素」子句（「摘要僅提出解釋框架」）：只能接研究要素清單裡的名詞，而且只有摘要類才收（開頭沒寫主詞的「僅提出概念框架」、接在論文類後面的都不收）。
   - 研究要素前面的修飾語「使用、採用」一定要帶「所」或「的」（所使用、所採用、所用、使用的、採用的；第一輪修正，審查 A1）：「摘要未說明具體研究方法，採用實證分析」的後半是在講研究做了什麼，照修改前拒收。
   - 至少要有一個否定子句；子句之間可以接而、但、且、卻；最後可以接「填 null」「故填 null」（也收 none、空值）。
   - 所以 brief 的四種寫法都存 NULL：「摘要未明確說明具體研究方法與資料來源」「未於摘要中說明具體資料來源與分析方法」「摘要未明確提出理論或理論框架，填 null」「未明確說明（摘要僅提出解釋框架，未描述實證資料或分析方法）」。其他欄位照常驗證。
   - 任何詞表外的字出現就不算整欄：「摘要未明確指出理論框架，僅提及『禮物經濟』的概念」（禮物經濟）、「以問卷調查分析（摘要未說明樣本數）」（前面有內容）照舊由夾帶規則拒收；「受訪者未提及隱私疑慮」「原文未揭露姓名時仍可推得作者身分」「本文探討使用者為何不揭露個人資訊」照舊當內容；「未說明研究方法，但採用了深度訪談」照既有規則當內容（不會變成 NULL）。
   - 原本的兩條正規式（整欄的 `_PLACEHOLDER_ZH`、夾帶的 `_EMBEDDED_PLACEHOLDER`）一個字都沒改：原本存 NULL 的照樣存 NULL；新規則只會讓更多欄位存 NULL。驗證與寫入前的正規化是同一個函式（`normalize_zh_summary` → `is_placeholder`），兩邊一致。實作是一個小的狀態機（`_whole_field_meta`）：從頭一個子句一個子句往後讀，狀態是目前的主詞類別，每個子句用固定開頭的正規式在目前位置比一次；每一段都用佔有式量詞或在固定位置分岔，子句比不上時只會在動詞之前的固定幾個字內失敗，線性時間（20 萬字元的長輸入測試）。
7. **四欄全部變成 NULL**（照既有行為，這次沒改）：驗證通過、回四欄都是 None 的內容（不是拒收）；`services/ai_results.py` 照平常寫成一筆 `active`、四欄全空的列（`NewAiResult` 收得下，資料表的兩個 CHECK 都成立：拒收才要求全空、有值才要求非空白）；論文頁的 AI 區塊是 `empty`（`repo/ai_blocks._zh_summary_block`），畫面（`web/src/components/paper/ZhSummarySection.tsx`）四欄都顯示「摘要未提及」，照樣有 AI 標章與固定一行。也就是這次改動之後，四欄都只寫說明的輸出會從「拒收」變成「一筆四欄全空的有效結果」，不會自動重跑。決定 5 原本就讓四欄都是佔位字的輸出這樣存（取捨「四欄全是 NULL 也寫成 active」）。

### 取捨與還不知道的事

允許清單的已知漏網與偏保守：

- **全名在摘要裡、但和縮寫講的不是同一件事**：輸入有 `peer to peer`（例如「peer to peer comparison」）時，輸出的 `P2P` 也會過。全名本身就是依據，模型寫錯對應時抓不到。GloVe 原本也登記了 `global vectors`，太一般（`a global vector of prices`），第一輪修正拿掉，只留 `global vectors for word representation`。
- **詞形變化的寬度**：最後一個詞用上一節的字尾規則，字尾剛好對得上的不同詞也會過（`vector autoregressive model` 讓 `VAR` 過是想要的）。第一輪修正後前面的詞要一模一樣，所以 `team members exchange`（TMX）、`leader members exchange`（LMX）、`signaling detection theory`、`self-determined theory`（SDT）、`structure equation models`（SEM）、`complexity proportional assessment`（COPRAS）都不再由清單放行；其中 SDT、SEM 兩例整筆照樣會過，是既有的首字母規則（`signaling detection theory` 的首字母就是 sdt），和清單無關。代價：前面的詞是複數或詞形變化、又沒有另外登記的寫法救不回來（`decision-making trials and evaluation laboratories` 的 DEMATEL、`multi-criterion decision making` 的 MCDM）。
- **偏保守的誤擋**：全名黏在前一個詞後面（`Weapplythedecisionmaking…`）、詞與詞之間有兩個分隔（`decision - making`；斷字的 `decision-\nmaking` 在副本裡變成 `decision- making`，也是兩個分隔）、全名開頭的詞前面接連字號（`fuzzy-decision making trial and evaluation laboratory` 的 DEMATEL）、英式美式拼法沒登記的、全名縮寫的大小寫和登記的不同（`Glove`），都照樣擋。最後一個詞的複數與詞形變化用「複數變化」與「前 4 個字母」兩種索引找候選，規則和 `_same_word_form` 一樣，所以不會比原本少認（原本另外要求開頭的詞前 3 個字母一樣）。
- **清單沒有的縮寫照舊**：沒登記的縮寫只能靠原本的首字母比對（`TAM`、`UTAUT`）；MICMAC、VIKOR 這次沒放。
- 2 個字母的縮寫很容易碰巧對上（原本的取捨）不受影響：清單只增加「輸入有全名」這一種放行。
- 放行多少篇要用 `radar runs retry` 重跑才知道（約 75 篇是照上次的輸出估的）。

整欄說明的已知漏網與偏保守：

- **詞表外的說明寫法認不得**：例如「摘要對研究方法語焉不詳」「摘要僅概略提到研究背景」「研究方法：摘要無相關描述」（「無」「語焉不詳」「研究背景」不在詞表）照舊拒收或當內容。之後看到常見的再加進詞表。
- **詞表內的組合不一定是說明**：說明類動詞（說明、提及、描述…）不論主詞都當說明，所以沒有主詞的「未說明研究方法與資料來源」「未說明具體方法」這種原本當成內容存的也改成 NULL（決定紀錄逐條列了原本當內容、現在存 NULL 的寫法）；主詞是本研究、作者時也一樣（「研究未說明的變數」）。「提出、提供、呈現」這類可能在講研究本身的動詞，第一輪修正後只有在明寫（或沿用）摘要、原文、文中時才當說明，所以「摘要未說明研究方法，也未提供樣本數」存 NULL、「未提出假設」照修改前當內容。主詞沿用只看前一個子句：「本文未說明研究方法，摘要也未提供樣本數」存 NULL；開頭沒寫主詞的「未提供樣本數，摘要未說明研究方法」不會因為後面才寫摘要就收（照修改前拒收）。
- **四欄全空的結果**：四欄都只寫說明的論文，畫面顯示四欄「摘要未提及」，和模型直接填 null 一樣；看不出模型原本寫了說明。

### 補充 PR 1 的已知漏網與偏保守的誤擋

上一節（把輸入讀得更完整）的審查留下的項目，這次一起處理或補記：
