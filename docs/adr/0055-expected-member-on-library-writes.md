# ADR-0055：文獻庫的寫入與成員專屬的讀取帶「這個分頁以為的成員」，後端在那一刻比對

- 狀態：提議（epic-3h PR 3，2026-11-21；epic-3h2 PR 1 審查修正同日更新：讀取也比對、標頭跟資料走）
- 相關：ADR-0008（session 與 `Origin`）、ADR-0046（成員版的登入）、ADR-0047（錯誤回應）、ADR-0049（文獻庫的三個寫入端點）、PR #114（找論文有暫留列時切回視窗先確認）

## 背景

同一個瀏覽器，成員甲的分頁開著，乙在另一個分頁登入（cookie 換成乙的）。甲的分頁在發現換人之前按的「加入」「移出」「復原」，請求帶的是乙的 cookie，後端照 session 認成乙，就寫進或刪到乙的文獻庫（epic-3g 審查 D1、Q8、P3-1、P3-2）。

#114 只擋了「找論文有暫留列」那一種（切回視窗先問「我是誰」，問到換了人就不送）。沒有暫留列的找論文、論文頁、我的文獻庫頁（復原）都還會發生；切回視窗時「我是誰」問不到（網路錯、伺服器錯）就照常送出（L2）也還在。Kevin 2026-11-21 決定要修。

## 考慮過的選項

1. **後端在寫入的那一刻比對**：前端的三種寫入都帶一個請求標頭，值是這個分頁以為的成員；後端和這次 session 的成員比，不同就什麼都不寫、回錯誤。
2. **每次切回視窗先問「我是誰」**（把 #114 的做法擴大到所有頁面與所有寫入）：確認前按鈕先等，換了人就不送。
3. **只靠前端擋**：例如監聽 `storage` 事件或定時問「我是誰」，發現換人就把按鈕停用、整頁換掉。

## 決定

選 1。

- **標頭**：`X-Radar-Expected-Member`，值是成員 ID（標準 UUID 寫法）。原則：**寫入帶的值＝畫面上那份資料是用誰的身分讀的**，不是「路由現在認定的人」（見下面「前端」與「兩個方向」）。
- **後端**：比對只有一個函式 `radar/entrypoints/api/auth.py` 的 `check_expected_member`，經 `member_as_expected`（先認 session、再比對）用在：
  - 文獻庫的三個寫入（`PUT`、`DELETE /api/v1/library/{paper_id}`、`POST …/restore`）；
  - 成員專屬的讀取：論文頁 `GET /api/v1/papers/{paper_id}`（回 `in_my_library`）、找論文清單 `GET /api/v1/papers`（每一列的 `in_my_library`、範圍我的文獻庫）、文獻庫清單 `GET /api/v1/library`。
  
  `library.py` 的四個端點共用相依項 `acting_member`（就是 `member_as_expected`），`papers.py`、`paper_list.py` 直接呼叫。行為：先認 session（沒登入 401，順序不變），再比對：
  - 沒帶標頭：不檢查，行為和以前完全一樣。
  - 帶了、和 session 的成員相同：照常。
  - 帶了、和 session 的成員不同：**409 `member_changed`**，不呼叫 services，什麼都不讀不寫（讀取不回任何資料）。
  - 值不是標準 UUID（含空字串、沒有連字號、大括號、`urn:uuid:` 前綴），或標頭出現不只一次：**400 `expected_member_invalid`**，不呼叫 services。大小寫不拘。
  - 兩種錯誤都帶 `Cache-Control: no-store`，格式照 `problems.py`（RFC 9457）。比對的是 session 認出的成員，不看請求裡別的欄位。
  - **不比對的讀取**：`GET /api/v1/me`（它就是用來問「現在是誰」的，比對了就問不出換人）、`GET /api/v1/display-names` 與 `GET /api/v1/client-config`（設定值，每位成員都一樣，沒有誰的資料可以錯置）、登入登出（還沒有或正要結束 session）。之後新增回成員專屬資料的讀取，要改用 `member_as_expected`。
  - 標頭沒有寫進 OpenAPI 的參數（直接讀 `request.headers`，和 `Origin` 檢查一樣；要能分辨「出現兩次」）；端點說明與錯誤代碼列舉有更新。400／409 也沒有逐一寫進各端點的回應宣告：全站的 API 一律只宣告 `default` 的 problem 回應（`app.py` 的 `PROBLEM_RESPONSES`，`/readyz` 的 503 例外），不為這兩個破例（審查 M2）。
- **前端**：
  - 標頭只在 `web/src/datasource/api/index.ts` 加（`expecting`；三種寫入的 `change` 與三個讀取共用）；409 `member_changed` 變成結果 `memberChanged`。讀取帶了預期成員時，讀到的結果記下 `readAs`（＝帶的那一位；後端比對過，所以這份資料就是這一位的）。
  - **讀取帶誰**：這一頁認定的成員（路由 context 的 `member`）。找論文、我的文獻庫把它交給清單的查詢（`paperListQuery`／`libraryListQuery`／`libraryCountQuery` 的 `memberId`）；論文頁的 loader 用 loader 執行當下的 context。「再載入」只接同一位讀的那一份（`readAs` 相同）。這幾個查詢（含論文頁）的**快取鍵最後一段是讀的成員**（`paperListKey`／`libraryListKey`／`paperKey`）：換人後的頁面不會接到上一位進行中的讀取或留下的 409（審查 fix2 N1）。「再載入」確認暫留列的補查回 409 時，整份清單回 `memberChanged`、走換人流程，不當成查不到（審查 fix2 N2）。
  - **寫入帶誰**：那份資料的 `readAs`，不是 context 現在的值。論文頁：loader 回傳結果的 `readAs`，`usePaperLibrary` 交給 `useLibraryChange(readAs)`；找論文：清單資料的 `readAs` 放進 `RowsReadAs`（React context），每一列的 `LibraryToggle` 取用；我的文獻庫：清單資料的 `readAs`。沒有 `readAs`（資料不是帶預期成員讀的，成員版沒有這種畫面）就**不送、回 `"failed"`**。
  - **頁面跟著成員重新掛上**：找論文與我的文獻庫的 key 含 context 的 `member_id`（再加上 409 與 #114 的換人次數），論文頁那一塊的 key 含資料的 `readAs`。換人時上一位的 `placeholderData`、「已移出」「復原」（`gone`）、移出中（`removing`）等元件狀態一律不留。
  - 寫入或讀取收到 `memberChanged`：不重試、不改快取；寫入回 `"failed"`（按鈕馬上恢復，不等換人做完）。同時照「發現換人」處理（`followMemberChange`，讀取經 `useFollowMemberChange`）：問一次「我是誰」→ 清掉上一位的查詢快取 → 找論文與我的文獻庫同步重新掛上 → 重跑路由的登入檢查與資料讀取（導覽列、論文頁換成現在的人）；沒有人就回登入頁並帶「登入已經過期」。同時收到好幾個 409 只處理一次；換人流程已經做完（沒有進行中的一輪、快取的「我是誰」與路由的成員都已不是這次寫入帶的預期成員）之後才回來的舊 409 只回 `"failed"`，不再跑一次（審查 fix3 G2a）；「我是誰」說沒有人時，世代號還是這一輪的才回登入頁（比照 401；審查 fix3 G2b）；這個流程失敗（例如重跑路由丟錯）不留沒人接的 rejection，下一個 409 重新開始。讀取 409 期間清單是骨架、論文頁是載入中。
  - **換人途中不先用上一位讀**（審查 fix2 N1）：重新掛上的那一刻路由 context 還是上一位、快取裡的「我是誰」已經是現在的人。兩者不同的這段期間，找論文與我的文獻庫不讀成員專屬的資料（`member.tsx` 的 `useMemberSwapPending` → 頁面的 `paused`，清單是骨架）；路由換成新的人後因 key 再掛上一次，一掛上就用新的人讀。#114 的流程與同頁換網址時 `beforeLoad` 認到別人也一樣適用。
  - **收尾**：這一輪結束（拿掉進行中的那一次）之後，快取裡畫面正在用、結果是 `memberChanged` 的查詢照現在的身分重讀（流程開始前用上一位送出、流程期間才回來的 409）。頁面對「每一份」409 結果各處理一次（用查詢這次結果的時間 `dataUpdatedAt` 認是哪一份，不用結果物件：TanStack Query 的結構共享在內容相同時沿用同一個物件；審查 fix3 N1），所以重讀又是 409（真的又換了人）會開始新的一輪，不會接到已經結束的那一輪而停在骨架。
  - L2（切回視窗時「我是誰」問不到）：畫面上的資料仍是上一位讀的，寫入照樣帶上一位，後端會擋。
- **兩個方向怎麼保證「標頭＝資料的主人」**（審查 M6）：
  - **資料先換、context 後換**（#114 的流程先重新掛上、再重跑登入檢查）：新讀到的資料是用 context 那一位讀的、`readAs` 是那一位，寫入帶它。讀取時 cookie 已經是別人就 409，不會讀進來。結果是「少讀少寫」，不是寫錯人。
  - **context 先換、資料後換**（同一頁換網址時 `beforeLoad` 先認到下一位；409 之後 `router.invalidate()` 讓論文頁在背景重讀）：畫面上還沒換掉的資料（placeholder、元件狀態、背景重讀前的論文頁）`readAs` 仍是上一位，寫入帶上一位 → 409，不會寫進下一位的文獻庫。找論文與我的文獻庫另外因為 key 含成員而立刻重新掛上，上一位的列直接離開畫面；「我是誰」已經換人、context 還沒換的那段期間不讀（見上面「換人途中不先用上一位讀」）。
  - **讀取途中 cookie 又換了**（「我是誰」認到甲、讀取送出時已經是乙）：讀取帶甲 → 409，資料不進畫面，照換人處理（審查 H3）。
- **#114 的「有暫留列時切回視窗先確認」留著不拆、不擴大**：它讓畫面早一點換成對的人；有了後端的保護之後，它裡面「確認期間寫入先等」那段等待變成多餘的保護，要不要拿掉由 Kevin 決定。
- **測試守著**：e2e 的替身 API 對三個寫入路徑記下沒帶標頭的請求，`e2e/fixtures.ts` 在每個測試結束時要求是空的（新增一種寫入卻沒帶標頭，測試就失敗）；替身的三個讀取也照後端比對（不符 409）。「值是不是資料的主人」由 `library.spec.ts` 的 fix1 那一組守（同頁換網址、409 後背景重讀時再按、讀取途中換 cookie）；清單的 `readAs` 那一層單獨由 `web/src/pages/library-write-as.test.tsx` 守（故意做出「清單是甲讀的、頁面認定乙」，寫入要帶甲）。換人只跑一輪、換人後只用新的人讀、補查的 409 由 fix2 那一組（e2e）與 `library-change.test.ts` 的 fix2 組守。

## 理由

- **只有寫入那一刻的比對沒有空檔**：選項 2 的「問」和「按」之間永遠有一段時間（問完、畫面還沒換掉之前按下去，或滑鼠從別的視窗直接點進來時 focus 和 click 幾乎同時，#114 第 3 輪花了很多力氣在這一段）；後端在同一個請求、寫入之前比對，cookie 是誰、分頁以為是誰，一次就對清楚。
- **問不到時不必兩難**：選項 2 在「我是誰」問不到時只能選擇擋（網路一抖動就按不了）或照送（L2 的缺口）；帶標頭不需要再問一次。
- **不用每個寫入點都記得等**：選項 2 每新增一個寫入點都要記得先等確認；選項 1 的標頭只在一個函式加，還有 e2e 的替身守著。
- **選項 3 擋不住**：前端偵測一定有延遲（`storage` 事件不涵蓋 HttpOnly cookie 的改變，定時問有間隔），按下去的那一刻仍可能送錯人。
- **沒帶標頭照常**：這個保護防的是自己人的舊分頁，不是惡意請求。權限仍然只看 session；能偽造請求的人本來就能用自己的 session 寫自己的文獻庫，帶不帶標頭都不會多出權限。沒帶照常也讓既有的 API 用法（整合測試、之後的命令列工具）不用跟著改。
- **409 與 400 分開**：409 是「狀態衝突」（分頁的狀態和伺服器的不一致），前端要照換人處理；400 是請求本身寫錯，前端不會送出這種值，不需要特別處理（照一般失敗）。

## 取捨

- 每個寫入多一個標頭、後端多一次字串比對，成本可以忽略；session 只認一次（相依項回傳的成員直接給路由用，不重複查資料庫）。
- 換人之後第一次按下去會「沒反應」一下（按鈕恢復、整頁換成新的人），不顯示新的文字：State Patterns 沒有這種句子，沒有設計稿就不加（照 AGENTS.md）。
- 成員專屬的讀取也多一個標頭與一次比對，換來「讀到的資料一定是標頭那一位的」。換人時的請求（審查 fix2 L-b，照修正後的行為）：每一輪換人流程問兩次「我是誰」（流程本身一次、重跑路由的登入檢查一次），之後照新的人重讀這一頁（快取清過，設定值與顯示名稱也重讀）；由讀取發現的，再加上發現它的那一個 409。換人途中不會先用上一位再讀一次，也不會跑第二輪。流程開始前已經送出的上一位的讀取照樣會回來，但已經取消、不進畫面。
- 寫入的標頭跟著資料走，所以每個寫入點都要拿得到那份資料的 `readAs`（新增寫入點時要接上；沒接就不送，不會寫錯人）。
- 既有 e2e 測試 `library.spec.ts` 的 R3 寫的是這個 ADR 要擋掉的行為：**Kevin 2026-11-21 核准只改 R3**——甲的畫面上按移出，送出的標頭是甲、替身回 409，甲乙的文獻庫都不變，畫面換成乙的清單（後半段「站內換頁再回來」從乙的畫面開始）。其他既有測試不改。
