# ADR-0010：前端是一份 React 程式、兩種建置；頁面只透過資料來源層拿資料

- 狀態：提議（等 Kevin 在 PR 確認）
- 日期：2026-11-12
- 更新：2026-11-13（「跑不順」的偵測寫明只有一個函式、一組門檻，以及做首頁的 Story 要量什麼；元件庫補一句不引入第二套；介面文字的檔案格式定成 JSON）
- 對應：PRD FR-37～FR-40、FR-42、FR-44、NFR-2、NFR-12、NFR-13；UX 文件「給架構階段的事項」（介面元件庫）、Interaction Primitives（篩選寫進網址）；`DESIGN.md`；架構文件 AD-21、AD-22

## 背景

有兩個網站要做：成員版（登入後使用，有後端）與示範站（靜態快照，沒有後端）。UX 文件裡示範站的 9 個畫面中，趨勢、關係排行表、論文清單、論文頁、資料涵蓋範圍這 5 個和成員版是同一種畫面，只是內容比較少。

UX 文件留給架構決定的：介面元件庫。brief 與 `docs/skills-plan.md` 已經定了前端用 React。

## 考慮過的選項

**兩個網站怎麼做**

- **A. 兩份前端程式。** 各自最單純，但同一個畫面要做兩次、改兩次，很快就會長得不一樣。
- **B. 一份程式、兩種建置，中間隔一層「資料來源」。** 頁面不知道資料是從 API 來還是從靜態檔來。
- **C. 用支援靜態輸出的框架（Next.js、Astro）。** 示範站好做，但成員版就要跑 Node 伺服器（1 GB 主機已經滿了），或者變成兩套做法。

**元件庫**

- **1. 完整的現成元件庫（MUI、Ant Design）。** 最快有畫面，但外觀很難改成 `DESIGN.md` 的樣子（髮線分隔、不用卡片外框、自訂字體）。
- **2. 無樣式元件＋自己的樣式。** 元件庫只負責行為（鍵盤操作、焦點、無障礙屬性），外觀全部自己寫。候選：Base UI、Radix、React Aria。
- **3. 全部自己寫。** 下拉選單、對話框的鍵盤與無障礙行為很容易做錯；UX 文件的目標是 WCAG 2.1 AA。

## 決定

**B＋2（Base UI）。**

### 結構

```text
web/src/
  pages/         畫面；只呼叫 datasource，不直接連網路
  components/    共用元件（含 AiText、AiBadge、DataDateBar、Caveat）
  datasource/
    types.ts     兩種實作共用的函式清單
    api/         成員版：呼叫後端 API
    static/      示範站：讀靜態 JSON，在瀏覽器裡篩選
  stats/         占比、期刊等權、成長排名的計算（ADR-0011）
  generated/     由工具產生的型別與 API 呼叫函式，不手改
  i18n/          介面文字（JSON）
```

規則：

1. **頁面與元件不得直接 `fetch`，也不得 import `datasource/api` 或 `datasource/static`**；只能用 `datasource/types.ts` 定義的函式。用 ESLint 規則擋。
2. **兩種實作從第一個前端 Story 就都要有。** 新增一個示範站也有的畫面時，兩邊一起寫；只有成員版才有的功能（我的文獻庫、上傳、問答、證據簡報），`static` 那邊不實作，示範站的路由表也不放那一頁。
3. **建置時決定用哪一種**（`VITE_BUILD_TARGET=member` 或 `demo`）。示範站的建置結果裡不含成員版的頁面與 API 呼叫程式。兩個站互相連的網址（示範站的「成員登入」、登入頁的「回示範站」）也是建置變數。
4. **型別只從後端產生**：`radar export-schema` 輸出 `openapi.json`（成員版的 API）與 `demo-openapi.json`（把示範站的每個靜態檔描述成一個只能讀取的端點，格式和前者相同，所以用同一個工具產生型別），兩個檔都進版控；前端的型別由它們產生。CI 檢查「重新產生後沒有差異」（NFR-12）。問答串流的每種事件內容也列在 `openapi.json` 裡（ADR-0006）。
5. **篩選、排序、目前顯示幾篇、選取的項目全部寫進網址**，而且有型別：每個頁面宣告自己接受哪些網址參數，不合法的值在進頁面前就被擋掉或換成預設值。清單是「再載入 N 篇」一直往下加，不是「第幾頁」，所以網址記的是「目前顯示幾篇」；後端分頁用的書籤（cursor）不進網址。資料來源層的清單函式接受一個筆數上限（設定值），重新整理時一次拿回來。從論文頁返回清單時的捲動位置，交給路由的捲動還原與資料快取。
6. **介面文字一律走 i18n**，元件裡不得出現寫死的中文；用 lint 檢查（NFR-13）。**i18n 檔是純 JSON**（i18next 的格式，一種語言一個資料夾、一個命名空間一個檔），不寫成 TypeScript：證據簡報的匯出檔由後端產生，固定文字要從同一份檔案取（ADR-0011）。匯出會用到的鍵集中在 `export` 與警語的命名空間，值只用「兩層大括號包住名稱」的代入寫法，不用元件標記。警語（FR-39）、AI 標章的文字、空狀態的說明都是 i18n 的項目，全站只有一份。後端回的錯誤只有代號（全站一份清單，放在 `radar/domain/errors.py`），畫面上的字由 i18n 的 `errors.<代號>` 提供；後端不回中文訊息。
7. **AI 產生的文字只能用 `<AiText>` 元件顯示。** 它只允許很小一部分的 Markdown（段落、粗體、清單），不允許 HTML、圖片、連結（NFR-2）。站內的論文連結只由問答的 `citation` 事件或資料裡的論文 ID 產生，不從 AI 的文字裡解析。
8. **每個 AI 產出旁邊都有 `<AiBadge>`**（FR-37），資料來自 API 回傳的來歷欄位；元件拿不到來歷就不顯示內容。
9. **有數字的頁面都有 `<DataDateBar>`**（截至日期＋快照編號，FR-40），資料來自 API 回應或 manifest 裡的快照資訊。
10. **字體自己放**：Instrument Serif 與 DM Mono 用 npm 套件裝進專案，不連 Google Fonts。中文標題字體 `DESIGN.md` 還沒選定，這份 ADR 不決定；選定後同樣必須是可以自己放、授權允許嵌入的字體。
11. **成員版的前端檔案由 `api` 容器送出**，和 API 同一個網域，不需要處理跨網域。`/api/` 以外找不到的路徑一律回頁面殼，固定網址才打得開（示範站那邊見 ADR-0007）。
12. **兩邊都會出現的資料只有一個形狀。** 計數方塊的列、關係列、AI 標章要用的來歷資料、快照資訊、論文書目、AI 區塊的外層、問答的回答，在成員版 API 與示範站檔案都會出現。它們各只有一個後端資料模型（放在 `radar/domain/contracts.py`），API 的回應與示範站的白名單模型都由它組成，所以兩份 OpenAPI 檔裡的型別同名同形，共用的元件只要認一種。這個模型由第一個用到它的 Story 定義；後做的 Story（例如示範站匯出）不新增形狀。
13. **期刊、主題、方法一律用設定檔的代號**（小寫英文加底線），在 API、網址參數、計數方塊、示範站檔案裡都一樣，不用資料庫的 ID；未分類固定是 `unclassified`。它們的**顯示名稱是資料，不是介面文字**：由一個 API 端點與示範站的 `taxonomy.json` 提供，不放進 i18n。設定檔加一個主題時，所有畫面同時有名字。
14. **減少動態**：使用者的系統設定要求減少動態時，一條全站 CSS 規則關掉所有過場；另有一個共用的判斷函式給首頁星系與 60 秒示範用。60 秒示範的影片檔放在 `web/public/`，跟前端一起部署，不從外部網站載入。
15. **斷點只用 `DESIGN.md` 的四個值**（768、900、1200、1232）。Tailwind 內建的斷點（640／768／1024／1280）和顏色、間距、字級一樣全部清掉，免得順手用到 1024。
16. **不把小檔案內嵌進程式。** 建置工具預設會把很小的圖檔與字體直接嵌成 `data:` 網址，而正式環境的安全標頭（CSP）不允許這種網址；本機開發伺服器沒有 CSP，所以看不出來。做法：關掉內嵌，並讓瀏覽器測試跑在帶 CSP 的建置結果上。（這個預設行為是憑既有知識寫的，第一個前端 Story 要對著當時的版本確認。）
17. **論文標題與原文摘要只經一個共用元件顯示**，由它加上語言屬性（頁面是繁體中文，論文標題與摘要多半是英文；手填的中文論文看論文的語言欄位）。

### UX 文件問的另外兩件事

- **首頁在手機上「跑不順」的門檻**：數字現在定不了。首頁規格 §13 寫明加上柔光、震波、流星之後沒有重新量過效能，暫時的手機版也沒有在任何手機上試過。做首頁的那個 Story 要先量，再把門檻寫回首頁規格；偵測與切換成靜止版的機制照規格 §6.7、§8。
  - **現在就能定的**：偵測只有一個函式、一組門檻（三個常數），放在首頁元件旁的一個檔案；規格 §9 的「跑不順」和 §8 的「效能太差」用同一個（UX 文件的要求）。量法是進場開始後連續幾十格、每一格花的時間；超過門檻的格數到一定比例就判定跑不順。門檻（毫秒）、看幾格、比例是那個檔案裡的三個常數。
  - **判定之後做什麼**：手機與沒有滑鼠的觸控平板換成靜止版（規格 §9）；其他裝置換成靜態圖（規格 §8）。判定只在進場時做一次，之後不來回切換。
  - **那個 Story 要量的**：至少一支近兩三年的中階 Android 手機與一支 iPhone，各用自己的瀏覽器；記下每一格的時間分布，定出三個常數，寫回首頁規格 §8、§9、§13。Story 開工時先放一組起始值（每格超過 40 毫秒、看 60 格、超過三成），標明是還沒量過的暫定值。
  - **起始值不設在 33 毫秒**：iPhone 的低耗電模式會把畫面固定在每秒 30 格，每格 33.3 毫秒；門檻設 33 的話這些手機一律被判成跑不順。量的時候不算分頁在背景與進場最前面的幾格。低耗電模式要不要直接給靜止版，量過之後提給 Kevin 決定。
  - 這裡有兩種退場，不要混在一起。**靜止版**（規格 §6.7）：同一支畫布程式只畫完成的那一格就停，瀏覽器自己算；偵測放在首頁元件裡，量前幾格每格花的時間。**靜態圖**（規格 §8）：連畫布都不能用時顯示的圖片。
  - 靜態圖在前端建置時用同一支畫布程式產生，跟頁面殼一起部署，可以比資料舊；圖旁的替代文字用 `manifest.json` 的數字。這樣正式主機不用為了每週重畫一張圖而裝 Node。
- **AI 產出還在產生時能不能給預計時間**：不給。畫面只有一句「還在產生，晚一點再回來看」（UX 文件）；API 裡分成「幾分鐘內會好」與「最晚 24 小時」兩種狀態，只用來決定前端多久再問一次，不顯示成時間（ADR-0004）。

## 理由

1. **同一個畫面只做一次。** 示範站是給面試官看的門面，成員版是每天用的；兩邊長得不一樣，或同一個數字兩邊算法不同，都是會被看出來的問題。
2. **資料來源層讓「示範站沒有後端」變成一個實作細節**，不是另一套程式。
3. **無樣式元件正好對上這個專案的情況**：外觀有自己的設計稿，行為（鍵盤、焦點、螢幕報讀）想用別人驗證過的。
4. **型別從後端產生**，後端改了欄位，前端在編譯時就會報錯，不會等到畫面壞掉才發現。

## 取捨

- **資料來源層多一層間接**，而且示範站有的畫面要寫兩種實作。換來的是頁面不用管資料從哪來。
- **TanStack Router 比 React Router 少人用**，範例與問答比較少。
- **自己畫圖表比較花時間。** 趨勢頁的圖只有折線、長條、小倍數三種，量不大。
- **沒有用到 TypeScript 7 比較快的編譯器。** 這個專案的前端不大，差別是幾秒。升級的條件寫在工具表。
- **引用匯出（APA、RIS、BibTeX）只在前端實作一份**（Kevin 2026-11-14 決定，取代原本的「成員版在後端、示範站在前端各一份」）：成員版與示範站共用 `web/` 的同一份，用 `tests/golden/exports/` 的資料檔測。Must 裡沒有需要後端產生引用的地方：證據簡報的匯出檔用 DOI 連結，問答的「複製引用」與論文頁的 RIS／BibTeX 下載都在瀏覽器裡做。之後 Should 的 S02（文獻整理表＋批次匯出）如果要在後端產生，再加後端那一份，並通過同一批資料檔。
- **Tailwind 清掉預設值後，不能直接抄網路上的範例樣式**，要換成自己的代幣。這是刻意的。

## 名詞

- **建置**：把原始程式轉成瀏覽器可以直接執行的檔案的步驟。同一份程式可以用不同設定建置出不同的版本。
- **資料來源層（datasource）**：頁面和「資料實際從哪裡來」中間的一層。頁面只說「給我某年的趨勢」，由這一層決定去問 API 還是讀檔案。
- **無樣式元件**：只提供行為（開合、鍵盤操作、無障礙屬性）、不帶任何外觀的元件，外觀由使用的人自己寫。
- **路由**：網址和畫面的對應規則。
- **i18n**：把介面上的文字從程式裡抽出來、放進對照表的做法；之後要改文字或加語言只改對照表。
- **lint**：自動檢查程式有沒有違反規定寫法的工具。
- **設計代幣**：設計稿裡定下來的一組具名的值（顏色、字級、間距），程式只能用這些名字，不直接寫數值。
- **Canvas**：瀏覽器裡用程式一筆一筆畫圖的區域，適合同時畫上萬個點。

## 2026-11-17 更新：CI 上的瀏覽器測試失敗時自動重試一次

**發生什麼事。** GitHub 的機器上，Firefox 跑 axe 掃描時偶爾整頁當掉（`frame.evaluate: Page crashed`）。每次只當一項、當在不同頁面，其餘測試全過。論文頁合併之前約二十次 CI 出現一次（2026-11-16 13:21，導覽列的測試）；論文頁合併之後掃描的頁面變多，七次裡出現四次，PR 連續重跑三次都被擋住。

**考慮過的選項。**

- A. 維持不重試，失敗時人工重跑。每次約 6 分鐘的 GitHub 分鐘數，而且要有人盯著。
- B. CI 上失敗時自動重試一次，本機維持不重試。
- C. 找出 Firefox 當掉的根本原因再修。原因在 Firefox 或 axe 裡面，本機重現不了，花多少時間不好估。
- D. axe 掃描只在 Chromium 跑。最省事，但少掉另外兩種引擎的無障礙檢查。

**決定。** B（Kevin 2026-11-17 決定）。`web/playwright.config.ts` 的 `retries` 在 CI 上是 1，本機是 0。

**取捨。**
